# Herdr 原生工作区迁移验收计划

本清单是未来实现的执行计划；除 [evidence.md](evidence.md) 已记录的元信息检查外，下列功能检查均未执行。未勾选项不代表通过。状态仅使用“已完成”“进行中”“失败待决策”“环境不足未验证”；当前各功能阶段均为“环境不足未验证”，因为还没有可验收的实现或授权的原生运行环境。

## 记录与停止条件

每次执行先记录目标 `main`、候选 commit 或源摘要、依赖锁摘要、平台类别、实际参数向量、退出码、预期与观察差异、脱敏证据引用。验证后的实现若改变，重跑受影响检查；最后对稳定 diff 复核。原始终端日志、私有路径和会话正文不进入公开仓库。文档检查不等于 OpenSpec 校验。

默认测试只能使用仓库与临时 HOME/XDG、阻断网络、假子进程、虚构项目/profile 和文件哨兵；不启动 Herdr、Avalon、Pi、Codex、DSH 等第三方宿主。不能用真实认证、会话或剪贴板内容作断言数据。真实 smoke、模型调用与原生独立 server 属于后续单独显式授权步骤；本清单本身不构成授权。

出现接口前提不成立、事务或并发顺序无法确定、需要扩大权限或修改上游宿主时，标记“失败待决策”并交回主代理。相同失败经过两种有效尝试仍未解决，也交回主代理。超时后结果不明必须先只读查询和对账，禁止盲目重试创建、发送输入或关闭操作。不得通过终止已有 daemon、接管已有终端、弱化断言来取得通过。

## 阶段 0：接口、配置和候选身份

- [ ] 首次安装及每次显式升级前重新核实官方最新 stable，记录候选选择和留在旧版的具体原因；在选定版本的 tagged 源码核实实际使用的公开 CLI/socket 命令、字段、ID 寿命、创建/查询/聚焦能力、错误码和超时语义。已有静态审计为 v0.9.5，不能自动沿用为新版结论；记录完整 commit 与源码位置。
- [ ] 将已核实的启动约束转成契约测试：`pane run` 是文本注入，`agent start` 最终也发送 shell 编码后的命令；tab create 没有通用 argv。区分 `request.id` 关联与幂等保证，tokens 冷恢复会清空；不以这些机制声称原子去重或持久用途注册。
- [ ] 证明 `(server, checkout realpath)` 可以可靠绑定到原生对象，且关闭、移动、重启后的查询足以识别失效绑定。不能靠标题、cwd 近似或最近日志补齐身份。
- [ ] 核实 named server 的配置、socket、日志、持久化隔离方法。单独设置 HOME 不能替代此项；不能证明隔离时停止原生启动步骤并提出设计决策。
- [ ] 分别记录磁盘客户端版本与摘要、实际 server 版本/协议/所需 capabilities、实际配置/规则/集成及验收记录。未验收的本机 0.8.0 不算已通过基线；不硬编码精确等于 0.9.5，不将不同版本字符串自动判为不兼容。
- [ ] 核实默认关闭恢复、声音、toast、后台更新、实验 history 的公开配置方法与生效边界；不能以配置文件已写入代替生效证据。
- [ ] 明确已有原生 server、活动终端与私人状态的保留边界，记录撤销操作；不停止已有 daemon、不修改现有私人状态。

## 阶段 1：默认离线隔离测试

在实现完成后，由实现者提供实际可执行的测试命令与测试文件，使用已准备的仓库 `.venv`；解释器满足工程声明的 Python `>=3.11`，依赖按锁准备，不要求精确等于本机的 3.11.11。记录实际版本、argv 和退出码，其他解释器版本的通过范围以实际结果为准。以下观察全部由假子进程和虚构 socket 响应驱动。

- [ ] 临时 HOME/XDG 和仓库外哨兵均未被写入；网络请求与第三方宿主执行会使测试失败；凭据、session 文件与原生 socket 未被读取或连接。
- [ ] `work enter` 首次创建、再次聚焦；项目身份含 server 与 checkout realpath；同项目不同 worktree、不同 server 均不合并；路径规范化行为与符号链接夹具明确。
- [ ] 非 Git 路径在任何 server 启动/修改前退出 2，提示使用原生临时工作区；不偷偷创建“近似项目”。
- [ ] `open shell/edit/build/debug/pi/codex/dsh` 默认复用，`--new` 才增加实例；连续 `cd` 不导致项目自动切换或终端重归属；原生手工终端不被接管。
- [ ] 已有工作 shell 被复用时只聚焦，不发送命令或控制字符；活动状态未知时同样不注入。编辑器和 Agent 不向复用 shell 发送启动文本；新拥有终端的唯一 shell 编码边界、就绪检查和元字符行为经过测试。
- [ ] Agent argv 保持原 `agentcfg` profile 与项目 cwd，不触发 sync/apply、依赖安装、联网或隐式迁移；缺配置时明确失败，敏感值不进摘要、日志和异常。
- [ ] Avalon 经 `machine.editor` 单 launcher 启动；参数与 cwd 边界清晰，不以 shell 拼接引入命令执行；未知字段失败，不静默回退 profile。
- [ ] 两个并发 `work enter`、两个并发同 role `open`、聚焦期间关闭目标：根据原生确认结果处理，不产生静默重复或错误归属；结果不明时先查询再报告。
- [ ] 模拟“创建成功但响应丢失”“发送前超时”“查询超时”“连接中断”：不盲重试非幂等请求，不把 UI 状态或缺响应判作成功/失败确定事实。
- [ ] 模拟原生终端移动、关闭、项目关闭、server 重启、ID 复用、过期 `HERDR_*` 环境：清除或拒绝失效引用；不向错误 server 或另一终端发送操作。
- [ ] 冷恢复清空用途 tokens 后，默认 `work open build` 在身份未知时退出 4，不新增/接管/关闭；显式 `work open build --new` 可以建立新的 primary 并供之后复用，保留恢复终端，其他用途的未知状态不被自动解除。
- [ ] 配置应用成功、部分失败、未知字段、所有权冲突及回退：只撤销本次拥有的文件变更，不更改认证、会话、私人恢复数据或活动实例。
- [ ] 不新增守护进程、宿主补丁、第二套终端数据库或额外权限；测试失败不会自动切换为真实宿主执行。

## 阶段 2：原生独立 server

状态：环境不足未验证。前置条件为阶段 0 的隔离证明、可用的当次较新稳定候选和用户对本阶段的显式授权。当前已审计候选为 0.9.5；先记录实际 argv，再按选定 release 已核实的接口执行。本文不猜测 server 启动命令，授权只覆盖专用测试 server，不覆盖现有 daemon。

- [ ] 使用专用 socket、配置、日志和持久化位置启动；从原生只读查询确认 server 身份及配置；证明未连接现有 socket，默认关闭项确实生效。
- [ ] 在虚构项目中重复阶段 1 的创建、聚焦、复用、`--new`、移动、关闭、重启、过期环境和并发场景。每步记录原生对象 ID 的脱敏对应关系与可见终端数。
- [ ] 注入受控连接中断或延迟，复现结果不明的请求；先查询原生事实，再做显式修复；任何非幂等重试都需有先前操作未生效的证据。
- [ ] 让启动所用 shell 正常退出，观察 server、终端和已启动测试进程实际存活情况；区分 shell 退出、客户端 detach 与 server 退出，不提前假定语义。
- [ ] 在专用环境中验证恢复默认关闭；若未来测试显式恢复，分别记录布局、程序重启与原进程存活，不将重新运行描述成原进程复活。
- [ ] 退出时仅清理本阶段创建且身份确认的对象与文件；专用 server 清理不影响现有 daemon、原生手工终端或私人状态。

## 阶段 3：真实终端与 SSH 交互

状态：环境不足未验证。需要真实终端链路及独立授权；记录本地终端、SSH、是否嵌套 tmux、客户端数量和尺寸，不记录机器身份或连接端点。每项先使用无账号测试程序。

| 场景 | 执行与观察步骤 | 通过条件 |
| --- | --- | --- |
| zsh 重绘与 resize | 使用实际 zsh 配置类别，在提示符、长命令、多行输出间反复缩放；如使用 P10k，单独记录 | 无丢行、残影、提示符错位或输入错位；失败保留复现步骤，不援引 Fish 修复代替结果 |
| `C-x` 字面输入 | 在测试程序显示收到的字节，输入 `C-x` 及其组合；确认应用快捷键边界 | 能按已决定键位规则传递字面输入，不意外触发工作区操作 |
| Avalon 组合键 | 核实 launcher 对应实际 profile；启动测试文件，观察编辑、窗口、终端相关组合键 | profile 正确且组合键到达目标，不因终端前缀冲突丢失；不改写编辑器上游 |
| CJK 与 Shift+Enter | 输入中文、混合宽度字符、多行文本、Shift+Enter，缩放后继续输入 | 光标、回显、换行和提交行为均符合目标程序实际协议；不把屏幕状态作为完成证据 |
| OSC 52 写入 | 向终端输出明确的合成复制文本；按直连与嵌套 tmux 分别验证，由操作者在测试文本框确认 | 只验证写入合成内容；不读取原剪贴板，不查询或公开真实内容；记录链路支持边界 |
| 多客户端尺寸与焦点 | 两个独立客户端以不同尺寸连接测试 server，交替 resize、切项目、detach | 记录尺寸策略与同一 server 共享活动工作区的行为；不承诺客户端独立焦点，无输入错位或错误终端操作 |
| SSH 断连 | 在可销毁测试任务运行时断开 SSH，再连接同一测试 server；另测 server 已退出 | 区分客户端断连与进程存活；确认重连目标身份，失败时不自动重跑命令 |
| 启动 shell 退出 | 比较启动 shell 退出、客户端退出、显式 server 退出三个动作 | 分别记录进程与终端结局，符合阶段 0 确认语义；不误杀现有 daemon |

## 阶段 4：项目规模与资源观察

状态：环境不足未验证。先在独立测试 server 中建立 3 个虚构项目，每个含多个 checkout/worktree，合计 20–30 个终端；shell/edit/build/debug/Agent role 均有代表实例，真实 Agent 留待阶段 5。

采用 [upgrade-benchmarks.md](upgrade-benchmarks.md) 的版本化 workload、采样、阈值和结果契约，首轮建立实测基线，后续同机比较最后通过版本与候选。未校准门槛和缺失数据不算性能通过。

- [ ] 记录项目、checkout、role、实例和原生 ID 的脱敏清单；跨项目进入与聚焦不会混用 worktree，手工终端仍由原生用户操作管理。
- [ ] 在空闲、持续输出、窗口移动、resize、反复 attach/detach 后，于事先约定的固定采样窗口记录 CPU、RSS、客户端数、终端数与残留测试进程数。
- [ ] 比较多轮 detach 前后资源变化与采样跨度；观察是否持续增长。先确定可接受阈值与复现次数，再执行，不在看到结果后修改门槛。
- [ ] 对关闭、重启及 stale env 重复抽样，确认没有错误聚焦、重复实例或遗留引用；发现持续增长或结果不明，标记失败待决策，不宣称“可替代 tmux”。

## 阶段 5：真实编辑器与 Agent

状态：环境不足未验证。需要用户单独授权真实 smoke、相应账号与测试输入；不得将已有账号文件复制进夹具或公开证据。Herdr 的 Agent 状态只作 UI 观察。

- [ ] Avalon 使用选定的 `machine.editor` launcher，在测试 checkout 进入正确 profile；验证 CJK、Shift+Enter、组合键、resize，与阶段 3 的终端链路记录关联。
- [ ] Pi、DSH 分别经既有 `agentcfg` profile 启动，独立 Codex 经显式官方入口启动；cwd 与项目 checkout 一致，不自动 sync/apply、联网安装或迁移账号。
- [ ] 对授权的短测试交互，分别记录 Agent 自身退出/完成证据、Herdr 显示状态与会话绑定；Herdr 状态不触发任务完成判定。Codex 不以已移除 turn hooks 为实现前提。
- [ ] 观察重复完成通知、错误会话绑定、重连和多客户端状态；声音/toast 默认关闭仍需确认，不以关闭通知掩盖错误的绑定或调度行为。
- [ ] Agent 活动时再次打开同 role 只聚焦，不向活动 shell 注入文本；`--new` 明确产生独立实例；真实中断与恢复操作限于获授权的测试实例。

## 阶段 6：配置回退与最终门禁

- [ ] 以测试配置执行应用、故障和回退，确认不触碰 private 状态、现有活动实例或其他工具的所有权；实际 argv、退出码和回退后差异都有记录。
- [ ] 稳定最终 diff 的来源、锁、许可、公开内容和相对链接检查完成；候选与目标 `main` 未发生未评估变化。
- [ ] 将每项实际结果更新为四种状态之一；任何已知失败列出精确接受范围与决策，环境不足列出缺少的平台/授权/运行包，不用“未运行”冒充通过。
- [ ] 合入前按仓库门禁审查候选与历史；本清单不授权提交、合并、远端发布或停止现有 daemon。最终报告区分设计文档完成、隔离测试通过和真实平台通过。

## 阶段 7：后续升级回归与推广

状态：环境不足未验证。当前没有已通过的生产性能基线，以下是未来执行门槛。

- [ ] 按 [升级基准](upgrade-benchmarks.md) 的冻结 fixtures 和配置比较基线/候选，记录 release、资产、server、协议、配置、规则和集成的独立身份；分别对比固定规则 runtime 与完整候选包。
- [ ] 检查项目身份、默认复用不发命令、并发和超时对账、冷恢复身份未知、shell 编码、输入/resize/剪贴板、共享焦点及断连进程存活；任何误操作、权限退步或进程意外退出阻止推广。
- [ ] 汇总必需的延迟分布、CPU、RSS 稳态/峰值及按所选范围要求的长期增长，使用测量前冻结的噪声、相对/绝对门槛；必需指标缺工具/样本或阈值未校准时不能通过。wakeup/PSS 等附加指标不可用时逐项保持未验证，不扩大权限，也不自动阻塞具备必需证据的升级，报告不得将附加未测项写成通过。
- [ ] 在授权专用环境中验证配置 check 与 reload 的不同作用、快照格式、版本混用和旧新回退；不能把 reload 成功当成启动期设置已更新，不让旧版直接读未经验证的新版状态。
- [ ] 真实客户端和新工作试用通过后，才显式提升未来启动入口；记录仍运行旧 binary 的 server，保留旧任务，不默认 live handoff。回退入口不宣称迁移现有进程。
