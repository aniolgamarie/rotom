## 4. 新旧实例切换

1. 新base/pro各用独立、稳定的原生agent directory、会话目录、部署状态和完整锁。
2. 不默认接管 `~/.pi/agent`，不复制旧auth、MCP auth、trust、session、任务库或浏览器状态。
3. 用户在最终新实例单独登录；模型与服务绑定来自非秘密覆盖和SecretRef。
4. 新配置部署前提供可审阅差异；非空未接管目标、冲突、pending恢复和活动/未知owner阻止不安全写入。
5. 旧实例不自动终止，旧工作树不自动删除，旧运行包不继续补丁构建发布。
6. 配置回滚保留新增原生状态；不能把配置rollback当软件降级或数据库迁移。旧运行包重新打开新版状态前另做兼容判断。
7. 公共发布资料只记录通用路径、来源、版本和必要证据，不导出实际账号/会话验证清理。

## 5. 完整依赖与安装验收

每个候选必须核对以下五个对象的一致性：canonical仓库、不可变源码提交、发布tarball/发行物、实际package manifest与许可证、完整依赖锁。源码清单为private或由打包脚本生成时，不能仅依据源码版本号判断发布内容。

| 检查 | 需要证明 |
| --- | --- |
| 宿主身份 | 版本、来源、完整性、平台、入口和必要资源相符，没有源码补丁 |
| 插件公开接口 | 没有私有导入、monkey patch或必须修改宿主的安装步骤 |
| 安装脚本 | lifecycle脚本目标与副作用可解释；未知脚本不能默认跳过后仍称安装完整 |
| 依赖闭包 | 锁包含传递依赖、原生模块及必要构建资源，不在run时补装 |
| Pi提供的peer包 | 与指定宿主公开扩展加载规则相符，避免额外嵌套宿主副本 |
| 工具依赖 | 浏览器/语言服务器/系统库来源、版本与平台前提明确 |
| 源码和许可 | 上游署名保留，许可证与选中发行物对应 |

只设置直接版本、执行 `pi install ...@version` 或看到安装marker，都不能代替上述检查。依赖变更与锁、vendor、构建输入一起审阅。

## 6. 默认隔离验证

不得启动第三方宿主。使用临时HOME/XDG/原生agent目录、阻断网络、假进程、虚构provider/model和文件哨兵。

| 编号 | 受影响契约 | 关键失败路径 |
| --- | --- | --- |
| ISO-01 | 输入schema与引用 | 未知字段、无效插件/模型/资源引用、空数组和false的含义 |
| ISO-02 | 原生字段所有权 | 三方比较、漂移保留、重叠selector、双方修改冲突 |
| ISO-03 | 秘密边界 | validate/render/plan/doctor不读秘密正文；秘密不入argv/摘要/日志/备份 |
| ISO-04 | 命令副作用 | lock/sync/apply/run分离；run不安装、不部署、不修改锁 |
| ISO-05 | 依赖暂存与激活 | 缺包、完整性不匹配、安装失败、中断恢复、不改变实例home |
| ISO-06 | 资源发现与会话归属 | 项目packages/扩展/Skill/父目录资源哨兵，sessionDir覆盖、未授权发现 |
| ISO-07 | 管理器生命周期 | 主进程退出、后台后代、异常退出、未知owner、维护冲突；不自动杀进程 |
| ISO-08 | 子执行契约 | 工具/资源/会话继承、角色模型、并发/递归约束、失败/取消结果投影 |
| ISO-09 | MCP与外部工具 | 精确argv、禁止启动安装、SecretRef缺失、工具环境与状态目录 |
| ISO-10 | 多宿主/配方隔离 | base/pro/旧Pi互不读写；受影响的DSH/OMP共享契约不回归 |
| ISO-11 | 配置恢复 | pending、rollback、原生新增状态保留，软件和数据库不降级 |

隔离测试证明管理器行为与输入输出契约，不证明第三方插件真的遵守工具限制或模型真的完成任务。测试是否新增取决于实际变更风险，不机械编写镜像实现的测试。

## 7. 单独授权的原生与账号验收

以下是未来应执行的场景，**本轮均未执行**。不将用户要求设计文档解释为安装、登录或模型调用授权。

| 编号 | 场景 | 证据与范围 |
| --- | --- | --- |
| NAT-01 | 官方Pi原生资源加载与启动 | 指定版本、锁、平台、实际argv；不加载未知项目包 |
| NAT-02 | 原生会话继续、压缩、分支、UI | 归属、规则与资源是否保持；无磁盘撤销承诺 |
| NAT-03 | 两个子代理候选的相同最小任务 | SDK/进程模式、工具/资源约束、取消、结果、版本限制 |
| NAT-04 | 有限并行和工作树 | 单写入者/分离工作副本；主agent集成；无共享文件覆盖 |
| NAT-05 | 父子退出和维护 | 后代资源释放、活动检查、未知状态处理，不把退出0当全部通过 |
| NAT-06 | Skills兼容 | 完整支持文件、工具名、触发与流程强度，简单任务不会强制整套流程 |
| ACC-01 | 实际模型与角色绑定 | 账号授权后记录实际模型/effort/结果，不输出凭据或会话正文 |
| ACC-02 | 文档与搜索 | 账号/服务授权后验证结果与引用、认证过期、超时和禁用 |
| ACC-03 | 浏览器交互 | 授权的测试站点，专用profile/session、依赖和退出 |
| ACC-04 | 可选隔离 | 指定平台下的挂载、网络、凭据与扩展边界；不向其它平台外推 |

至少分别记录Linux与macOS的实际结果；Windows是否纳入支持由用户需求和资源决定。缺平台/账号时标为环境不足未验证，不阻塞无关文档或已完成模块。

## 8. 版本组合与支持矩阵模板

| 字段 | 内容 |
| --- | --- |
| 候选 | commit或稳定源码摘要、目标main |
| 来源 | 宿主、插件、通用CLI/MCP、不可变引用与许可 |
| 锁 | 两档各自完整锁身份，启用模块清单 |
| 环境 | OS/架构/终端/工具链类别，不写私人主机元数据 |
| 执行 | 实际argv、退出码、脱敏证据位置 |
| 结果 | 通过/失败/未执行，具体场景和限制 |
| 模型 | 获授权场景实际执行模型与effort，不能仅记录配置意图 |
| 已知问题 | 触发条件、影响范围、是否有接受决定 |

例如Pi 1.2修复记录不证明1.3通过，Node peers宽范围不证明所有平台可用，Linux成功不证明macOS/Windows成功。新支持矩阵不能借用旧toolkit的历史通过数量。
