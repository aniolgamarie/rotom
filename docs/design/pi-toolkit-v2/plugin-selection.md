# 插件、社区方案与工具选型决策

临时设计材料：仅用于开发分支讨论；合入 `main` 前必须删除，或整合到正式文档后移除本临时文件。本地提交不代表设计已采纳或产品已验收。

状态：2026-10-16 研究后的设计决定。入选代表优先验证，不代表发布包、Pi 1.3.0 或某个平台已经通过验收。用户确认默认灵活协作。

## 1. 决策方法

先检查硬门槛，再比较价值。硬门槛包括公开来源与许可证、未经修改的宿主、公开接口、安装副作用可解释、完整依赖可锁、原生状态所有权可保留、可独立禁用。没有证据的项目标记未知，不用乐观打分补齐。

比较维度是：原生覆盖程度、真正补充的能力、进程内代码与外部服务数量、版本适配记录、配置与状态复杂度、平台前提、上下文开销、认证路径、卸载和回退成本。此处结论是基于证据的设计判断；不使用未经测量的数字加权制造客观排名。

本文使用五种结果：

- **基线**：选用原生或已有通用能力。
- **优先验证**：有明确增量价值，先做小范围组合验证。
- **替代候选**：与优先项互斥，需要场景或证据触发切换。
- **按需模块**：用户或项目需要时启用，不属于默认启动负担。
- **观察/退出**：本版不采用；保留原因与重新评估条件。

维护活跃、历史较长、兼容当前版本、承诺长期支持分别记录。持续发布兼容修复是有价值的证据，同时也说明实际维护面存在；不能写成“长期稳定已证明”。

## 2. 宿主与整套方案

| 候选 | 增量与成本 | 决定 |
| --- | --- | --- |
| 官方 Pi CLI + 精简配置 | 原生升级、公开配置和生态；承担少量组合验证 | 两档共同基线 |
| 官方 SDK 嵌入自有宿主 | 可深度控制生命周期，但重新承担交互、资源与版本适配 | 不进入新主路径 |
| OMP / 社区 Pi fork | 可能直接提供更多能力，也改变宿主、支持与兼容范围 | 独立产品；不混入 Pi 配方 |
| 旧自研 toolkit | 已有大量实现材料，也包含监督、租约、权限与恢复耦合 | 只作为迁移证据，不继承功能完整性要求 |
| 大型个人配置整包 | 可参考真实工作方式，通常夹带环境与行为假设 | 逐项借鉴，不整体复制 |

依据：[官方基线 O01–O12](upstream-and-portable-tools.md#o-baseline)、[E05 个人配置实例](community-research.md#e05)。对 OMP 的排除是范围选择，不评价其产品能力；本轮不修改或重复设计 OMP。

### D01：产品只有两档，附加能力采用模块

模型提供方、浏览器、搜索和工作流偏好不再产生独立公开 profile。避免每个组合生成单独锁和支持承诺。base/pro 分别有完整锁，服务与模型绑定放机器覆盖；模块的可用组合仍需有限、明确地列出。

## 3. 子代理与多 agent 协作

| 比较项 | 官方 subagent 示例 | nicobailon/pi-subagents | tintinweb/pi-subagents | pi-messenger/Crew |
| --- | --- | --- | --- | --- |
| 证据 | [E13](community-research.md#e13) | [E02](community-research.md#e02) | [E03](community-research.md#e03) | [E04](community-research.md#e04) |
| 定位 | 展示公开扩展的最小实现 | 委派、工作流、前后台、产物及观测 | Agent 工具、队列、steer、角色及工作流 | 跨会话通信与 Crew 执行 |
| 主要优点 | 依赖和行为较易理解，随官方源码可追溯 | 工作流和结果观测较完整，已有 1.x 修复记录 | 与仓库历史来源更接近，另一套公开编排方案 | 独立会话协作和预留信息 |
| 主要负担 | 示例质量不等于产品维护支持；若本地扩展即形成自有代码 | 功能面较宽；发布包和源码清单需分开核对 | 完成通知/Esc 后续 turn 语义近期有变更 | 新增 presence、消息、预留和任务图状态 |
| 当前版本研究 | 必须绑定选定 Pi tag 的示例 | 观察到 0.78.0；不是最终安装锁 | 观察到 0.22.0；不是最终安装锁 | 观察到 0.15.2；不是最终安装锁 |
| 首版位置 | 对照与必要时的范围退让 | 第一顺位小范围验证 | 第二顺位对照验证 | 观察，不与委派器同时默认加载 |

### D02：先验证一种委派器，只开放需要的执行方式

第一顺位仍是 nicobailon/pi-subagents，原因是角色、结果产物和观测能力与复杂任务闭环较匹配，且有 Pi 1.x 适配记录。这个判断没有证明它比 tintinweb 更轻、更稳定或更省 token；功能广度也可能成为淘汰理由。

两个候选必须做同一组最小任务对比：一次只读委派、一次有边界的写任务、两个独立任务、工具失败、用户取消、模型凭据缺失、重载与会话继续。记录实际模型、argv/资源路径、结果回收方式、状态目录、执行时长与上下文用量；控制模型、输入和输出要求，不能用不同模型的结果比较插件效率。

准入重点：能否经公开接口落实实例归属、会话目录、资源选择、工具选择和禁止递归；是否会自动安装包、发现额外项目资源、隐式依赖 web 插件或错误复用认证。前台 SDK 会话无需任意 CLI argv 透传；同一 profile 的 agent directory 可以继承。E02/E03 已有 session、工具和深度配置证据，但等效资源发现和认证归属仍须验收。无公开配置证据的要求保持阻断项，不能用私有 API 绕过。

首版只需要同步委派和最多两个子任务。若第一顺位必须启用宽泛编排或不能满足准入，改验第二顺位；两个都不满足则推迟高阶委派功能，继续交付基础版，不在仓库 fork 插件或创建兼容桥。

### D03：暂不引入跨会话 teams 与 Crew

pi-messenger 的文件预留是协作信息，不能推断为所有工具写入的强制排他锁。Crew 自有执行机制与子代理插件不是同一个引擎。当前需求用主 agent + 有边界任务包即可满足；出现长期跨会话协作需求后再评估，届时明确哪套任务状态为唯一来源。

## 4. 工作流、计划和 Todo

| 候选 | 价值 | 负担或冲突 | 决定 |
| --- | --- | --- | --- |
| 简短提示模板 + 文件计划 | 原生、透明、无任务服务 | 需要清楚约定状态与交接 | 两档基线 |
| Superpowers 精选 Skills | 成熟方法可跨宿主复用 | 需检查工具名、相对引用和流程假设 | pro 优先验证 |
| Superpowers 完整引导 | 自动组织规划、实现与审查 | 流程更强、可能增加轮次和自动委派 | 显式选择，默认关闭 |
| OpenSpec | 适合项目级变更与持续规格 | CLI、项目初始化和产物维护 | 项目按需选择 |
| Spec Kit | 规格、计划、任务及可配置工作流 | 模板、脚本、gate 和项目集成 | 项目按需选择 |
| 官方 plan/todo 示例 | 最小公开 API 对照 | 仍是执行扩展；示例不是默认产品 | 参考，不默认复制维护 |
| rpiv-todo | 任务显示与分支回放，有近期持久化修复 | 同系列依赖和 UI/状态语义 | 可选 Todo 第一对照候选 |
| pi-todotools | 阶段式 Todo 与面板 | 工具名迁移、回放/压缩需核对 | 可选 Todo 第二对照候选 |
| mitsupi todos/goal | 真实文件任务实践 | 个人集合含自动延续等额外行为 | 借鉴，不整包加载 |
| 旧 Task Keeper | 持久任务与执行治理 | 数据库、租约与恢复耦合 | 新主路径退出 |

依据：[T01–T03 方法论](upstream-and-portable-tools.md)、[E09](community-research.md#e09)、[E10](community-research.md#e10)、[E13](community-research.md#e13)。

### D04：计划是普通项目资料，Todo 面板不是首版必需

用户选择灵活协作，因此不把 Todo 工具、plan-mode 或完整自动引导放进基础版。复杂任务用文件记录目标、任务、验证与交接；简单任务不强制创建计划文件。

有 OpenSpec/Spec Kit 的项目沿用已有位置与状态；没有时由项目约定选择普通 Markdown。不要同时自动写多个任务系统。若用户频繁需要任务面板，再在 pro 中只选一个 Todo 插件；其回放、codemode 间接调用和压缩持久化必须单独验证。

所谓 plan 模板只是工作约定，不是只读安全模式。需要强制只读时应使用经验证的工具选择与外部权限边界；不能给提示模板起一个名字就承诺无写入。

## 5. MCP 接入

| 项目 | 原生 MCP | pi-mcp-adapter |
| --- | --- | --- |
| 证据 | [O07](upstream-and-portable-tools.md) | [E07](community-research.md#e07) |
| 已有能力 | stdio/HTTP、认证、工具/资源、exposure、Codemode | 另有生命周期、管理 UI、proxy 等增量 |
| 维护面 | 与宿主版本一起验证 | 额外依赖、原生 keyring、设置切换与集成 |
| 关键区别 | 延迟工具暴露不等于 server 懒启动 | 安装/更新可关闭原生 MCP，卸载需恢复 |
| 决定 | 两档基线 | 观察，有实际生命周期需求后再评估 |

### D05：只使用一套 MCP 所有权

不同时装原生与 adapter 来竞争配置。未来若需要 adapter，必须把关闭原生、原有配置、认证归属、卸载恢复和失败处理设计成明确变更；配置 rollback 不等于 token 或服务状态 rollback。只为 UI 好看不足以承担这项切换。

## 6. Web 搜索、网页和文档

| 能力 | 优先方案 | 对照/替代 | 为什么不同时默认启用 |
| --- | --- | --- | --- |
| 技术文档 | Context7 原生 MCP | ctx7 CLI；Context7 Pi 扩展 | 同一文档服务重复暴露，增加路径和依赖 |
| 通用搜索 | Brave 官方 MCP | Exa MCP；Tavily MCP | 认证、费用、索引和错误语义需明确，避免静默回退 |
| 网页阅读和浏览器 | Playwright CLI + Skill | Playwright MCP；agent-browser | 多浏览器会话与状态成本重叠 |
| 统一搜索/正文/PDF | 单独评估 pi-web-access | 通用工具组合 | 统一接口有价值，但额外依赖、路由和缓存也有成本 |

依据：[T04–T10](upstream-and-portable-tools.md)、[E06](community-research.md#e06)。

### D06：先准备文档、搜索、浏览器三个独立模块

文档模块用 Context7 MCP，浏览器模块优先 Playwright CLI。搜索模块暂以 Brave 为标准候选，理由是来源明确、工具目的清楚、能直接接原生 MCP；这不是对搜索质量的绝对判断。用户已有 Exa/Tavily 账号或更依赖抽取时可以选择替代项。

网络能力均按需启用，不以无 key 说明承诺可持续免费使用。正文阅读、搜索摘要、动态浏览器和 PDF 是不同能力，不能把“能打开 URL”写成全部已覆盖。

### D07：pi-web-access 进入专项对比，暂不列默认核心

它覆盖统一提取和 provider 路由，对复杂研究任务有实际吸引力，值得与通用组合比较。取一组普通文档页、动态页、长文、PDF、失败 URL、重定向和大响应，用相同问题比较正文质量、来源引用、时延、上下文、缓存位置和认证路径。

若明显改善常见任务，且能够关闭无关 provider、浏览器认证扫描及自动 fallback，可作为 pro 的 web 模块实现，**替换**重叠能力。若核心子代理角色隐式要求该包，首版选择不依赖它的角色；不能为预设 researcher 角色顺带引入第二个核心扩展。

| 候选 | 决定 | 理由 |
| --- | --- | --- |
| 原生终端、主题、footer | base/pro 基线 | 新版原生设置较完整，升级成本最低 |
| 已有 Rosé Pine 等主题资源 | 重新验收后可保留 | 声明式资源；仍需检查新 schema 和窄屏/对比度 |
| pi-powerline-footer | pro 可选，默认关闭 | 除状态显示外还有输入、队列、bash、自动 follow-up 行为 |
| mitsupi 主题/状态/文件工具 | 单项研究 | 个人平台和工具替换前提，不整包默认加载 |
| 官方 status/footer 示例 | 设计参照 | 若复制后长期改动，就承担自有插件维护 |

依据：[O05](upstream-and-portable-tools.md)、[E05](community-research.md#e05)、[E08](community-research.md#e08)、[E13](community-research.md#e13)。

### D08：UI 价值与输入副作用分别验收

插件叫 footer 不代表它只画状态栏。要验证 Enter/Alt+Enter、steer/follow-up、Esc、粘贴、多行、外部编辑器、bash 模式、窄屏与 tmux。未经这些检查，不因 peers 范围覆盖就称其为低负担稳定 UI。

## 8. 权限与隔离

| 候选 | 可提供的作用 | 维护与边界 | 决定 |
| --- | --- | --- | --- |
| Pi 原生项目信任 | 控制部分项目资源加载 | 不限制工具执行；仍有上下文/sessionDir例外 | 保留原生理解，受管启动用明确资源准入 |
| 官方 permission/path 示例 | 演示工具事件门禁 | 不是完整 shell/扩展进程隔离 | 参考，不承诺产品级保护 |
| @gotgenes/pi-permission-system | 工具、shell、MCP 等规则/审批 | 解析依赖、语法、子代理转发与取消组合很广 | pro 观察，首版不默认引入 |
| MasuRii/pi-permission-system | 规则门禁 | 研究版本 peers不含1.x，条件安装脚本待审 | 当前不入选 |
| 整进程容器/沙箱 | 约束宿主与扩展的实际访问边界 | 挂载、网络、凭据及平台运维 | 有隔离需求时优先专项研究 |
| Gondolin 工具扩展 | 选中工具在 microVM 中运行 | 其它扩展可能仍在宿主、环境变量边界需核查 | 高阶可选实验，非默认保证 |

依据：[E11](community-research.md#e11)、[E12](community-research.md#e12)、[T12–T15](upstream-and-portable-tools.md)。

### D09：不在新版本重建统一权限平台

首版面向受信任本机开发使用，清楚说明 Pi 使用启动进程权限。有审批要求时，可单独评估 gotgenes 包的具体规则和转发路径；有安全边界要求时优先整进程隔离。两类需求分别解决，不能用插件确认框替代 OS 权限。

安装脚本存在不自动证明宿主被修改。对 MasuRii 候选，目前有版本范围不匹配和脚本目标未知两个独立理由暂停准入；不得未经证据指控其修改宿主，也不得跳过来源审阅。

## 9. 语义代码能力、后台任务与其它增强

| 能力 | 首版 | 后续评估触发 |
| --- | --- | --- |
| 全文搜索与文件定位 | Pi 原生工具 + rg | 真实大型项目显示检索瓶颈 |
| 符号/引用导航 | Serena 可选观察 | 目标语言受支持，实测减少无效读取，关闭重复工具与无关 memory |
| 后台 shell | tmux/常规终端工具，显式使用 | 子代理或 CLI 生命周期有可靠证据后再整合 UI |
| 长期记忆 | 不提供全局自动记忆 | 明确数据范围、收益、隐私、失效与删除需求 |
| 自动模型路由 | 原生模型切换与角色绑定 | 有实测收益且可解释费用和失败路径 |
| 外部 agent 委派 | 不列高阶必需能力 | 用户明确需要跨宿主能力，另做官方 CLI 边界设计 |
| 自定义压缩/loop guard | 原生压缩、取消与任务边界 | 可复现原生不足；旧本地包不能当社区维护证据 |
| 自动代码 checkpoint | Git 与工作树、用户已有备份 | 有明确恢复语义及公开成熟方案，不自行补齐 |

依据：[T11](upstream-and-portable-tools.md)、[E16](community-research.md#e16)。不将原生会话树描述为磁盘回滚，也不承诺跨平台后台进程回收已经成立。

## 10. 首版组合与重评估条件

| 组合 | 拟包含 | 实施准入 |
| --- | --- | --- |
| base | 官方 Pi、原生设置、主题、精简规则与四类模板 | 配置/发现/会话归属和离线部署契约 |
| pro core | base + 一种子代理扩展 + 精选方法型 Skills/角色 | 子执行公开配置、取消/失败、模型绑定与有限并行 |
| docs | Context7 原生 MCP | 依赖/认证/服务开关及调用结果 |
| search | 一种搜索服务的原生 MCP | 来源/账号/错误和数据路径 |
| browser | 一种 CLI + Skill | 浏览器依赖、状态隔离与退出 |
| optional | Todo/UI/Serena/隔离/统一 web | 分别有需求与独立验收，不影响 base |

重评估由新证据触发：原生功能覆盖、上游不再维护、公开接口变化、实测显示常见任务无收益、安装/取消/状态所有权失败、依赖不能闭合或维护成本超出预算。每次替换更新本表、来源和能力矩阵，不以本地补丁维持已失效选型。
