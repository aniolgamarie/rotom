临时设计材料：仅用于开发分支讨论；合入 `main` 前必须删除，或整合到正式文档后移除本临时文件。本地提交不代表设计已采纳或产品已验收。

日期：2026-10-16。状态：可审阅设计草案；没有安装或运行新的 Pi 组合，没有替换现有配方。

## 目标与已确认偏好

用户要求重新规划 Pi，可以放弃旧工具包的功能和架构：基础版以原生能力、配置优化和低负担扩展为主；高阶版借助有维护证据的社区方案，覆盖复杂开发工作。用户进一步确认：高阶版默认采用**灵活协作**，复杂任务再启用规划、子代理和审查。

新方案把维护责任集中在配置、依赖来源、组合选型和验收。官方 Pi 执行任务，通用 CLI 和 MCP 提供外部能力；不再为新配方建设一套自有 agent 执行平台。

## 主要设计决定

| 决定 | 设计结果 |
| --- | --- |
| 两档产品 | `pi-base` 与 `pi-pro`，模型和服务差异不再各自生成产品配方 |
| 官方宿主 | 直接启动未经修改的官方 Pi CLI；不嵌入 SDK 接管主交互循环 |
| 原生优先 | MCP、Codemode、会话树、压缩、模型切换和终端设置采用原生实现 |
| 基础版负担 | 默认 0 个第三方进程内扩展，保留少量声明式资源 |
| 高阶版核心 | 重点验证 `nicobailon/pi-subagents`；先同步与有限并行，后评估后台任务 |
| 工作方法 | 精选 Superpowers 方法型 Skills；完整自动引导默认关闭 |
| 外部能力 | Context7、搜索、浏览器和语义索引分别选择一种实现，按需启用 |
| 资源准入 | 同步阶段获取依赖；启动只加载已部署、已锁定的本地资源 |
| 配置治理 | 继续遵守三方比较、所有权、秘密隔离、部署恢复和维护锁契约 |
| 旧执行平台 | AgentManager、Task Keeper 和自研监督恢复链不进入新版启动路径 |

这些是设计选型，不是依赖已锁定或组合已验收的结论。Pi 1.3.0 是调研基线；最终宿主与插件版本由组合验证确定。
