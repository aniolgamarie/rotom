# Terminal configuration manager design

The current `termcfg` boundary is zsh/tmux public configuration and locked plugins. It does not read agent recipes or manage proxy processes. The [user guide](termcfg.md) describes commands and explicit legacy migration. Historical proxy requirements in `specs/003-sync-terminal-tools/` describe the retired implementation and do not authorize current proxy operations.

The source catalog declares every managed file and digest. Plan snapshots include target identities, current v2 ownership state, selected components and plugin lock identity. Apply and rollback hold the machine operation lease and repository read lease, validate the current selection and snapshot, back up before replacing, and journal writes. Repository lock publication uses an exclusive repository lease. Plugin archive extraction admits only declared resources and verifies private installed files.

Current state is strictly `{version, machine_id, targets, previous}` with version 2. New journals use version 2 and terminal components only. A separate frozen strict v1 schema admits old state/journals only for migration, recovery and status diagnostics. Legacy recovery derives restoration solely from journal paths, identities and backups, without the removed source catalog or core lock. Unknown fields fail in both versions.

Explicit `migrate --drop-mihomo` holds the existing machine lease, refuses a pending journal, validates legacy metadata, and durably writes a private migration marker before updating state and machine selection. The marker stores validated nonsecret old metadata, retained backup references, intended results and before/after digests. State is written first, machine second, completion last. Repeated execution accepts only recorded before/after metadata during an incomplete migration and refuses observed drift. Parsed values are matched to captured bytes, and raw digests are rechecked before publishing the marker and before metadata writes. These best-effort checks plus the operation lease serialize cooperating callers; they do not make the final check and rename atomic against external writers. Completed markers are retained as the metadata archive. Existing targets, backups, packages and private proxy data are untouched; the migration transfers no service ownership.

Machine leases use the machine ID, so two IDs targeting one HOME can overlap. A bounded isolated regression records this limitation. No HOME-wide locking contract is introduced here; callers must avoid that overlap. Native host and platform validation is independent of isolated tests.
