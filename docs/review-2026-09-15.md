# 工具链与适配器修复复审

## 最终行为

本次承接未提交补丁，补做 fresh reviewer 独立评审。sync 接受 Node 24.2.0 起的 24.x 和 npm 11.x；run 检查相同 Node 范围；生成锁仍要求精确 Node 24.14.0 / npm 11.19.1。

此前交接中的“Node 24.1.0 现在可以运行”结论已纠正。DSH 入口使用 `import.meta.main`，[Node 官方文档](https://nodejs.org/download/release/v24.3.0/docs/api/esm.html#importmetamain) 记录其从 24.2.0 提供；[既有原生验收](upstream-verification.md) 已记录 24.1 空退出。版本预检放行不等于完成该版本的原生验收。

## 保留的修复

- 工具链使用严格 ASCII 三段版本解析，拒绝前导零、多行及非 ASCII 数字；无效实际输出隐藏。Node/npm 版本错误含期望值、有效实际版本及文档指引。
- 去掉 lock-policy、manifest、lock schema 中未消费的 node_distributions，去掉 agent.toml 中未消费的 ownership 声明；未知字段仍失败。
- checked 的失败诊断包含命令及退出码，不回显子进程 stdout/stderr。
- Adapter 补齐 dependency_backend、shared_files、launch_preflight、prepare_runtime、capture_projection、capture_configuration 的公共方法及默认行为。
- DSH 依赖来源路径参数化；DshBackend 将实际 adapter declaration 版本传给锁校验和解析。
- README、入门教程和操作文档区分日常版本范围、精确锁解析与已有原生证据。

可选的 status 元数据缓存已撤回。每次 status 都重新计算完整 node_modules 形状、链接目标及包清单摘要，并逐项核验 REQUIRED_FILES；磁盘 marker 和进程内元数据均不能代替正文验证。这仍不是对全部普通依赖文件正文的完整安全审计。

## 独立评审发现及处置

| 发现 | 处置与回归 |
|---|---|
| 同 major 比较重新接受已知不工作的 Node 24.1 | 加入 Node 24.2.0 下限；sync/run 覆盖旧版本拒绝、兼容版本接受、跨 major 拒绝 |
| 非 Node/npm 的 preflight 即使版本完全匹配也失败 | 其他工具保留精确比较；非 npm 后端完整命令测试覆盖成功与脱敏失败 |
| seal 计算摘要后再采集 stamp，可能信任中途变更的包清单 | 撤回缓存；故障注入覆盖 seal 期间修改清单后必须判为 damaged |
| metadata-only 缓存仍可能漏掉同长度修改 | 独立 reviewer 在真实文件系统的 20 次合成循环中观察到 11 次 stamp 相同但正文摘要不同；最终版本不依赖时间戳证明正文未变，保留恢复 mtime 的回归 |
| 原快路径的逐项 Path/JSON 开销大于完整摘要 | 随缓存一并撤回，不声称此次提升 status 性能 |

复审还修正了 stale-lock 测试的 monkeypatch 参数签名，避免错误地依靠 TypeError 被包装后“通过”。新增精确锁解析测试确认版本不符时不调用安装命令、不改写仓库锁。
