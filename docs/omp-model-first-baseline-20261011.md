# OMP 新标准路由基线重测

日期：2026-10-11。结果：**模型优先路由验收未通过**。

本轮复用原有 11,473 条合成公开场景，不修改命令、历史解析预期或历史审批标签。
新标准见 [产品验收草案](omp-permission-acceptance.md)，独立路由契约见
[routing-policy.json](../tests/fixtures/omp/permission-product-acceptance/routing-policy.json)。

## 验收口径

无明确前置配置/拒绝规则时，命令应先进入模型。解析器不认识语法不能直接转人工。
源集合含 11,472 个非空命令及 1 个空字符串；空字符串保留为参数校验样本，
须阻止且不弹出权限询问，不作为权限路由例外。Shell 语法不确定仍应交模型判断。
这一区分在测量前固定，未按生产解析结果或旧 `expectedGate` 生成新期望。

本轮假模型统一返回有效 `ask`，假 UI 选择拒绝，全部待审命令不执行。
通过意味着先审查再正确处理 ask；不意味着低风险任务免确认完成，也不证明模型判断质量。
路由前人审与模型 ask 后人审分别计数，不能将后者当作故障。

## 测量结果

通过公开插件入口分别测量 raw `permission_bash`、原生 Bash 和原生 zsh，原生设置/执行上下文由假运行时提供。
共 34,419 次路径观察；三条路径各自覆盖全部 11,473 条源记录，结果一致。

## 隐私检查的单独观察

12 条敏感输入门控场景使用 `REDACTED` 等合成公开占位符，包含 API key 参数、查询或示例等秘密形状。
按本轮固定契约仍计路由失败，但不能据此宣称真实凭据应该发送到远端，或推导真实隐私误判率。
修复设计必须区分正文中的秘密、读取秘密的操作意图及已脱敏文本，保留真正的秘密保护。

另有独立合成消息对照：同一 `pwd` 调用，用户消息为 `Authorization: read-only query` 时，
三路径均未进入模型并产生 `SENSITIVE_INPUT`；改为 `User permits: read-only query` 时均进入模型。
前者没有凭据正文，说明词面匹配会误伤许可描述。此观察与原集合分别报告，不更改原集合标签。
