## 3. 高优先级：macOS recovery-grants存在静态可定位的缺陷

位置：`src/agentcfg/pi_validation_recovery.py`的`_run_recovery_case_darwin()`。

1. 第55行创建`gate_read/gate_write`，把读端交给helper。读到ready握手后，整个函数没有向`gate_write`写入`G`或关闭该写端。`scripts/pi-supervisor-macos.c`第285行明确等待此放行字节；owner目标不能启动，后续等待owner/worker文件会超时。这不是必须上macOS后才能发现的问题，应补完整握手流程的替身回归。
2. 第98行要求`owner.wait()`等于`-SIGKILL`。这里的Popen对象是helper；C helper在受监督child被SIGKILL后返回`128 + signal`，即137，而不是helper自身被信号杀死的-9。需要按helper实际退出/收据契约核验。
3. `scripts/pi-native-recovery.py`第56—62行在owner死亡前已经主动停止worker并留下收据。此流程不能证明“owner崩溃后，对仍活动的遗留worker进行显式停止恢复”。应区分“回收已结束执行”和“停止活动遗留执行”两类验证，不能用前者代替后者。
4. 第109行以`observe(...) != "alive"`作为`target_terminated`，把unknown也包含在内。终止事实应来自明确dead/有效终止证明。

应保留尚未实机执行的状态，但不能把当前代码定性为“只缺实机验证”。T098需据此重新审定；Linux已取得的历史通过不因这项复核被改写。
