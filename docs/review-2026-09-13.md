## 已复现问题

### R1 / P1：读取本地配置没有执行私人文件安全检查

位置：`src/agentcfg/config.py:45`、`src/agentcfg/config.py:60`、`src/agentcfg/cli.py:75`。

`init-local` 会创建 0600 文件，但后续加载使用普通 `Path.open`，没有检查既有文件的权限、属主、文件类型或链接。CLI 还会先 `resolve()`，使原始路径中的符号链接在检查前消失。

复现：创建 0644 本地 TOML，通过符号链接传给 `--local … validate`，返回 0。它不意味着本轮发生了密钥泄漏，但用户从其他地方复制或编辑文件后，即使文件可被其他用户读取，管理器也会接受，无法履行本地秘密文件的保护约束。

建议：选择 profile 和完整加载统一使用安全读取入口；打开前保留原始路径，检查私人目录、0600、当前属主、普通单链接文件和读取前后身份。权限异常应给出操作说明，不静默改用户权限。对应 DEP-01、CFG-06。

### R2 / P1：首次启动准备中断后无法正常重试

位置：`src/agentcfg/profile_runtime.py:18`、`:28`、`:51`。

首次准备先写 profile `package.json`，最后才记录 `.agentcfg-package-owner.json`。两者之间进程退出、磁盘错误或其他中断，会留下有 package、无 owner 的状态。下一次启动把自己创建的 package 判成“未接管”，持续失败；配置 apply/rollback 的 journal 没有覆盖这段包准备流程。

复现：在写 owner 时注入一次 IO 错误，移除故障后重试 `prepare`，仍报未接管冲突。

建议：为包拥有的 profile 初始化增加可恢复的准备记录，记录预期内容和绑定，重试时只恢复能证实归本次操作所有的产物；不能通过放宽首次接管规则解决。对应 CLI-04、LOCK-05。

### R3 / P2：损坏的运行包会被报告为已安装，sync 无法修复

位置：`src/agentcfg/dependencies.py:134`、`:144`；`src/agentcfg/runtime.py:44`。

安装状态只由 `.agentcfg-ready` 的内容和权限决定，不检查必需入口是否还存在。依赖被误删后，标记仍在就会让 doctor 报 installed，sync 返回成功且不做任何事，实际启动才失败。

复现：运行目录仅保留匹配的 ready 标记，没有 `node_modules`，`installed()` 为 true，`sync()` 返回 `installed=true, changed=false`。

建议：至少核验已安装 manifest 和必需运行文件，区分“未安装”与“安装已损坏”；提供受锁保护的暂存重建与明确修复方式，不删除账号和会话。对应 CLI-04、CLI-06、LOCK-04。

### R4 / P2：OAuth provider 参数通过校验后被静默忽略

位置：`src/agentcfg/dsh.py:93`、`:109`。

schema 和适配校验允许在选中的 Codex/Cursor provider 下配置 `provider_options`，但输出这些选项的 `_api_fields` 直接跳过所有 OAuth provider。配置看起来合法，实际没有作用。

复现：在默认配方加入 `provider_options.codex.reasoning="medium"` 和 `transport="sse"` 后，解析结果包含这些值，DSH 产物与未配置时完全相同。

建议：按锁定原生版本提供明确的 OAuth 参数映射及所有权；尚不支持的选项应在 validate 阶段拒绝，不默认认为静默省略可接受。对应 CFG-01、DSH-09。

### R5 / P2：锁文件没有验证当前平台和实际 adapter 兼容性

位置：`src/agentcfg/dependencies.py:72`、`:112`。

锁读取检查摘要和 npm 结构，但没有把元数据中的 adapter 版本与当前 adapter 比较，也没有校验当前平台是否在适用集合内。摘要一致仅能证明元数据自洽，不能证明兼容性。另外，生成新锁时上游 SHA 写死在函数中，未来升级需同步改代码，否则来源记录可能过期。

复现：在临时仓库副本中将平台集合改成只包含虚构平台，并将 adapter 版本改成不兼容值、重新计算正常摘要，`read_lock()` 仍接受。

建议：区分支持的平台和已执行的验证证据；校验锁 schema、实际 adapter 版本与平台，未实测平台明确报告。来源 SHA 从经核实的配方声明取得，不能仅复用旧常量。对应 LOCK-02、LOCK-03、LOCK-05。

### R6 / P2：存在待恢复部署时 sync 仍进入安装流程

位置：`src/agentcfg/dependencies.py:144`。

apply/rollback 会处理 journal，run/plan 会拒绝 pending 状态；sync 获得实例锁后没有检查 pending。上次进程已退出时，文件锁不会代替恢复状态检查，依赖修改仍可继续。

复现：在状态目录放置 pending 记录，调用 sync，假安装检查已经收到 `node --version` 调用，而不是先返回恢复待处理。复现于第一项假进程调用处终止，没有实际安装依赖。

建议：sync 在创建暂存目录和任何依赖子进程前拒绝未解决 journal，并提示先执行 apply/rollback 恢复。对应 DEP-05。

## 其他产品和扩展缺口

- capture 当前只支持 `terminalImages`。Spec CLI-07 的主题/模型选择场景还没有对应实现；文档虽然披露了范围，任务勾选不能视为这个场景已通过。需要补实现或明确调整该场景及验收状态。
- plan 将受管字段统一显示为 `<managed-field>`，技能路径显示为 `<managed-resource>`；保护了私有信息，但多个冲突时难以定位具体项。缺密钥的错误也没有指出缺少哪个引用。应提供安全且可操作的定位方式。
- 多工具的数据、渲染和部署核心已可复用；依赖及运行层仍有 DSH/npm 路径和命令耦合。接入 Pi/Codex 前应建立依赖后端的选择接口，并测试完整命令流程，不能仅增加一个 adapter 目录。当前文档已说明还需这些工作。
- 维护技能已提供有效指导，但仍缺独立 Agent 行为验收，尤其是局部修改 TOML 时保留秘密、注释和无关 profile。
