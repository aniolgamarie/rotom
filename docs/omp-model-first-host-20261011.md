## 已确认原因、修复及最终复验

追加额度已用 8/10，剩余两次未使用；命令始终只作文本审查，没有执行任何真实模型样本。
诊断不保存正文，仅保留受限的结束原因、长度、token 数和参数错误分类。

GLM 同一普通样本曾在 512 token 上限下成功但用了 491 token，随后复现
`stop_reason=max_tokens`、输出 token 数 512、最终文本为空。
旧客户端把推理与最终决定共用的输出额度固定为 512，确实可能在输出 JSON 前耗尽。
本轮将两种 API 的输出预算统一提高到 1024；明确达到上限且没有完整决定时记录 `REVIEW_OUTPUT_TRUNCATED`。
完整且严格有效的决定继续保留，未知响应形状仍拒绝，不补写 JSON，也不从 token 用量猜测截断。
最初那条 `REVIEW_JSON_INVALID` 的正文未保存，无法独立证明它也属于同一种截断。

Kimi 备用在预算已为 1024、请求仍显式携带 `temperature=0` 时返回 HTTP 400，
受限诊断识别为温度参数约束。客户端去掉该可选参数，使用 provider 默认值，不按模型名称硬编码温度。
这也符合官方 SDK 仅在调用方提供采样参数时才发送的行为；部分 Kimi 模型不接受任意温度。
[Kimi 官方参数说明](https://platform.kimi.ai/docs/api/models-overview)

## 失败及恢复记录

最初沙箱 UID 不匹配被文件保护拦截；实际 UID 的 `/tmp` 容量小于官方二进制，改到数据盘后又因共享祖先目录为非 sticky 0777 被保护拦截。
最终采用空间充足且符合保护要求的 `/dev/shm`，没有修改系统目录权限或生产 guard，也未删除他人的临时数据。
测试 helper 在用户命名空间内最初错误要求父目录仍显示宿主 root UID。
修复仅限验收脚本：进入 namespace 前记录私有父目录身份 fence，内部按精确 uid_map、目录 inode/dev/mode 及不同网络命名空间校验映射。
未将所有 overflow UID 加入可信名单；23 项合成 fence 边界检查通过。

脱敏 fixture 首次把 `credentials:` 同时当普通标题与已声明的凭据槽位，期望产生歧义。
修订为 `Synthetic test values:` 并事先固定独立期望；命令、503 备用、包一致、脱敏及计数断言未改，旧失败与版本差量保留。
真实 reviewer 脚本最初以原生显示名称查模型，匹配数为零，在子进程创建前失败，未发请求。
改为 catalog ID → provider/remote ID 的唯一匹配，预检通过后才执行获准三次请求；此修复未改模型配置。

详细报告、fixture 版本差量、受限启动诊断及预算账本位于被 Git 忽略的
`.cache/omp-model-first-host-20261011/` 和 `.cache/omp-model-first-live-20261011/`。
独立只读复核确认最终源码差量、真实结果、计数及新摘要一致，旧失败事实保持可追溯。
