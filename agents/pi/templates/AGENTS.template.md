# Pi 工作约定

## 实施与验证

遵循业务仓库的约定和用户授权；保持变更范围明确。读后再改，使用项目现有的构建和测试入口，
不得把未执行的检查写成通过。不提交秘密。代码注释使用中文、双引号、2 空格缩进；业务仓库有明确约定时以该约定为准。
提交只包含当前任务的文件，使用 conventional commit。是否提交、发布或合并遵循用户授权。

## 按实际能力路由

- 普通模式：父会话实施；`scout` 只读定位，`reviewer` 在新上下文中审查具体 diff/patch/源码。
  角色仅使用 read/grep/find/ls，无嵌套、记忆、shell 或写权限。传入完整任务、规则、路径和验收标准。
- managed 模式：通过 `kernel_task` 和 `kernel-orchestrate` 发起 inspect/fix；Task Keeper 管理候选、
  检查、审查与预算。缺少绑定模型、项目检查或监督能力时返回阻塞，不能改用普通角色假装完成受管流程。
- 外部委托：唯一入口是 `model_delegate` 与 model-delegate 技能。显式选择 backend/model、任务和工作区，
  七个用途模板只补充任务上下文，不产生第二层角色或授权。明确请求 Codex 时必须实际调用 Codex backend。
- 普通只读委托不能写；高级写操作需要显式授权、独立 worktree 与公共工作区写租约。
  managed worker 不得调用外部委托，不以其他工具绕开父级策略。

## 结果与控制

启动 ID 和通知不等于完成。读取终态、非空结果和本次 receipt，关联请求、模型、候选与运行身份。
检查结果和模型结论分别报告；失败、超时、空输出、未回收活动不能标为成功。
等待使用工具提供的 wait/poll 游标，不用 sleep 忙轮询。取消等待不等于取消任务。
恢复只使用已声明控制协议，不自行启动第二管理者、不复用旧 grant 或旧 receipt。

## 配置维护

配置、资源、依赖通过 agentcfg 管理。缺少必需插件、模型、凭据或能力时明确报告缺口。
不得从旧 Pi home、全局包目录或 cwd 自动补齐资源，不在会话中运行原生包安装和自动更新。
