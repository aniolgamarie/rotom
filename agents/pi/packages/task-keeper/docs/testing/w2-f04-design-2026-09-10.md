# W2/F04：有界诊断重规划契约（已实现，完整验收待收口）

原依据：v6 §18 的一次重规划可配置上限、D7、Finite semantic repair、任务9.7；设计思想要求模型调用用于尚需诊断的问题，而普通重试不应改名为规划。参考本机设计包`design-philosophy.md`的StepProposal原则及`design-v6.md`的资源/语义上限。

## 触发及合法变更

增加显式可选开关`features.semanticReplanning`，默认关闭；使用已有受限scout profile，开启且上限大于0时要求该角色已绑定/获准。模型不能靠项目配置打开用户未开的开关。没有新provider、插件、在线Advisor或通用规划器。

唯一初始重规划模板为“诊断后修复”：fix的可信必需构建/测试确认实现失败、原执行已终止、仍有语义/派发预算、且现有策略选择同路线修复时，在下一次writer前插入一个有界只读诊断step。诊断接收当前候选与原失败证据，writer接收诊断工件；依赖图实际发生变化，所以它区别于同图的普通重试。

环境错误、额度等待、未知终止、用户取消不触发该变更；没有预算不追加模型调用。已有cascade/critique保持各自受控路径，不把诊断变成新的无限策略组合。

## 身份、计数与恢复

TaskSpec封存`maxSemanticReplans`；原job的持久计划保存已用次数。每次成功提交图变更原子增加一次，超过上限拒绝；0禁止添加诊断step。普通retry、心跳和资源变化不计重规划，也不能清零计数。

原root目标、required/风险、workScope、候选和消费记录不变；同一次后续writer仍消耗原共享语义尝试和step/request预算。新增诊断step照常占模型/reader槽，并保留必需验收请求预留。重启、pause/resume与策略变化不重置已用次数。

重规划通过现有Scheduler的受控模板修改，不开放任意依赖、命令或角色参数。原阶段未确认终止时不能改图；新增图仍验证引用有效/无环。诊断失败阻塞其writer依赖，不能静默跳过并声称诊断成功。证据包的decisionRevision包含计划拓扑/重规划次数，旧建议不能跨图变更继续执行。

## 验收与退出

复用固定repair、环境失败、quota与plan/预算夹具，核对默认关闭/0、不超过1次、诊断先于下一writer、诊断工件确实进入writer输入、root required/次数不刷新、未知占用不改图及非法变更回滚。实际Pi夹具应观察新增read过程及最终独立验收，而非只增加一个计数字段。

实现和真实验证齐全后才关闭F04；本文件本身不表示重规划已交付。W3–W7的原故障、矩阵、实网与效果验收继续按固定清单收口。

## 已实施与定向验证

已按上述模板实现。开关为可选配置，关闭时保留原schema-6策略摘要；项目只能收紧。TaskSpec封存上限，Scheduler在同一事务更新图、plan-revisions和下一语义尝试，失败整组回滚。状态/doctor显示已用及有效限值；证据包的语义revision也包含图拓扑和次数。

新增4条F04回归（2条状态、2条实际Pi），复用原repair/配置/环境/quota夹具。实际Pi中连续两次实现失败、第三次成功，只插入一次diagnosis；诊断先读真实失败工件和候选，后续两个writer的实际输入都含从诊断工件读取的唯一标记。最终12个派发step、3次语义尝试、1次重规划，原required及用户主树保留。零上限则两次writer、8个原流程step完成，没有诊断调用。

原quota-recovery和两种环境失败场景开启此可选开关后继续通过，未生成诊断；并未把失败类别重命名为语义失败。状态检查覆盖0/1、重复请求拒绝、unknown不改图、持久重开、commit失败回滚。暂停期间候选改变时恢复重跑现有诊断step，重规划次数不增加；只重置writer而遗留失败诊断会使其永久阻塞，该边界已处理。

诊断的请求预留同时用于路线恢复选择和实际child admission；追加图前保留剩余必需step额度。图变更拒绝会阻塞并保留错误，不使finalizer抛出未处理异常。未新增任意DAG或新的provider/plugin假设。

完整故障/请求路径组合仍按W3–W5固定矩阵审核；本次定向验证不自动替代它们。
