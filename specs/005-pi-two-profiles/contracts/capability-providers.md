# 能力提供者与替换契约

状态：部分基础实现，产品替换流程仍在实施；已实现范围见第5节及plan.md阶段记录。对应R01–R03、R10–R16、R31–R37与M07。用户入口由能力定义，提供者可以是Pi原生能力、公开扩展、官方CLI或独立受管服务；不把所有提供者改造成同一插件接口。

## 1. 配置来源与准入

继续使用Pi依赖声明、`agents/pi/plugins.toml`、profile配方、资源manifest及现有schema。旧profile使用`agents/pi/dependencies.json`，`pi-base`/`pi-full`使用独立的`agents/pi/dependencies-modern.json`；固定路径和schema边界见第5节。下列字段是对这些记录的逻辑要求；任务阶段决定复用字段或最小schema扩展，不另造通用配置语言。

| 字段组 | 必需信息与校验 |
|---|---|
| 能力身份 | capability、契约版本、Base/Full归属、必需/可选、是否单owner；同一自动压缩、权限权威或执行队列不得选择两名owner |
| 提供者身份 | provider/source ID、来源类型、固定版本或内容身份、完整锁与许可证、公开入口；不能依赖latest或只有目录存在 |
| 兼容性 | Pi/运行时范围、公共接口、依赖能力、冲突能力、状态格式；未知字段/能力/不兼容必须失败 |
| 行为边界 | 已支持的操作、取消/恢复语义、权限投影、隔离覆盖及未覆盖项；不以工具注解代替验证 |
| 配置与数据归属 | 受管文件/字段、用户所有状态、秘密引用、会话/任务格式、旧恢复引用与卸载范围；不保存秘密值或其散列 |
| 维护信息 | 选型理由、候选验证、迁移/回退方法、弃维护处理、证据索引；没有兼容迁移时明确记录阻塞条件 |

未知提供者拒绝；不能在启动时联网搜索、自动下载替代品或按插件名猜接口。选择发生在显式配置/锁/部署阶段，运行和诊断只消费已部署选择。只注册profile所选资源，同时核对安装树以防Base隐式携带Full代码。

管理器失败沿用退出码：未知字段/配置冲突表达错误为2，凭据缺失为3，所有权/活动实例/恢复待处理为4，依赖缺失或原生兼容校验失败为5，文件系统/内部失败为6；原生宿主成功启动后的退出码保持原语义。诊断0可以附带待登录或漂移，不据此签发产品通过。

## 2. 适配位置

- 权限：仓库策略与一次许可是权威；公共Pi事件、文件/命令operations和监督者是接入点，市场插件返回值不能覆盖硬拒绝。风险reviewer只提供候选决定。
- 日常工具：优先Pi原生搜索/编辑、压缩与原生MCP/Code Mode；只在权限、取消、资源与错误语义的实际边界上加仓库适配。
- 委派：Pi/Codex调用共同delegate语义；Task Keeper消费它，不直接导入后端插件内部对象或复制队列。
- 持久服务：客户端只使用durable-service契约，SDK、SQLite及registry留在服务内部。不能让TK写Durable存储。
- 主题/footer等无执行副作用资源不强制实现执行器接口；普通资源仍核对来源、加载冲突及卸载残留。

这里允许仓库自有适配代码演进，不允许修改上游宿主、monkey patch全局宿主行为或依赖未公开模块。兼容既有配置可做明确迁移，不能默默丢字段。

## 3. 替换生命周期

```text
selected -> staged -> validated -> activation-pending -> active -> retired -> removable
staged/validated/activation-pending -> failed -> restored | recovery-required
active -> replacement-staged（原active继续拥有已有任务）
```

1. 保存原选择、配置基线、状态格式及恢复引用，记录替换意图；不轮换备份冒充成功。
2. 在隔离目录安装并验证候选。锁和资源集合先可审阅；验证不能修改旧实例或调用未授权账号。
3. 用同一能力契约验证允许、拒绝、取消、错误、卸载与恢复；不兼容不进入激活阶段。
4. 活动实例、许可、未知执行或待恢复数据仍依赖原提供者时，保留其包及状态。只在允许的空闲边界切换，不能强杀任务取得更新权。
5. 按现有三方部署激活。多文件失败使用pending记录恢复；不能宣称配置、数据库与进程跨系统绝对原子。
6. 新执行绑定新RuntimeIdentity/CapabilityBinding，未消费旧许可失效。相关旧通过证据标stale，历史失败事实保留；重新验收后才声明新组合支持。
7. 卸载只清理明确受管且无活动/恢复/必需证据引用的资源；不删除用户数据。旧版本不读取新格式数据库，回退按配置/运行包/数据分别执行。

同一会话跨提供者恢复只在明确证明格式和语义兼容时允许。不能复用名称相同但行为不同的工具、任务或registry条目伪装兼容。新提供者不接受旧grant，不能用更换后端来重试已拒绝或未知副作用操作。

## 4. 可验证结果

M07至少覆盖一组等价提供者替换、失败恢复及不兼容拒绝；同时验证实际安装/加载集合、Base独立性、用户状态哨兵和旧引用保护。两个替身可证明部署与选择机制；原生组合、操作系统边界和模型质量分别在实际层验收，不互相替代。

故障点包括：候选未装全、未知配置、重复owner、迁移前/后异常、激活中断、旧任务未停止、卸载仍被引用文件、重启时identity不匹配。失败后报告原提供者是否仍可运行、哪些文件已改、恢复下一动作，不能只显示“安装失败”。

## 5. 已实现的锁家族与候选生成边界

| 选择 | 依赖声明 | 构建配方 | 锁目录与schema |
|---|---|---|---|
| 旧profile及默认旧调用 | `agents/pi/dependencies.json` | `agents/pi/build/recipes.json` | `locks/pi/`，v1 |
| `pi-base`、`pi-full` | `agents/pi/dependencies-modern.json` | `agents/pi/build/recipes-modern.json` | `locks/pi-modern/`，v2 |

路径由`pi_lock_layout.dependency_layout`固定。显式family与profile冲突、schema不符或所选家族文件缺失都失败，不读取另一家族补齐。同名vendor文件不能跨家族取用。冷重建、原生验证、资产安装和`fetch-pi-assets.py --profile`沿用同一选择；该脚本省略profile时保留旧全量行为，指定profile时只获取其声明资产。

v2生成器要求显式能力/提供者/来源身份及`candidate`选择，核对资源归属、完整npm解析与选择绑定；不推测兼容性，不将来源ID直接当作能力ID，不自动写成current/accepted。生成前后核对配方摘要，输入改变即拒绝。现代package.json与package-lock.json使用两者内容派生的目录名，manifest最后发布；中断发布不会把旧manifest仍引用的文件对改写为新内容。这只说明候选文件发布顺序，不表示配置、资产和进程之间具有跨系统事务。

提供者的`verified_host_versions`仍为必填，可以为空；可选`candidate_host_versions`一旦存在就必须包含至少一个固定版本，两组不能同时为空。仅`candidate`选择允许使用候选版本，`current`/`accepted`只能使用已验证版本。兼容声明变化进入绑定和验收上下文身份，先前候选证据不能通过只改状态或填入旧摘要升级为验收通过。候选版本只表达待验证目标，不代表实际原生加载成功。

提供者可显式声明 `support_sources`，每条严格包含 `source_id`、`source_version`、`source_identity`。它表示该能力所需的辅助包或二进制，不创建新能力或新配置/状态owner。辅助来源必须在能力允许来源和profile范围内，与锁中内容身份及版本一致；无包版本的资产使用null，依赖内容摘要。主来源与辅助来源不得在同一提供者中重复，未知字段失败。所选提供者的主/辅助来源并集必须等于依赖切片的直接来源集合，全部进入验收上下文和实际安装核对；缺辅助来源不能用主包存在替代。多个提供者可共享同一精确来源，仍需各自明确声明。该字段不改变资源注册规则，也不会在运行时自动安装依赖。

现代自建原生资产使用互斥的 `build_record` 来源，旧URL资产保持现有行为；v1不允许自建记录。固定源码输入、构建记录、归档和许可证一并进入校验，记录recipe与内容digest进入来源身份。仅当前 `bubblewrap-v1` 配方已实现，详见[独立helper边界](../native-helper-build.md)。公共输入导入不产生正式manifest或验收证明，candidate仍在写入guard前拒绝激活。

声明了vendor_path的资产在解析前及发布目录写入前两次核验，范围包含聚合读取器会检查的未选来源。校验通过安全文件句柄流式核对SHA256；raw必须符合声明大小（上限4GiB），tar.gz上限128MiB。校验本身不下载；缺失、损坏、越界或错家族都以固定`pi-build-asset-input`在发布前拒绝，保留已发布manifest。外部主动损坏旧manifest引用的资产会使旧聚合锁暂不可读；发布失败保护不等于自动恢复外部改动，测试只在恢复被破坏输入后核对原锁身份。

候选读取/生成和正式安装是不同边界。`sync`在取得写入guard前拒绝candidate选择；生成候选不能替代兼容证据、验收记录或激活授权。已安装实例的启动与恢复继续依赖保存的运行包/回执身份，不重新绑定当前源码锁；锁家族拆分不自动迁移或删除旧包和状态。

候选生成/失败已有合成来源测试，自建helper已有真实内容导入与只读校验；真实现代Base依赖和构建配方当前登记9个直接来源、6个能力提供者与96个自有运行文件（25条TS、71条supervisor；2026-10-06完整计划Shell准备阶段）。所选Pi1.0.1仅列为候选兼容，尚未生成完整正式manifest或证明实际UI/宿主组合。显式文件摘要、精确安装核对及公开SDK启动入口已实现基础，Full实际提供者及完整替换/回退验收仍待完成。现有recipe_digest仍扫描较宽的仓库实现/资源集合，不能据此声称Full源码变化与Base构建身份完全独立。
