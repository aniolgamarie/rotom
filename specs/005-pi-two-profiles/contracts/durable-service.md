# Full持久只读服务契约

状态：设计，未实现。对应R25–R29、R32、R37和F11–F16、X01/X05–X08。初始候选是官方`@earendil-works/pi-durable@1.0.1`，单独Node进程和SQLite；不是将Pi前端进程挂后台，也不接管Task Keeper工作流。

## 1. 边界与本地连接

服务只为Full按需启动或连接。使用用户所有、权限受限的本地Unix socket，socket目录在任务不可写范围内；校验文件所有权、链接边界、连接用户和会话授权。首次显式持久任务可以按部署契约连接服务，普通启动/编辑/诊断不隐式启动服务或模型。

同一用户下的恶意本机进程不在工具隔离承诺内。受管子任务不可挂载服务控制目录或认证材料；“peer UID相同”不代替请求范围校验。客户端不能通过JSON自报管理员、扩大读根或改变模型路线。

请求至少包含协议版本、requestId、操作、既有taskId（如适用）和非秘密输入；授权由可信连接与已部署任务配置确定。未知字段或版本拒绝。逻辑操作为submit/status/message/continue/cancel/result/watch；CLI命令名在实现时接现有管理入口，本文件不声明新命令已存在。

同requestId同规范请求返回同身份；同ID不同内容冲突。查询状态、结果、订阅和重连不能隐式启动scheduler、重试模型或恢复任务，不能使用会推进工作的SDK wait接口实现只读查询。

## 2. 单owner与持久化

- 启动顺序为校验部署身份/私有目录→原子取得owner锁→检查旧owner与格式兼容→打开存储→读取并核对未完成任务→按可证明安全的范围恢复。owner占用或未知不启动第二服务。
- owner记录绑定boot/process birth身份及服务版本；PID、超时心跳或文件缺失不能单独证明可接管。锁保持至服务退出和写活动结束。
- 首选官方SQLite存储，经公开数据库适配配置并验证同步持久化（目标WAL与FULL）。不能私改SDK内部连接；若正式包不暴露可配置的公共适配，换已验证公共存储适配或阻塞，禁止以默认设置冒充断电持久保证。
- 服务任务/文档由Durable存储拥有。预算与模型发送账本只记录外部调用的授权和结算事实，不生成另一套任务队列；不与TK数据库共表或双写同一权威任务状态。
- 对用户确认受理、发出外部调用、报告结果前必须完成对应持久写入。存储满、只读或持久化失败时停止新副作用；无法保证已经确认的记录可恢复时保持recovery-required。
- 数据迁移先关闭所有者并验证副本恢复；registry、SDK及数据库格式一起形成恢复身份。不得打开不兼容新库后再尝试退回旧代码。

持久化保证以测试过的本地文件系统与存储设置为边界；不承诺抵抗介质损毁。进程崩溃、宿主重启、存储损坏和断电窗口分开验，不把进程kill测试当断电证据。

## 3. SDK适配和版本规则

只使用发行包公开的Harness、Registry、Storage、受限自定义工具及模型Provider注册能力。SDK是可替换实现，不把其内部状态直接当作Rotom公共协议。

部署时固定registry提供者和契约版本；服务端显式选择工具清单，禁止注册完整CodingTools后只靠提示词说只读。业务文件仅允许受限读取/搜索；专用状态、日志及任务产物可以写，不提供任意Shell或向业务位置发布产物的能力。

初始版本不在任务进行中热替换registry。所有phase、call与恢复记录绑定原registry身份；客户端改cwd/工具/策略应作为新的受管操作检查，不能直接调用SDK configure/uninstall绕开在途任务约束。旧registry缺失时保留任务不可恢复原因，不自动使用同名新版代码续跑。

SDK设置显式关闭未知隐式模型重试；压缩及后台总结也经同一计量和发送准入。配置字段不存在或无法覆盖某种调用时，对应路径不开放，不能用统计看似零来证明没有请求。

## 4. 模型请求的发送与恢复

公开模型Provider适配是唯一发送入口；把调用方身份、任务/phase、实际模型、输入/策略和预算绑定成一次attempt。此适配只包装公开提供者接口，不覆盖全局fetch、不修改宿主。

```text
prepared/reserved -> sending（先持久记录） -> result-recorded -> settled
sending -- crash/response-lost --> unknown（预留仍在）
prepared -- proof-not-sent --> not-sent（可释放预留）
unknown -- reconciliation/explicit new authorization --> new bounded attempt | settled | blocked
```

在sending记录与实际网络发送之间仍有不确定窗口；崩溃恢复无法知道是否发出时必须保持unknown，不能通过重发获取答案。单次调用结果落盘后再通知任务推进，响应重复按attempt身份归并。服务恢复发现unknown时，阻止该任务后续付费调用，但不使无关任务永久不能查询或执行。

SDK的resume、submit或wait可能启动调度。恢复服务必须先执行准入核对；即使调度开始，Provider发送入口仍必须对unknown拒绝自动发请求。若所选公开接口不能证明所有模型/压缩/重试调用经过此入口，Q5不通过，Full持久能力保持未交付。

读取重放仅在工具明确允许且输入/授权身份仍一致时进行；只读不等于免费或无敏感访问。Model request重放不因工具标记为safe自动获准。运行中的请求被取消后仍可能产生费用；有证据才结算，未知不计为零。

## 5. 观察、继续和取消

- watch提供当前快照和有界后续更新，慢客户端可收到快照重置标记；不保留无限日志，前端断开只移除订阅。
- message/continue绑定同一task与requestId，区分补充当前任务与新授权尝试；不自动新建任务冒充恢复。
- cancel先记录请求并撤销未用许可，再通知所有受限工具和Provider中止；收到请求不代表停止。只有SDK任务静止与外部活动终止可核对，才报告terminated/canceled。
- 执行状态、返回内容、费用结算和证据有效性分别记录。结果可取不代表所有后台工作已停；服务不可用不把请求降级为普通短任务。

## 6. 验证切点

默认替身层覆盖owner竞争、重复ID/冲突、发送前后掉线、commit失败、取消迟到、registry替换、只读越界、磁盘满、数据迁移失败及只读查询零推进。独立进程层核对真实owner锁、重启与存储设置；原生层验证Pi产品入口断前端后服务存活；live层才评价账号/模型调用与真实用量。

必需oracle至少包括外部请求计数、受保护文件哨兵、原任务ID、预算累计、owner数量和物理停止事实。任何未知窗口都不能因演示成功而删掉；整个恢复契约不承诺外部副作用exactly-once。
