日期：2026-10-04。范围：本目录的规格、设计、任务与验收定义；不是产品实现的 T098 最终审查，也不签发产品通过。

## 结论与范围

计划保留原36条需求，并按用户本轮补充增加R37插件可替换性；共37条需求、100个实施任务和63个验收状态项，另有8个跨领域不变量场景。当前 Linux x86_64 为唯一必需平台；Mac等按需。Base是中间交付，Full中的统一委派、Task Keeper、Durable以及模型审批能力仍须交付。模型审批默认关闭不豁免启用态质量验收。

规划阶段的独立审查未发现未关闭的HIGH/CRITICAL设计矛盾。此结论不证明公开接口、沙箱、真实模型质量或恢复行为已经通过；Q1–Q5均有实施实验与明确出口。禁止以计划完整性代替实现证据。

## 审查过程与修正

参考包和代码证据由主代理与独立证据代理核对；设计代理编写实体、契约和验收定义，并只读审查其未负责写入的主计划等文档。主代理统一取舍、复核需求覆盖和文档一致性。修改期间的审查属于阶段性证据，最终以写入结束后的稳定内容复核为准。执行模型按当轮工具实际配置记录；新的长期执行遵循当前AGENTS.md及角色配置，不沿用旧的固定模型要求。

| 发现 | 修正及约束 |
|---|---|
| Base可能被共享依赖、全局资源或Full专用Skill污染 | 同时验package/lock/资源/安装树/实际加载；数据库领域知识保留，共享Skill不携带Full调度 |
| 主会话认证和Codex委派认证混淆 | Base单独验Pi认证，Full另验Codex；不为Base安装Codex，不复制OAuth token |
| 固定命令沙箱被误当作日常Shell或整个Pi的隔离 | 日常Shell设Q2实测；逐入口覆盖矩阵；Q3独立验证整进程，缺组件不能证明技术不支持 |
| 模型批准被解释成权限或隔离保证 | 硬策略、可信意图、一次许可和OS执行分层；模型无权越过deny或扩权 |
| 可选启用被解释成可不实现审批能力 | Full关闭态零调用及启用态质量均必需；未授权质量评测保留未完成 |
| 单次review禁止重试可能误禁止所有恢复 | 仅禁止该审查调用隐式retry/fallback；TK有界返工与只读对账按预算继续 |
| 多profile的Writer与外部编辑边界不清 | 受管入口共享原子租约；外部编辑使快照失效；未知执行先对账，不自动重派 |
| 服务、delegate和TK重复掌握恢复 | 明确一个存储owner和各层权威状态；取消确认与实际停止分离 |
| 失败检查可能被丢成无效证据 | 可信执行失败是有效的失败证据；非零、零测试、全跳过均不通过 |
| heartbeat/日志增长可能让所有证据自我失效 | 语义输入与观测数据分离；预算实时准入，实际相关输入变更才使旧结果stale |
| 候选Q4/Q5结果可能冒充最终组合通过 | T059、T078仅候选可行性，不更新正式依赖；选定正式组合后重新验收 |
| 一次性回退可能误授权删除活动旧包 | 保留活动实例或恢复引用；配置、运行包、数据恢复分别验收 |
| 两处拟议路径误写成现有路径 | quickstart修正为test_pi_validation_runtime.py，T021改为pi_login.py/pi_host.py |
| 委派模型规定和最终审查时点更新 | 计划遵循最新AGENTS.md角色配置；最终审查固定写入后的稳定内容 |
| 插件市场变化可能把产品绑定在某个包上 | 新增R37/M07；按能力和稳定行为隔离具体提供者，复用清单/适配器，选型状态显式记录，验收替换、卸载及失败恢复，不建立通用插件平台 |
