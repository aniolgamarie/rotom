## Clarifications

### Session 2026-09-24

- Q: 本次是否需要支持将已经在用的 OMP profile 原地纳管，并继续使用其中现有的登录状态和会话？ → A: B，只新建独立环境；允许重新登录，仅导入非秘密配置与资源，旧环境的登录状态和历史会话保留原位，不做原地纳管。
- Q: OMP 首版纳管需要覆盖全部配置类别，还是先交付核心配置，其余后续补充？ → A: A，完整覆盖模型/provider、模型角色、规则、完整技能包、提示词、主题/快捷键、扩展和 MCP；每类都有实际可用的纳管能力与验收样例，不要求支持全部原生字段或所有插件。

- Q: 本机不具备 macOS、Linux arm64 与真实账号/模型验证环境，如何处理？ → A: 用户明确将这些平台实机、真实登录、真实 usage 和指定模型调用转为独立遗留，不纳入本 spec；保留未验证状态，当前以隔离验收与本机 Linux x64 无账号 smoke 收口。见[范围修订](scope-change-20260924.md)。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用统一入口管理 OMP 配置 (Priority: P1)

作为维护多个 Agent 的用户，我希望通过现有管理入口选择 OMP、复用公共配置和资源，审阅部署差异、部署、检查、启动、捕获允许的本地修改及回滚，而不再维护一套互相脱节的 OMP 配置同步流程。

**Why this priority**: 完整配置生命周期是本次纳管的核心价值，单纯增加一个启动别名不能满足需求。

**Independent Test**: 使用一个虚构 OMP 配置集和受控运行环境，完成校验、渲染、差异预览、部署、重复部署、捕获和回滚；检查预期资源、状态及失败结果。

**Acceptance Scenarios**:

1. **Given** 公共模型、规则、技能和 OMP 设置已声明，**When** 用户选择 OMP 配置集并预览部署，**Then** 用户能看到目标身份、受管范围和具体差异，预览不修改原生目标。
2. **Given** 差异无冲突且运行依赖已准备，**When** 用户部署并启动，**Then** OMP 使用已部署配置和资源；重复部署不产生多余写入或轮换备份。
3. **Given** 原生设置被用户修改，**When** 用户再次预览、部署或捕获，**Then** 未受管内容保留，单方原生漂移可见，双方冲突阻止覆盖，捕获仅产生允许的非秘密提案。
4. **Given** 部署中断、目标活动或恢复未完成，**When** 用户重试部署或回滚，**Then** 不发生不安全写入，用户获得可操作的恢复提示；成功回滚不删除新增的非受管数据。
5. **Given** 输入含未知字段、无效引用或未支持能力，**When** 用户校验，**Then** 明确失败并定位问题，不静默丢弃配置，也不加载扩展执行代码。
6. **Given** 首版必交的八类配置各有一个支持范围内的样例，且主题与快捷键分别有样例，**When** 用户通过统一流程声明、部署并在授权的原生验收中使用，**Then** 各类均按预期生效，不能将整类标为不支持后认定首版完成；各类同时具备可离线重复的隔离验证，真实验收未执行时明确记录。

### User Story 2 - 明确选择与隔离两层 Profile (Priority: P1)

作为同时使用多个 OMP 工作环境的用户，我希望 rotom 的配置配方与 OMP 的原生身份有明确、稳定的对应关系，切换配置集后能知道使用哪套设置、登录状态和会话，并保留 OMP 原生 profile 的可理解行为。

**Why this priority**: 错误的 profile 映射会导致配置生效于错误账号或会话；原生能力不能仅凭目录名称推定兼容。

**Independent Test**: 建立两个 OMP 配置集、原生默认 profile 和两个命名 profile 的虚构样本，覆盖选择、继承、环境覆盖、目录重定向及碰撞，比较所有配置和状态哨兵。

**Acceptance Scenarios**:

1. **Given** 两个受管 OMP 配置集，**When** 分别部署、启动和查看用量，**Then** 每个配置集稳定对应一个明确的原生 profile；配置、账号、会话、缓存、部署状态、备份和活动锁不会混用。
2. **Given** 调用环境或透传参数指定了另一个 profile、原生目录或配置覆盖，**When** 用户选择受管配置集，**Then** 管理器拒绝会改变已部署身份或绕过受管边界的冲突，不静默切换，也不自动退回默认 profile。
3. **Given** 用户需要原生默认 profile 的快捷键继承或项目资源，**When** 查看有效配置来源并显式启用相关来源，**Then** 可解释来源及覆盖关系；非受管原文件保持不变，命名 profile 的账号和会话不因此合并。
4. **Given** OMP 数据路径受已有目录布局影响，**When** 相同配置集在不同目录布局下运行，**Then** 有效身份和路径符合部署记录；无法保证时在启动前失败，不能只因为设置了一个环境变量便宣称隔离成功。
5. **Given** 两个配方试图绑定同一原生身份，或用户修改已绑定身份，**When** 用户预览或部署，**Then** 报告碰撞或需要显式迁移，原账号和会话不被覆盖、复制或丢弃。

### User Story 3 - 安全迁入已有 OMP 配置与资源 (Priority: P1)

作为已有 OMP 使用者，我希望先了解哪些非秘密配置可以纳管、哪些保留原生维护、哪些不兼容，再将选定配置导入新建的独立 OMP profile。新环境可重新登录；旧环境的登录状态和历史会话保留原位。

**Why this priority**: 在新环境复用配置能减少重复设置，同时保留旧环境作为可继续使用的独立环境；本次接受新环境重新登录，不要求迁移账号和会话。

**Independent Test**: 用含设置、规则、技能、扩展、未受管文件及虚构认证/会话哨兵的来源目录生成迁移清单，并在独立目标演练冲突、中断与恢复。

**Acceptance Scenarios**:

1. **Given** 用户明确指定配置来源，**When** 生成迁入清单，**Then** 每项设置和资源均标为纳入、原生保留、替代或不支持并说明理由；认证、会话、日志、缓存和历史备份不进入公共配置清单正文。
2. **Given** 已有原生默认或命名 profile 可作为配置来源，**When** 用户首次纳管，**Then** 仅将选定的非秘密配置与资源导入新建的独立 profile，并提供差异；旧 profile 的配置、账号和会话保持不变。若目标身份已被非受管环境占用，报告所有权冲突，不提供原地接管。
3. **Given** 技能包含相对引用、脚本和资源，或扩展仅在 Pi 验证过，**When** 纳入 OMP，**Then** 技能保持完整资源关系；扩展有独立的 OMP 兼容结论，不以 Pi 可用推定 OMP 可用。
4. **Given** 旧同步流程指向已有原生环境，**When** 用户启用新的受管环境，**Then** 新旧目标分离，不改写旧同步流程；若发现另一管理器写入新目标则拒绝部署，并说明如何退出新环境继续使用旧环境。
5. **Given** 新环境尚未登录，**When** 用户按说明显式完成原生登录后启动或查询用量，**Then** 使用新 profile 自己的认证状态，不借用或复制旧环境的凭据与历史会话。

### User Story 4 - 在统一入口查看 OMP 订阅用量 (Priority: P2)

作为订阅多个模型服务的用户，我希望通过 `agentcfg usage` 查看 OMP 能提供的账号额度和窗口信息，复用原生认证、缓存和查询能力，并明确这些信息属于哪个运行环境。

**Why this priority**: 这是文档中已批准延期的 OMP 直接遗留事项，可独立交付并验证。

**Independent Test**: 使用假 OMP 程序和虚构账号输出，验证参数、标准输出、标准错误、退出码、缺失程序、无账号、部分服务失败及 profile 作用域。

**Acceptance Scenarios**:

1. **Given** 未显式选择受管配置集且 PATH 中有 OMP，**When** 调用 `agentcfg usage` 并传入原生查询参数，**Then** 按原生 OMP 上下文执行用量命令并透传参数、输出和退出码，不要求先创建受管配置、不读取 rotom secrets、不额外遍历其他 profile；rotom 实例、部署文件和受管 profile 目录哨兵保持不变。
2. **Given** 明确选择了受管 OMP 配置集，**When** 查看用量，**Then** 使用与启动一致的已部署原生身份和运行依赖，不因 PATH 或环境差异查询另一个账号环境。
3. **Given** OMP 不存在、没有已登录账号、服务查询失败或不支持某个用量来源，**When** 查看用量，**Then** 缺失程序返回管理器退出码 5；已成功启动原生程序的情况保留原生结果，文档解释其边界，不将无数据编造成零使用量。
4. **Given** 国内智谱、国际 Z.AI、Kimi 或 OpenAI 的用量支持程度不同，**When** 用户查询，**Then** 不混淆服务身份、不承诺上游没有提供的额度数据，不抓取浏览器 Cookie，也不另建订阅凭据管理系统。
5. **Given** 查询会刷新原生用量缓存或认证状态，**When** 用户显式调用用量命令，**Then** 这些副作用由对应原生上下文承担；命令不自动安装、部署、发起登录或调用模型生成内容。

### User Story 5 - 可复现准备依赖并核实支持状态 (Priority: P2)

作为维护者，我希望 OMP 与所选扩展的来源、版本和兼容性可追溯，更新失败后仍能使用上一套运行包；文档准确区分规格已完成、隔离测试通过和真实宿主验证通过。

**Why this priority**: 只有可复现安装与真实能力证据才能长期维护 OMP，不能让纳管依赖偶然存在的全局安装。

**Independent Test**: 用受控依赖与运行替身验证锁、同步、失败激活、缺失包及版本不匹配，同时检查遗留问题到需求和证据的映射。

**Acceptance Scenarios**:

1. **Given** 已声明 OMP 及相关依赖，**When** 用户显式锁定和同步，**Then** 依赖身份完整可追溯，只有验证成功的运行包可激活，失败不破坏上一可用版本和原生身份。
2. **Given** 运行包缺失、不兼容或配置尚未部署，**When** 用户启动受管实例，**Then** 得到对应失败及修复提示，不隐式安装或部署；现有 DSH/Pi 的配置与状态不变。
3. **Given** AGENTCFG-F01 纳入本次交付，**When** 更新遗留问题记录，**Then** 能找到对应需求、验证结果及剩余限制；其他工具的独立缺陷不被误标为已解决。
4. **Given** 仅完成隔离验证，**When** 汇报 OMP 支持程度，**Then** 明确真实宿主、账号查询和未覆盖平台尚未验证，不把文档、任务勾选或假进程结果当成真实使用成功。

### Edge Cases

- 原生 profile 名为空、仅空白、保留默认名称、含路径穿越，或不同名字解析到同一身份。
- profile 选择参数重复，原生新旧环境变量同时存在，或透传参数试图覆盖受管身份。
- 命名 profile 忽略部分目录覆盖，已有数据/缓存目录改变原生实际位置。
- 默认快捷键存在但命名 profile 未覆盖；项目配置、外部工具配置或全局资源意外参与发现。
- 原生设置会在启动或交互后持久化，或者旧格式会由宿主迁移；下一次部署不能吞掉漂移或把原生迁移误当成管理器成功。
- 配置目标与认证或会话数据共享物理存储时，不能整文件复制、捕获或备份秘密；不能安全区分的项目应拒绝纳管并说明原因。
- 迁移目标非空、归属不同、路径含链接、权限不符，或原生/受管实例正在使用同一身份。
- 用量缓存过期、只返回部分账号、未登录、凭据过期、断网或原生非零退出；透传命令不能伪造成功。
- 受管配置重命名或变更状态根目录，不能借此规避原身份活动锁或产生第二个写入者。
- Pi 资源在 OMP 中遇到不同的接口或加载规则；声明不兼容必须优于静默漏载。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 将 OMP 作为独立可选工具纳入现有配置生命周期，支持校验、渲染、预览、部署、检查、启动、允许范围内的捕获和回滚，复用公共配置来源与机器覆盖规则。
- **FR-002**: 系统 MUST 在首版实际交付模型/provider 选择、模型角色、规则、完整技能包、提示词、主题/快捷键、扩展和 MCP 八类配置的纳管能力，其中主题与快捷键均须覆盖。每类至少提供一个可用配置或资源的完整验收样例，验证声明、部署和原生生效；不得仅列出“不支持”、保留原生手工维护或推迟整个类别来视为完成。能力清单必须明确每类支持的字段或资源及限制，不要求覆盖全部原生字段或所有插件；超出支持范围的输入明确失败。
- **FR-003**: 系统 MUST 校验未知字段、引用、覆盖许可与能力，并保持现有对象合并、数组替换、空数组和 false 的语义；仅原生未受管字段可原样保留，不能以保留为由放过未知公共字段。
- **FR-004**: 系统 MUST 在任何写入前展示或允许预览受管目标、配置差异、归属及冲突，并保留现有三方比较、幂等部署、上一版备份与中断恢复契约。
- **FR-005**: 系统 MUST 区分“rotom profile 配方”与“OMP 原生 profile 身份”，对每个受管配方形成可查询、稳定且唯一的绑定；首次纳管仅为各配方新建独立原生命名 profile，不绑定已有非受管 default 或命名 profile；后续操作复用该受管身份。
- **FR-006**: 系统 MUST 使部署、检查、启动、捕获、回滚及受管用量查询使用同一原生身份，禁止两个受管配方同时拥有同一身份；身份变化必须作为显式迁移报告。
- **FR-007**: 系统 MUST 隔离各工具/profile 的受管设置、原生账号与会话、实例状态、备份和锁；缓存及原生共享设施必须明确作用域，不能把原生 profile 支持等同于全局进程级隔离。
- **FR-008**: 系统 MUST 校验原生 profile 名、选择优先级、目录覆盖和环境冲突；受管调用不得通过透传参数或继承环境改变已部署身份，不得悄然回退默认 profile。
- **FR-009**: 系统 MUST 明确默认 profile、命名 profile、快捷键继承、项目配置、外部工具发现及配置覆盖层的关系。受管模式默认不引入未声明的外部或项目来源，用户显式启用的来源应可解释、可验证；不修改原生默认文件来消除继承。
- **FR-010**: 系统 MUST 在所支持的目录布局下核实有效原生路径和身份，无法兑现绑定或隔离时在运行前失败；原生目录重定向或格式迁移不得改变管理器声明的所有权边界。
- **FR-011**: 系统 MUST 为用户明确选择的 OMP 配置来源生成资源清单，对每项给出纳入、原生保留、替代或排除与原因，并提供导入新环境前的差异、目标独占写入检查及恢复说明。
- **FR-012**: 系统 MUST 仅支持新建独立环境后导入非秘密配置，不提供已有非受管 profile 的原地纳管，不复制或迁移登录凭据与会话。旧环境的配置、账号、会话及其他数据保持原位；新环境允许重新登录，使用说明必须给出针对新受管身份的显式原生登录路径，配置管理命令不自动发起登录。
- **FR-013**: 系统 MUST 只捕获允许的非秘密字段和资源，不将认证、trust、会话、日志或缓存当作公共配置迁入，不整库或整目录导出。
- **FR-014**: 系统 MUST 维持秘密与普通配置的隔离，秘密不得进入公共配置、渲染结果、差异、摘要、异常及配置备份；无法安全分离的数据应保持原生管理，所需外部秘密仅按已部署引用在运行时解析。
- **FR-015**: 系统 MUST 保留技能的完整资源和相对引用；对 Pi 或其他宿主来源扩展逐项核实 OMP 兼容性，不因已有适配补丁、同名能力或来源相近直接视为支持；配置处理不得执行技能或加载扩展。
- **FR-016**: 系统 MUST 对受管 OMP 与选定依赖提供完整来源和锁定身份，显式同步后验证再激活；失败不得破坏上一运行包、原生账号 home 或其他工具实例。
- **FR-017**: 系统 MUST 保持命令副作用边界：配置校验、渲染、预览、部署及默认检查离线运行；锁定、安装、部署、启动分别显式进行，启动不隐式安装、部署或登录。
- **FR-018**: 系统 MUST 落实 AGENTCFG-F01，提供 `agentcfg usage` 到原生 `omp usage` 的薄封装，原样传递原生查询参数、标准输出、标准错误和已启动子进程退出码。
- **FR-019**: 系统 MUST 保留无需受管配置即可使用的原生用量模式：从 PATH 查找 OMP，遵循该调用的原生上下文，不额外扫描或聚合其他 profile，不读取 rotom secrets，不创建或修改 rotom 实例、部署记录及受管 profile；无程序时退出码为 5。原生查询自身的副作用按 FR-024 处理。
- **FR-020**: 系统 MUST 支持显式选择受管 OMP 配置集查询用量，使用与其启动一致的已部署身份和运行依赖；两种用量模式及参数边界必须明确，试图改变受管身份的冲突参数在启动前以退出码 2 拒绝，不让原生查询参数被误吞为管理器选项。
- **FR-021**: 系统 MUST 将“所有已登录账号的用量”限定为选中原生上下文可访问的账号，不自行跨 profile 扫描认证存储、导出凭据或新建一套用量采集与订阅认证系统。
- **FR-022**: 系统 MUST 保留原生无账号、不支持、部分失败、缓存及窗口信息的语义；不得把缺失数据写成零用量，也不将原生成功退出改写为管理器自创错误。面向用户的限制说明不得污染原生机器可读输出。
- **FR-023**: 系统 MUST 在实施前重新核实 OMP 用量入口和国内智谱的官方支持范围，区分国内智谱、国际 Z.AI 及其他 provider；优先复用 OMP 上游支持，继续排除 Cookie 抓取及独立订阅接口采集。
- **FR-024**: 系统 MUST 仅在显式用量调用中允许其原生网络查询、缓存和认证刷新副作用，不自动发起交互登录、模型生成或安装；受管模式不得由这些副作用改变其他 profile 的数据。
- **FR-025**: 系统 MUST 遵守管理器退出码 0/2/3/4/5/6 的现有含义，并在成功启动原生进程后保留原生退出码；参数/身份冲突、活动实例、缺少运行包须有可操作错误。
- **FR-026**: 系统 MUST 保持 DSH、Pi 现有配置、部署、账号与运行契约，OMP 接入不得将已有 profile 重解释为 OMP 身份或改写其他宿主目录。
- **FR-027**: 系统 MUST 更新 OMP 使用说明、profile 关系说明、迁入说明和相关遗留问题状态，给出需求与验证证据对应关系；与 OMP 无关的独立缺陷不得随本特性关闭。
- **FR-028**: 系统 MUST 以隔离环境验证配置、身份、冲突、秘密、恢复和用量透传，记录实际结果与未验证范围；本 spec 的真实宿主验收限本机 Linux glibc x64 无账号 smoke。Linux arm64/macOS 实机、真实登录、真实账号 usage 和指定模型调用转独立遗留，不作为本 spec 完成前提；未来执行仍须相应环境与独立授权，未执行项不能记为通过。

### Key Entities *(include if feature involves data)*

- **OMP 受管配方**: 可复用公共来源与机器覆盖的配置选择，包含所需能力、资源及唯一的原生身份绑定。
- **OMP 原生身份**: 原生 profile 名、有效配置/状态作用域及账号与会话归属；与配方名称有明确关系但不是同一概念。
- **受管资源与归属**: 允许管理的设置或资源、来源、期望内容、原生目标、边界及最近部署基线。
- **原生保留数据**: OMP 自行管理的认证、会话、缓存及用户未纳管内容，不属于公共配置或配置回滚对象。
- **依赖身份**: OMP 运行包及已选资源依赖的来源、版本、完整性和兼容范围。
- **用量查询上下文**: 原生或受管模式、选定身份、运行程序、原生参数与原生查询结果，不包含导出的秘密。
- **遗留事项证据**: 文档中的问题、已批准范围、当前事实、对应需求、验证状态与未解决限制。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户按使用说明可完成一个 OMP 配置集从声明到部署、启动和回滚的完整流程；FR-002 的八类必交能力覆盖率为 100%，每类至少一个支持范围内样例成功部署并生效，主题与快捷键分别验证。原生生效以本机 Linux glibc x64 无账号 smoke 判定；不支持或失败结果不得代替必交类别的成功验收，支持范围外输入均明确失败。其他平台及真实账号验收按 FR-028 转独立遗留，不计当前完成门禁。
- **SC-002**: 对两个受管 OMP 配置集、原生默认环境及既有 DSH/Pi 环境，身份切换、部署、用量和回滚场景均无跨环境配置、账号或会话污染；保护哨兵零意外变化。
- **SC-003**: 未变输入的重复部署不产生多余目标写入；全部冲突、活动实例和中断场景都保留可恢复状态及非受管内容，不出现静默覆盖。
- **SC-004**: 迁入清单中的每项资源均有处置和理由；所有受控秘密哨兵在公共产物、捕获提案、摘要、错误与备份中出现次数为零；导入配置期间旧环境的配置、账号与会话哨兵零变化，新环境无复制而来的登录状态或历史会话。
- **SC-005**: 用量原生模式与受管模式的参数、输出和退出码对照场景全部匹配预期；缺失程序、无账号、不支持、部分失败与身份冲突均有明确可重复的结果。
- **SC-006**: AGENTCFG-F01 的获批范围 100% 映射到需求与验收证据；旧文档中无法复核的结论均标注限制或修正，没有把平台/真实账号未验证项计作通过。
- **SC-007**: 用户从 profile 说明和有效来源报告中，可确定一个配方对应的原生身份、资源来源、账号作用域以及切换后保留的数据，不需要猜测两套 profile 是否同名或继承。

## Assumptions

- OMP 指 `can1357/oh-my-pi` 提供的 `omp`。本规格创建范围是需求与验收，不代表 OMP 已实现或通过真实运行验证。
- 采用“每个受管配方稳定对应一个新建的独立 OMP 原生命名 profile”的用户契约；不支持多个配方共享可变原生身份，不原地纳管已有非受管 default 或命名 profile。具体命名、路径、配置格式映射和参数语法由 plan 决定，并须证明符合本规格。
- 原生模式的 `agentcfg usage` 维持获批的 PATH 薄封装；受管模式是结合本次纳管增加的显式选择能力。原生模式遵循 OMP 自身数据访问行为，不承诺受管隔离，也不因此授予配置目录写入归属。
- 迁入仅处理用户指定来源中的非秘密配置和资源，目标为新建的独立环境；不全盘复制本机 OMP home，不迁移认证/会话。用户已确认可以重新登录，旧账号状态和历史会话继续在旧环境使用。
- 本次直接遗留范围为 AGENTCFG-F01；secrets 同文件、Pi 旧版本钉、DSH Cursor 认证等独立事项不整体并入。但新 OMP 路径必须满足秘密隔离、依赖可追溯和宿主独立验证要求，不能复制已有缺陷。
- 首版完整交付 FR-002 的八类配置，具体支持字段、资源映射、选定 OMP 版本与平台验收矩阵在 plan 阶段固定；设计不能删去任何必交类别。不预设与 Pi 完全兼容，也不要求将所有 Pi 多代理能力移植到 OMP。
- 原生共享服务可能跨 profile 工作；若所选部署方式不能满足受管账号/会话隔离，应限制该功能或更换隔离设计，不能仅修改支持声明来绕过需求。
- 显式复用默认快捷键等资源仅授权读取或经审阅的非秘密资源投影，不授予默认 profile 的账号、会话或文件写入归属；具体复用方式由 plan 固定。
- 宪章中对 DSH/Pi 的历史支持说明不构成 OMP 已获验收的依据；沿用其公共隔离、所有权和显式副作用原则，后续更新支持范围时与实际证据同步。

### Scope Boundaries

当前验收范围：软件实现、完整隔离回归、文档与本机 Linux glibc x64 无账号真实 smoke。登录入口及 usage 的软件契约仍以隔离测试验收。

纳入：OMP 配置生命周期，模型/provider、模型角色、规则、完整技能包、提示词、主题/快捷键、扩展和 MCP 八类配置的实际纳管，公共资源复用、原生 profile 兼容、依赖准备、向新环境显式导入非秘密配置、AGENTCFG-F01 用量入口及相关文档纠正。

不纳入：已有非受管 profile 的原地纳管、认证与历史会话迁移、重建 OMP profile 系统、跨 profile 合并账号/会话、浏览器 Cookie 抓取、独立订阅采集服务、全量移植 Pi 扩展体系、修复无关 DSH/Pi 缺陷、默认启动真实宿主或进行真实账号查询。

另外转出当前 spec：[OMP-F01–F05](../../docs/follow-ups/omp-platform-and-live-validation.md)，包括 Linux arm64、macOS 两架构实机、真实登录、真实 usage、指定模型调用。当前机器无对应环境，保留未验证；不撤销已实现的平台选择、账号隔离、登录或 usage 能力。
