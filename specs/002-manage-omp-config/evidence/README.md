# OMP 实施与验收证据

证据按实际执行操作分别记录；任务、测试文件或配方存在不代表验证通过。没有执行记录的项目一律为未执行。不得在证据中记录凭据、认证数据库内容、会话正文或含秘密的输出。

## 记录格式

每次验收包含以下字段：

| 字段 | 内容 |
|---|---|
| 日期与执行者 | 日期、主代理或执行子代理及实际观察到的模型 |
| 范围 | 对应任务、FR/SC、V 场景；隔离测试 / 宿主 smoke / 登录 / usage / 模型调用五者之一 |
| 授权 | 用户已授权实施及默认隔离测试；真实操作另记具体授权范围，无授权不执行 |
| 平台 | 实际 OS、架构、libc 和 Python；未运行平台单列 |
| 来源 | 管理器工作树状态、OMP tag 与完整 commit；不可变归档、asset、完整上游锁和本地包的 SHA256 |
| 命令 | 可重放的命令；私人路径可用命名占位符，不嵌入秘密 |
| 结果 | 退出码、收集/通过/失败数量；只有实际收集且有行为断言才可计为测试通过 |
| 断言 | 被证明的行为、哨兵、无变更/秘密边界、失败路径；不能只记录子进程退出 0 |
| 限制 | 未执行项、环境不足、失败待决策和剩余风险，注明不能从本次结果推断的范围 |

## 分层文件

- `foundation.md`：身份、严格输入、守卫、锁、发现和运行门禁。
- `us1.md` 至 `us5.md`：各故事的隔离行为和失败路径。
- `regression.md`：DSH/Pi/OMP 全仓隔离回归与秘密边界检查。
- `linux-smoke.md`、`macos-smoke.md`：按平台与架构独立记录九行原生能力。真实二进制必须与正式 lock 摘要一致。
- `login.md`、`usage-live.md`、`model-live.md`：各自授权的真实账号操作，不以无账号 smoke 替代。

合成锁、假二进制和假 receipt 只用于临时测试仓库；不进入正式 `locks/omp/`，不充当原生生效证据。只读下载源码/校验清单不是宿主执行或账号验证。
