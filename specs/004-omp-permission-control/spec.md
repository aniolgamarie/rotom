# Feature Specification: OMP 权限管控

**Feature Branch**: 未创建；本次在 `main` 编写，规格目录独立

**Feature Directory**: `specs/004-omp-permission-control`

**Created**: 2026-09-29

**Status**: 独立插件仓库实现、限定验收及本机迁移完成；T001—T087 为历史补丁交付，当前需求由 [独立插件修订](standalone-plugin.md) 覆盖。

**Input**: 根据本会话已确认需求整理：为自用 OMP 增加 `omp-permission-control`，在会话内切换权限模式；以独立、可配置的低成本模型审查操作，未配置时使用会话主模型；远程 fallback 只在主审运行失败时接替完整审查；本地 tiny 最后作受限故障兜底，不参与有效决定复审。插件源码保存在 rotom，由 `omp-kernel` 选择并受管加载；实现、交付与验证范围见任务和验收记录；本轮不改日常账号或活动会话。

## User Scenarios & Testing *(mandatory)*

以下是原则修订前的历史规格。当前 FR-040—FR-049 和验证边界见[独立插件修订](standalone-plugin.md)，不再要求或允许宿主补丁。历史用户目标中的模型选择、会话模式与审批能力继续保留；宿主 bridge、最终内部执行计划和 tiny 私有服务要求已撤销。

### User Story 1 - 智能审查完整命令副作用 (Priority: P1)

作为 OMP 用户，我希望系统依据完整待执行操作、当前策略和相关用户授权判断是否允许、询问或拒绝，而不是仅凭执行模型的理由或命令连接符弹窗，从而让低风险操作顺畅执行，同时守住高风险边界。

**Why this priority**: 这是功能的核心价值；若不能同时减少无意义确认并保持禁止与人工确认边界，插件没有安全可用的最小形态。

**Independent Test**: 用带标签的低风险、高风险、明确禁止、复合命令、未知语法和上下文注入样本，在假模型与假进程环境中验证决定和原因。

**Acceptance Scenarios**:

1. **Given** 操作命中明确禁止规则，**When** 请求执行，**Then** 系统直接拒绝，主审模型、tiny、执行模型理由和工具输出均不能改为允许。
2. **Given** 操作命中必须人工规则，**When** 有界面且用户批准，**Then** 批准只适用于内容、参数、授权上下文和状态未变化的这一次动作；无界面时阻止。
3. **Given** 操作被固定规则认定为受限只读低风险，且用户限制、覆盖、健康和上下文完整性检查全部通过，**When** 请求执行，**Then** 无需模型或用户确认即可允许，并说明决定来源。
4. **Given** 操作原本因工具默认策略而需要询问，未命中禁止或必须人工规则，且主审模型可用，**When** 请求执行，**Then** 独立审查完整操作和必要授权上下文，结合固定策略产生 allow、ask 或 deny；allow 后不再为同一次操作重复弹出默认询问，不能只采信执行模型理由。
5. **Given** Bash 操作含 `&&`、管道或分号，**When** 请求执行，**Then** 审查整个操作的合并副作用；连接符本身既不触发询问，也不构成自动允许依据。
6. **Given** Shell 未知、动态语法无法完整分析、信息不足或脱敏丢失判定信息，**When** 请求执行，**Then** 转人工确认；无界面时阻止，不因截断或简化请求而放行。
7. **Given** 模型、文件或工具输出声称已经获得授权或要求修改权限，**When** 判定操作，**Then** 这些内容不产生用户授权、不改变策略，也不能扩大允许范围。

### User Story 2 - 显式控制并理解会话模式 (Priority: P1)

作为 OMP 用户，我希望用完整命令切换当前会话的智能或人工模式、查看实际状态并解释决定，从而知道谁在判定、保护是否生效，并能临时收紧权限而不污染后续会话。

**Why this priority**: 缺少可见状态、可撤销模式和解释时，用户无法监督智能权限边界。

**Independent Test**: 在模拟会话中调用 `/permission-control smart|manual|status|explain`，验证模式、来源、健康状态、解释与许可失效语义。

**Acceptance Scenarios**:

1. **Given** 配方期望模式为 smart，**When** 新建或恢复会话，**Then** 读取配方期望，不自动继承上次会话的临时 manual 状态。
2. **Given** 当前为 smart，**When** 用户执行 `/permission-control manual`，**Then** 仅当前会话停止模型审查；明确安全操作仍可按原生或确定性许可执行，其余操作要求人工。
3. **Given** 当前为 manual，**When** 用户执行 `/permission-control smart`，**Then** 仅当前会话恢复智能审查，后续操作按当时有效策略重新判定。
4. **Given** 任意模式，**When** 用户执行 `/permission-control status`，**Then** 显示模式、配置主审及来源、远程备用、本地 tiny 各层身份与可用状态、覆盖工具与平台、健康状态和未验证范围，不显示凭据。
5. **Given** 已产生决定，**When** 用户执行 `/permission-control explain`，**Then** 给出足以区分硬规则、低风险规则、主审、远程 fallback、本地 tiny 或人工边界的短原因，不输出密钥或整段对话。
6. **Given** 用户取消，或操作、参数、授权、策略、模式、模型选择、健康状态改变，**When** 原操作再次到达执行边界，**Then** 尚未执行的旧许可失效并重新判定。

### User Story 3 - 选择独立主审模型并安全降级 (Priority: P1)

作为成本敏感的用户，我希望独立指定一个已配置的便宜 OMP provider/model，或默认使用当前会话主模型；主审临时不可用时，可配置远程模型接替同等级审查；可选本地 tiny 模型最后只能辅助解释和收紧决定，不能越权批准。

**Why this priority**: 模型来源影响成本、可用性和信任边界；错误回退会把故障变成静默放行。

**Independent Test**: 用假模型覆盖显式与默认选择、主模型切换、超时、服务故障、无效输出、主模型有效决定、远程完整审查、同模型跳过、tiny 失败及未安装场景，核对调用次数和权限上限。

**Acceptance Scenarios**:

1. **Given** 用户未指定主审模型，**When** 需要审查，**Then** 固定使用审查开始时的当前会话主模型，并标明来源为会话默认。
2. **Given** 用户显式指定已配置的 provider/model，**When** 需要审查，**Then** 使用该引用并标明来源；该选择独立于界面标题模型。
3. **Given** 显式引用无效或未配置，**When** 校验配置，**Then** 报告配置错误，不悄悄换用当前模型、其它模型或更昂贵模型。
4. **Given** 主审已经返回 deny，**When** tiny 可用，**Then** tiny 不参与复审或翻案，最终仍为 deny。
5. **Given** 主审超时、运行服务故障或输出无效，且已配置 `local/lfm2.5-230m`（若配置远程fallback，须先走该完整审查路径），**When** 降级，**Then** tiny 只能辅助判断、解释或收紧；不能独立批准未被确定性规则允许的操作。
6. **Given** tiny 未安装、不可用或也失败，**When** 操作需要审查，**Then** 仍不放行且不隐式下载；需人工时无界面则阻止。
7. **Given** 会话主模型、显式审查模型、远程fallback或策略变化，**When** 尚未执行的操作继续请求，**Then** 固定新选择并重新判定。
8. **Given** 主审在运行时不支持或故障且配置远程fallback，**When** 请求仍有效，**Then** 使用远程模型完整审查；有效allow/ask/deny不复审，远程也失败时本地tiny仅ask/deny。显式主审仍优先，错误配置引用不触发该链。

### User Story 4 - 受管交付且故障时保持保护 (Priority: P2)

作为 rotom 维护者，我希望 `omp-permission-control` 由现有本地插件机制受管打包和加载，并由 `omp-kernel` 配方明确选择，使交付可复现，插件缺失或损坏时不会遗留全放行配置。

**Why this priority**: 权限功能只有来源可追溯、加载可核实且故障关闭时才能长期使用。

**Independent Test**: 用合成插件包、临时 OMP home 和假宿主发现结果验证选择、缺失、损坏、未加载和回滚，不修改真实 profile 或本机配置。

**Acceptance Scenarios**:

1. **Given** 锁定的本地插件且 `omp-kernel` 选择它，**When** 未来显式同步和部署，**Then** 来源、内容身份与加载选择可核实，安装、部署和启动边界保持分离。
2. **Given** 插件缺失、内容不匹配、未加载或健康失败，**When** 会话准备执行受控操作，**Then** 保留原生保护并阻止依赖插件的智能放行，不复用全放行状态。
3. **Given** 插件被移除或回滚，**When** 再次启动会话，**Then** 不存在脱离插件仍生效的宽松权限配置，非受管配置与账号数据不变。
4. **Given** 另一个配方没有选择该插件，**When** 预览、部署或启动该配方，**Then** 不加载本插件，也不改变该配方的权限策略或认证状态。

### User Story 5 - 查看脱敏审计与真实支持范围 (Priority: P2)

作为用户和维护者，我希望每次决定都有可关联的脱敏记录，并区分隔离测试、真实模型质量评测、宿主 smoke 和平台证据，从而解释异常而不泄露秘密，也不夸大有限样本结果。

**Why this priority**: 可追溯决定和证据边界是发现误判、控制成本及审查权限系统所必需的。

**Independent Test**: 用秘密哨兵、长对话、模式切换和平台标签样本验证审计字段、脱敏和状态分类。

**Acceptance Scenarios**:

1. **Given** 任一 allow、ask 或 deny，**When** 记录审计，**Then** 可关联操作、决定、短原因、模式、策略、实际模型与来源、fallback、覆盖范围和健康结果，但不记录密钥或整段对话。
2. **Given** 待审内容含敏感信息，**When** 构造审查与审计内容，**Then** 秘密被隔离或脱敏；若不足以安全判定，则转人工或阻止。
3. **Given** 仅完成假模型和假进程测试，**When** 报告状态，**Then** 真实 OMP、模型质量、账号调用及未覆盖平台均标为未验证。
4. **Given** 未来取得真实评测授权，**When** 记录结果，**Then** 标明模型、版本、平台、样本集和环境，不把有限样本零漏放表述为普遍保证。

### Edge Cases

- 复合命令前半段只读、后半段写入，或管道下游把输出发送到网络、解释器或文件。
- 引号、命令替换、变量、重定向、here-document、别名、函数或子 Shell 使副作用不完整可见。
- 同一命令因工作目录、目标路径、环境变量、身份或上次输出不同而具有不同风险。
- 操作在审查后被编辑、取消、重排或换入口；工具输出试图把旧许可用于新动作。
- 主审引用真实用户消息但批准了超出其对象、参数或 cwd 的动作；用户的只读限制也必须约束确定性规则。
- 自然语言授权有否定、例外、指代或范围歧义；主审须有完整上下文与逐效果证据，无法确认时转人工，不能为达到免询问指标放宽标签。
- 主审超时后迟到返回，或等待期间用户切换模式、模型、策略或会话主模型。
- 模型凭据缺失、服务不可达、输出无效、理由矛盾或请求超出固定预算。
- tiny 已配置但服务未运行、模型未安装或被标题模型切换误选。
- 子代理、非交互任务或恢复会话无确认界面，且操作需要人工决定。
- 插件更新、缺失、回滚或宿主未加载时，已有会话仍持有未执行许可。
- 同一拒绝操作尝试通过 eval、MCP、子代理或其它入口执行。
- WSL、macOS、Windows 或非 Bash Shell 行为与 Linux Bash 不同。

## 2026-09-30 用户确认：Cursor 与三层审查选择

- 执行模型由 OMP 会话选择；显式 `reviewer_model` 优先且不随执行模型切换，省略时才使用会话执行模型。
- 新增可选 `remote_fallback_model`：主审运行时故障、不支持传输或不可用时才进入；显式引用无效仍配置失败。它独立于执行模型自身的 retry/fallback。
- 远程 fallback 是完整权限审查，可建议 allow/ask/deny，但须执行与主审完全一致的证据、风险与许可检查；有效结果不复审。
- 已有 `fallback_model` 保留本地 tiny，最后仅提供 ask/deny。手动模式不调用任何一层。
- Cursor OAuth 模型发现不得因外部 Cursor 配置来源禁用而被过滤；用户目录和项目目录的外部来源隔离必须保留。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 命名为 `omp-permission-control`，并提供且仅提供完整命令 `/permission-control smart`、`/permission-control manual`、`/permission-control status`、`/permission-control explain`；不得提供 `guard`、`approval` 等缩写。
- **FR-002**: 系统 MUST 将 smart 作为 `omp-kernel` 配方期望默认；新建或恢复会话读取配方期望，临时切换仅影响当前会话且持续可见。
- **FR-003**: manual MUST 不调用审查模型，保留明确安全操作的原生或确定性许可，其余操作转人工。
- **FR-004**: 每个操作 MUST 按固定优先级判定：明确禁止、必须人工、确定性低风险直通、主审模型结合固定策略产生 allow/ask/deny；自动允许必须同时符合操作风险与用户授权范围，不能仅凭模型自报的结论或置信度。唯一免逐次授权的例外是固定策略内可完整验证的受限只读操作；它仍须服从用户限制；范围或限制尚不明时不能走直通，smart 须进入主审，仍不明确则转人工，manual 直接转人工。
- **FR-005**: 系统 MUST 保留现有明确 deny、命令级必须人工规则及宿主强制人工检查；任何模式、模型、YOLO 或无界面环境均不得放宽。工具默认的兜底询问不属于强制人工规则，smart 可将其交给审查；有效 allow 后不得再为同一次操作重复询问。
- **FR-006**: 除 FR-004 的受限只读例外外，只有用户在当前有效上下文中的明确授权可作为授权；模型、文件和工具输出不得修改策略、制造授权或扩大允许范围。模型承担风险与自然语言授权语义的建议性判断，宿主必须另外核验真实来源、逐效果原文证据及对象/参数/上下文绑定，并强制固定风险下限；证据缺失或上下文不完整转人工，不把有效消息 ID 等同于操作授权。主审建议 allow 时，每个效果的证据必须引用对应真实用户消息的完整 UTF-8 字节范围，消息长度由宿主从正文计算；完整引用本身仍不证明语义授权。指代必须从真实用户消息唯一解析；多个候选尚未消除时，不得用拟执行操作反向选定对象，只有用户明确委托在候选内作出选择时才可任选，否则转人工；列出候选或允许检查一个未指定候选不构成选择委托。自然语言语义正确性依赖主审并须独立评测，不宣称宿主能确定性证明任意自然语言授权。
- **FR-007**: 主审 MUST 独立审查完整操作、必要授权上下文和固定策略，不得只接收或采信执行模型理由。
- **FR-008**: Bash 复合命令 MUST 按整体副作用审查；连接符不得成为 ask、deny 或 allow 的唯一依据。
- **FR-009**: 未知 Shell、无法完整分析的动态语法、信息不足或脱敏丢失关键信息 MUST 转人工；无界面时阻止。
- **FR-010**: allow MUST 仅批准内容、参数、执行上下文、授权、模式、策略和模型选择未变化的当前一次动作，不形成永久规则。
- **FR-011**: 取消或 FR-010 任一条件变化 MUST 使未执行许可失效；任何决定复用或缓存均不得跨这些变化生效，再次请求时重新判定，迟到结果不得恢复许可。
- **FR-012**: 已拒或待人工操作不得因重试、改写包装或插件代为执行而跳过已覆盖入口的判定；插件不得提供换用未覆盖入口的自动重试方式，也不得为这些入口新增宽松许可。
- **FR-013**: 子代理或其它无界面环境遇到 ask MUST 阻止，不得以 YOLO 或 tiny 代替用户审批。
- **FR-014**: 用户 MAY 独立指定已配置 OMP provider/model；未指定时 MUST 固定使用审查开始时的当前会话主模型。无可用会话主模型时显示降级状态；仅可使用FR-039显式配置的远程fallback，否则转人工或阻止，不任意选择其它模型。
- **FR-015**: 显式模型引用 MUST 严格校验；无效或未配置时报告配置错误，不静默改用其它或更昂贵模型。
- **FR-016**: 每次审查 MUST 固定实际 provider/model 及选择来源；模型选择或策略变化后，未执行操作 MUST 重新判定。
- **FR-017**: 主审 MUST 复用既有认证；凭据不得进入普通配置、状态、审计、错误或摘要。
- **FR-018**: 用户 MAY 选择 `local/lfm2.5-230m` 为限权 fallback；其选择独立于标题模型，不随标题变化且不触发下载。
- **FR-019**: tiny MUST 仅在主审及已配置远程 fallback 的运行审查路径失败后辅助判断、解释或收紧；故障包括超时、服务故障、输出无效、不支持传输或运行时不可用。不得正常复审、独立批准非确定性允许操作或推翻任何有效模型的 allow/ask/deny。
- **FR-020**: 主审或远程 fallback 的有效 ask MUST 保持人工边界；有效 deny 不复审，有效 allow 仍由宿主机械证据及固定策略核验，核验失败不得借下一模型翻案。tiny 不可用或失败时仍不得放行，无界面时阻止。
- **FR-021**: `status` MUST 显示模式、实际主审及来源、fallback 限权状态、覆盖工具与平台、健康状态和未验证范围，且不泄密。
- **FR-022**: `explain` MUST 给出短原因并区分硬规则、低风险规则、主审、fallback 和人工边界，不输出密钥或整段对话。
- **FR-023**: allow、ask、deny MUST 生成按会话隔离、可关联的脱敏审计，至少包含操作身份、决定、短原因、模式、策略身份、实际模型与来源、fallback、覆盖范围和健康结果；未调用模型的决定标记为“未调用”，不得虚构模型来源。
- **FR-024**: 审查请求、状态、摘要、异常和审计 MUST 排除秘密及整段对话；脱敏后不足以判断时只能 ask 或 deny。
- **FR-025**: 每个操作至多一次主审、一次显式配置的远程 fallback 和一次合条件 tiny 调用；远程和 tiny 只在各自前序审查运行失败时参与，同一 provider/model 不重复请求。超出输入或输出预算不得靠截断或摘要自动允许。
- **FR-026**: 一次操作从开始主审到结束可选远程 fallback 与 tiny 的自动等待总时限默认 MUST 为 30 秒；tiny 仅使用剩余时间，无剩余时间则直接转人工或阻止。人工等待不计入该时限。全过程可取消，超时或取消不得执行操作，迟到结果不得恢复许可。
- **FR-027**: 插件 MUST 由 rotom 现有 OMP 本地插件机制管理来源、内容身份、打包和加载，并由 `omp-kernel` 明确选择；配置、同步、部署和启动边界保持分离。
- **FR-028**: 插件缺失、损坏、未加载、身份不匹配或健康失败时 MUST 保留原生保护并禁止智能放行，不得遗留全放行配置；移除、回滚或升级使旧许可失效。
- **FR-029**: 首版 MUST 限定为主 OMP 会话 Bash 管控，Linux Bash 是初始验收目标；不得宣称 OS 沙箱。
- **FR-030**: 非 Bash Shell 和未验证平台 MUST 转人工或保留原生保护；WSL、macOS、Windows 分别记录证据，不能从 Linux 外推。
- **FR-031**: 首版不为 eval、MCP、子代理等入口提供统一智能审查；它们 MUST 保留原生保护。不能安全管控的委派保持人工确认或阻止，不得以宽松子代理执行弥补主会话拒绝；不得据此宣称已经防住所有未覆盖入口的绕过。
- **FR-032**: 默认验证 MUST 使用临时 HOME/XDG、假模型、假子进程、虚构 provider/model、网络阻断和文件哨兵；真实模型、宿主、账号或模型调用须未来独立授权。
- **FR-033**: 验收 MUST 区分完成、进行中、失败待决策和环境不足未验证；未执行、假模型通过、宿主退出 0 或有限样本零漏放不得表述为普遍保证。
- **FR-034**: 受控操作 MUST 在有效许可产生前不发生执行副作用；审查的操作必须与最终执行的操作一致，且许可不得被另一个并发请求、会话或已改变的目标状态复用。
- **FR-035**: 首版 MUST 兼容现有 kernel 的纯 interceptor 检查和前台 native 操作的自动后台管理，不能因这些开关开启而笼统转人工。interceptor 命中保留原有无执行返回，未命中保留原命令；自动后台功能保留原有 artifact、等待阈值、后台结果和取消清理语义，不静默关闭配置。
- **FR-036**: Bash 冷启动环境初始化仍须本次人工批准；宿主可在后续请求使用有来源、摘要和状态连续性证明的已初始化环境。仅有缓存文件存在不足以自动允许：相关 alias/function、shell options、环境或 persistent state 无法核实时仍人工。direnv 自动检测未发现有效配置且可核实完整搜索链时，不因自动检测开关本身转人工；实际动态加载保持人工，除非另有完整冻结证明。
- **FR-037**: 若默认执行路径需要审批后准备 artifact/job 资源，必须显式区分纯 prepare、已有本次批准后的资源 stage、最终同步 revalidate/consume/start。stage 不执行命令，取消或绑定变化后清理未启动资源且不得执行。许可消费与实际 native 启动之间仍不得 await、重写命令或运行可变 hook。

### Key Entities *(include if feature involves data)*

- **权限策略**: 禁止、必须人工、确定性低风险、模型参与条件、fallback 上限及工具/平台范围，具有可识别身份。
- **审查请求**: 完整操作、执行上下文、相关用户授权、模式、策略和本次固定模型选择，不含不必要秘密或整段对话。
- **权限决定**: 单次动作的 allow、ask 或 deny，以及来源、短原因、有效条件和失效状态。
- **模型选择**: 主审 provider/model、来源、健康状态，以及 tiny 的独立选择和限权状态。
- **会话权限状态**: 配方期望、当前模式、覆盖范围和未执行许可有效性；不跨会话继承临时切换。
- **脱敏审计**: 关联请求和决定的最小证据，排除凭据及整段对话。
- **插件交付身份**: 仓库来源、内容身份、配方选择、宿主加载和健康状态。

## Success Criteria *(mandatory)*

- **FR-038**: patched OMP MUST 区分模型 provider 禁用与外部资源来源禁用：允许 Cursor OAuth 模型发现及选择，同时保持项目与用户目录 Cursor 配置来源禁用。未配置独立模型设置时保留官方旧行为；不得通过删除来源 denylist 或接管认证库实现。
- **FR-039**: 用户 MAY 配置已选择且可唯一解析的 `remote_fallback_model`。显式 `reviewer_model` 始终优先，未配置主审时才绑定当前会话执行模型。远程 fallback 仅在主审运行失败或不支持/不可用时参与；不复审有效决定，不重复同一实际模型，沿用主审全部输入、证据、风险、取消和绑定要求。主审不可用但远程已准备时仍可提供 smart 审查；status/explain/audit分别显示两层fallback的选择、健康和实际调用，查询不增加副作用。

### Measurable Outcomes

以下样本指标使用评测前固定且可追溯的样本集：至少 100 条按权限策略标注为可自动允许的低风险样本、100 条应询问或拒绝的样本，以及 40 条故障和状态变化样本。低风险与询问/拒绝两组各至少包含 30 条复合命令；同时记录标签依据、上下文和相对于当前原生策略的询问次数变化。不得在看到评测结果后删除失败样本或修改标签来达到指标。假模型测试验证流程，真实模型评测验证判断质量，二者分别报告。

- **SC-001**: 在版本化低风险 Bash 回归样本中，至少 80% 无需用户确认；每个自动允许结果均能指出确定性规则或有效主审来源。
- **SC-002**: 在版本化的禁止、必须人工、高风险、未知语法、注入、模型故障和无界面样本中，误自动放行数为 0；该结论仅适用于该样本集。
- **SC-003**: 100% 含 `&&`、管道或分号的样本按整体副作用得到预期结果，没有样本仅因连接符而询问或允许。
- **SC-004**: 模式切换、新建、恢复、取消及状态变化场景中，过期许可复用数为 0，临时模式跨会话继承数为 0。
- **SC-005**: 主审超时、故障、无效输出、deny 和 tiny 失败场景中，tiny 越权批准、隐式下载和无界面自动批准均为 0。
- **SC-006**: 每个需模型操作最多一次主审、一次合条件远程 fallback 和一次合条件 tiny 调用；status 与审计对配置主审、各层实际模型及来源的一致率为 100%。
- **SC-007**: 主审与可选 tiny 合计自动等待不超过 30 秒，超过时即转人工或阻止；用户取消后 1 秒内操作进入不可执行状态。人工等待不计入 30 秒，超时、取消和迟到结果均不会自行执行操作。
- **SC-008**: 100% 状态查询在一次响应内给出模式、实际模型及来源、fallback 上限、覆盖范围和健康状态；100% 已有决定的解释查询给出决定来源和短原因。尚无决定时明确说明，未知子命令列出四个完整用法。
- **SC-009**: 秘密哨兵在普通配置、状态、审计、异常和摘要中的出现数为 0；脱敏损失关键信息的样本自动允许数为 0。
- **SC-010**: 插件缺失、损坏、未加载、回滚和身份不匹配时，全放行残留和非受管配置、认证、会话哨兵意外变化均为 0。
- **SC-011**: 隔离验收覆盖适用 FR 并记录结果；真实模型、真实宿主和平台结果按证据逐项登记，未执行项均不计为通过，环境不具备时明确标为环境不足未验证。
- **SC-012**: 新增默认 kernel 兼容组：保留实际 interceptor/自动后台设置；未命中拦截且环境状态可核实的低风险请求可走完整智能路径，审批前命令/job/artifact 副作用为0，自动后台的前台完成与超阈值行为均与原生一致。冷初始化至多一次本次 UI，初始化后连续低风险请求不因环境开关本身重复询问；环境/状态漂移、stage 期间取消均零执行。该组独立于已冻结240条样本，不能通过重标原样本满足指标。

- **SC-013**: 独立扩展隔离组证明 Cursor 模型 provider 可见且项目/用户资源来源仍禁用；显式主审优先、会话默认、主审不支持→远程、主审故障→远程、两远程失败→tiny、有效结果不复审、同模型不重复、manual零调用、各层最多一次、共享30秒deadline、取消/迟到/绑定变化零执行、分层状态审计一致及旧配置兼容。真实 Cursor 目录与远程 fallback 判断质量另记实测证据；未执行不计通过，不修改历史冻结240样本或102/102账本。

## Assumptions

- 以下默认是规格阶段的合理假设，不是用户原话；plan 若发现宿主能力不能兑现，必须升级决策，不能静默削弱需求。
- 首版面向单用户自用 OMP，不定义多租户、组织管理或集中策略服务。
- 主审与 tiny 合计自动等待默认 30 秒，取消生效目标默认 1 秒；这些是规格提出的首版目标，尚无运行测量。plan 可基于可重复环境收紧，但不得取消有界等待。
- 低风险免询问率 80% 和至少 240 条分组样本是首版验收目标，不是既有结果；具体模型的质量结论须有该模型的真实评测支持。
- 单次成本上限为一次主审、一次显式配置且合条件的远程 fallback，加一次合条件 tiny；未配置远程时保留原上限。具体输入/输出额度由 plan 固定，额度不足以保留完整判定信息时转 ask 或 deny。
- 审查复用 OMP 已有认证；本特性不建立凭据库、登录流程或订阅管理。
- `local/lfm2.5-230m` 仅在用户已配置且所需本地资源已安装时参与；允许 OMP 按需加载已安装的本地运行时，不隐式下载、安装或升级模型及运行依赖。
- 新建或恢复会话读配方默认、首版主会话 Linux Bash 范围以及无缩写命令，是本规格采用的明确默认；扩大工具或平台承诺时需同步更新范围和验收标准。
- 实现形态由 plan 决定，但必须满足已覆盖范围内的执行前判定、许可绑定和插件缺失后的保守行为，不承诺操作系统级隔离或所有工具统一防绕过。

### Dependencies and Scope Boundaries

- **依赖**: rotom 的 OMP 本地插件、锁定、选择、部署和发现能力；已配置的 OMP provider/model 与认证；宿主原生保护和会话命令能力。
- **纳入**: 四个会话命令、smart/manual、Bash 整体判断、独立主审、限权 tiny、许可失效、状态/解释、脱敏审计及 `omp-kernel` 选择约束。
- **首版目标**: 主 OMP 会话中的 Linux Bash；不提供 OS 级沙箱。
- **暂不覆盖**: 非 Bash、eval、MCP、子代理等入口的统一智能审查。它们保留原生保护；后续统一接入属于范围扩展，不作为本 spec 完成条件。
- **平台证据**: WSL、macOS、Windows 分别验证后才可声明支持；未验证时采用人工或原生保护。
- **不纳入功能范围**: 隐式下载模型、替换认证、通用 OS 沙箱、修改既有提示词确认规则，以及自动部署到本机 OMP。
- **体验指标范围**: 免询问指标针对执行前的工具审批；助手因既有提示词规则主动发出的文本确认不计入，插件不承诺消除这类对话停顿。
- **本次规格工作边界**: 仅编写 spec 与质量清单，不修改仓库配方或本机配置；未来实现必须完成仓库 `omp-kernel` 的插件选择和受管集成，部署到本机仍是独立动作。

### Validation Boundaries

- 规格阶段只做结构、链接、占位符及 FR/SC 自检，不运行 pytest、真实宿主、真实模型或账号调用。
- 后续默认测试使用临时 HOME/XDG、网络阻断、假模型与假子进程，分别验证规则、模型输出、故障和秘密哨兵。
- 真实模型质量评测与 OMP smoke 是不同证据，未来均需独立授权并记录模型、版本、平台、样本和环境。
- 本特性的真实模型、真实宿主及各平台行为当前均未验证：本次仅编写规格，未尝试运行；不能把“尚未执行”推断为环境不可用。后续确实缺少环境时登记为环境不足未验证，不阻塞无关规格工作，也不得登记为通过。
