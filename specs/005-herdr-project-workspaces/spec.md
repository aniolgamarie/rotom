# Feature Specification: Herdr 项目工作区与可验证升级

**Feature Branch**: `feat/herdr-native-workspaces`

**Created**: 2026-10-18

**Status**: Draft

**Input**: User description: "原生 Herdr 接替服务器上的 tmux 主力位置；Rotom 增加最小项目入口和受管配置；Avalon 保持独立编辑、审查。普通终端按实际 checkout 组织，Agent 状态只作提示；采用经过核实的较新稳定版，运行时按兼容范围使用，为未来升级准备可重复基准和回退方案。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 进入已有项目并保持归属 (Priority: P1)

作为通过远程终端工作的开发者，我希望选择项目后进入对应工作区，重复进入时仍找到原来的终端；不同工作副本彼此独立，临时切目录和切分支不需要重新整理终端。

**Why this priority**: 项目组织是替换主力终端环境的核心收益，必须在没有 Agent 状态集成时独立成立。

**Independent Test**: 用三个虚构项目及各自多个工作副本进入、离开和重新进入项目，验证归属与终端数量，不启动编辑器或 Agent。

**Acceptance Scenarios**:

1. **Given** 项目尚无工作区，**When** 用户执行 `work enter PATH`，**Then** 创建一个对应工作区和必要的初始终端，不预先启动编辑器、构建任务或 Agent。
2. **Given** 工作区已经存在，**When** 从项目子目录或指向同一工作副本的符号链接重复进入，**Then** 聚焦同一工作区，不新增重复工作区。
3. **Given** 两个工作副本同名或属于同一仓库，**When** 分别进入各自路径，**Then** 保持独立工作区；切分支或访问外置构建目录不改变归属。
4. **Given** 输入目录不属于 Git 工作副本，**When** 用户请求进入，**Then** 在启动或修改终端服务前拒绝，说明首阶段范围并提示使用原生临时工作区。

### User Story 2 - 按稳定用途找到终端 (Priority: P1)

作为开发者，我希望按编辑、人工 shell、构建、调试或 Agent 用途找到终端，已有工作继续运行；只有明确要求时才增加同用途实例。

**Why this priority**: 稳定用途减少手工整理，并防止重复打开时重跑命令或打断现有工作。

**Independent Test**: 在一个工作区内创建用途终端，使其中一部分持续输出或等待输入，重复打开用途并显式新增，核对终端数量和收到的输入。

**Acceptance Scenarios**:

1. **Given** 当前项目已有可确认的默认构建终端，**When** 用户执行 `work open build`，**Then** 只聚焦它，不发送输入、不改变目录、不重启任务。
2. **Given** 已确认某用途不存在，**When** 用户打开该用途，**Then** 新建一个对应终端；shell、build、debug 只打开人工交互终端，不猜测或自动执行任务命令。
3. **Given** 当前用途已有默认终端，**When** 用户执行 `work open ROLE --new`，**Then** 增加独立实例，不替换已有默认终端。
4. **Given** 服务冷恢复后，旧用途终端的身份无法确认，**When** 用户普通打开该用途，**Then** 明确报冲突且不新增、接管或关闭终端；显式 `--new` 可以建立新的默认实例，并保留旧布局。
5. **Given** 用户位于 Herdr 外部，或当前终端的项目归属无法确认，**When** 执行 `work open ROLE`，**Then** 拒绝并提示先运行 `work enter PATH`，不自动创建、启动或连接工作区，不按当前目录或最近项目选择目标；`--new` 也不绕过该前提。

### User Story 3 - 保持输入正确与工作连续 (Priority: P1)

作为开发者，我希望中文、编辑器组合键、复制粘贴和分屏缩放保持可用，远程连接断开后可回到仍在运行的工作。

**Why this priority**: 输入错误、错误目标和任务意外退出会直接造成误操作，属于切换主力入口的阻断项。

**Independent Test**: 使用无账号的输入记录和持续运行测试任务，覆盖不同终端尺寸、多客户端、断连和重新连接，独立于真实 Agent 会话验收。

**Acceptance Scenarios**:

1. **Given** 正在输入中文、多行文本或编辑器组合键，**When** 分屏、缩放或切换终端，**Then** 输入仍送达正确目标，光标和内容无影响使用的错位；前缀键可以按明确操作原样传入。
2. **Given** 两个客户端连接同一主环境，**When** 其中一个切换项目或调整尺寸，**Then** 按已声明的共享焦点与尺寸规则呈现，不承诺独立项目焦点，也不误向另一终端发送输入。
3. **Given** 持续测试任务正在运行，**When** 客户端退出、远程连接中断或启动 shell 退出，**Then** 仍运行的终端服务保留原任务，重新连接可以回到它。
4. **Given** 终端服务已经停止并重新启动，**When** 恢复布局，**Then** 不将布局恢复描述为原进程恢复，不自动重跑历史命令或选择最近 Agent 会话。
5. **Given** 用户通过编辑器明确请求复制合成文本，**When** 完成复制与多行粘贴验收，**Then** 本地得到预期内容，不查询原剪贴板；普通复制习惯不被强制改成自动同步。

### User Story 4 - 显式管理配置并安全回退 (Priority: P2)

作为维护者，我希望自愿启用 Herdr 配置管理，先审阅将修改的文件，再部署或回退，已有终端配置和私人状态保持各自所有权。

**Why this priority**: 受管配置让迁移可重复，但不能通过接管现有目录或停止长任务来实现。

**Independent Test**: 使用独立测试目录准备已有配置、非受管文件和状态哨兵，分别执行预览、采用、重复部署、冲突和回退场景。

**Acceptance Scenarios**:

1. **Given** 机器只选择了原有 zsh/tmux 组件，**When** 更新 Rotom 或重复部署，**Then** 不自动启用 Herdr，不改变既有组件的恢复行为。
2. **Given** 已有私人 Herdr 配置且未授权采用，**When** 预览或部署，**Then** 明确提示冲突或采用要求，不覆盖配置或接管整个目录。
3. **Given** 已成功部署声明文件，**When** 重复部署或回退，**Then** 无变化部署不重写或轮换备份，回退只处理所拥有文件，不改账号、会话、缓存或活动进程。
4. **Given** 某次写入中断或目标被外部修改，**When** 再次操作，**Then** 提示恢复或冲突，不静默覆盖，也不声称配置回退完成了软件或会话降级。

---

### User Story 5 - 继续使用独立编辑器与既有 Agent 入口 (Priority: P2)

作为开发者，我希望在同一工作副本中打开已经验收的 Avalon 和所选 Agent，沿用原有配置、身份与审查习惯；终端迁移不改变工具本身的职责。

**Why this priority**: 终端组织需要衔接现有工作流，不能引入新的账号、编辑器或 Agent 管理体系。

**Independent Test**: 对每种启动入口核对目标工作副本和既有身份；编辑器与 Agent 的实际交互分别取得对应授权后验证。

**Acceptance Scenarios**:

1. **Given** 用户已配置并验收独立 Avalon 入口，**When** 打开 edit 用途，**Then** 启动所选编辑器环境，工作目录为项目工作副本，不升级语言服务或额外编辑器组件。
2. **Given** 已部署明确的 Pi/DSH 配方或独立 Codex 入口，**When** 用户打开相应用途，**Then** 使用指定配置和工作副本，保留其原有身份与状态位置，不顺带安装或部署；缺少准备时明确失败。
3. **Given** Agent 已修改文件，**When** 用户在 Avalon 显式刷新并审查、导出所选修复要求，**Then** 只将选定文件交给同一工作副本的目标 Agent，不广播或开放整个编辑器状态；关闭审查不删除已保存导出。
4. **Given** 独立 Codex 入口需要准确的终端关联，**When** 使用已选的不共享 daemon 策略，**Then** 不修改全局启动习惯，不停止现有 daemon，也不改变 Pi 内部的委托行为。

### User Story 6 - 有证据地采用较新稳定版 (Priority: P2)

作为维护者，我希望优先使用适合当前环境的较新稳定版，能够重放同一组功能与资源检查，再决定是否推广；遇到问题可以保留原有工作并撤销未来启动入口的切换。

**Why this priority**: 升级能力必须从首轮建立，避免永久停留在最初候选，也避免追新导致输入、恢复或资源退化。

**Independent Test**: 使用隔离的虚构工作负载建立首轮记录；已有通过版本后，在相同环境比较候选，并演练不影响存量任务的推广与回退。

**Acceptance Scenarios**:

1. **Given** 用户开始首次安装选版或显式升级评估，**When** 核对官方稳定发行，**Then** 优先评估较新稳定版；暂留旧版时记录原因与重评条件，不永久固定本轮版本，不默认选择预览版。
2. **Given** 尚无通过的基线，**When** 完成首轮测量，**Then** 只记录实际结果和校准状态；没有满足验收与门槛时，不声称已有生产基线或升级回归通过。
3. **Given** 已有通过基线，**When** 在相同环境比较新候选，**Then** 使用可重放负载和事先冻结的评价标准，区分程序、配置、检测规则与集成变化，并分开记录 Agent 成本。
4. **Given** 候选出现错误输入、错误目标、权限退步、任务退出或必需指标退化，**When** 作出推广决定，**Then** 停止推广并保留最后通过入口；附加指标不可用只标未验证，不扩大权限。
5. **Given** 候选完成独立验收和新工作试用，**When** 显式切换未来启动入口，**Then** 旧实例和长任务继续运行；回退前分别验证程序、配置和持久状态的边界，不假定旧版能读取新版状态。

---

### User Story 7 - 按需查看 Agent 状态提示 (Priority: P3)

作为开发者，我可以在需要且权限允许时启用受管实例的状态提示，但即使提示缺失或集成不可用，项目与人工终端工作仍可继续。

**Why this priority**: 状态是增强功能，不能成为终端组织、任务完成判断或迁移上线的前置依赖。

**Independent Test**: 关闭所有状态增强验证核心流程；对可选增强分别核对两个并发实例和错误、延迟事件的关联结果。

**Acceptance Scenarios**:

1. **Given** 所有状态增强关闭，**When** 进入项目并打开人工终端、编辑器或 Agent 入口，**Then** 核心操作保持可用，不依赖状态图标或通知。
2. **Given** 增强无法在既有权限边界内接入，**When** 用户评估启用，**Then** 保持关闭并说明限制，不自动扩权或安装控制其他终端的能力。
3. **Given** 两个并发 Agent 实例，**When** 出现子任务、延迟状态或无法确认的会话关联，**Then** 不把事件错误归到另一根会话，不据提示调度任务、判断完成或关闭终端。

### Edge Cases

- 路径含空格、中文、引号或命令含义字符；路径不存在、指向文件、链接失效或不属于支持的工作副本。
- 同名仓库、主工作副本与 linked worktree、切分支、外置构建目录以及跨终端服务的同一路径。
- 多人次入口同时创建、创建已经生效但响应丢失、查询超时、连接中断和重复请求。
- 用户手工移动或关闭终端，另一个客户端改变焦点，旧终端标识被复用，调用环境仍保留旧信息。
- 服务冷恢复保留布局却失去用途归属；不能将未知当作已确认缺失，也不能凭同名终端自动接管。
- 外部远程 shell 或项目归属不明的终端执行 `work open`，必须提示先 `work enter PATH` 且不产生终端侧副作用；`--new` 不绕过上下文要求。另须处理当前仍在旧 tmux 中、旧新程序与服务版本不同或无法确认支持能力的情况。
- 配置已有原生修改、文件或父目录不安全、未完成恢复、无变化部署和回退期间新增非受管数据。
- 复制链路不支持、首次复制失败、输入协议差异、多客户端尺寸冲突、快速缩放和窄屏显示。
- 新候选改变配置默认值、检测规则、集成或持久状态；缺少对照数据、测量工具、权限或某个平台。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供 `work enter PATH`，从外部远程终端进入所选主环境，或从内部切换到对应项目；重复进入复用已确认工作区。
- **FR-002**: 项目身份必须使用所选终端服务内的实际 Git 工作副本规范路径；子目录和链接归一到该副本，不同 worktree 必须分开，名称、分支、标题或当前命令不能作为身份。
- **FR-003**: 系统必须只在确认不存在时创建工作区；并发进入、响应丢失和超时必须先确认当前事实，无法确认时明确报错，不盲目重试或产生静默重复。
- **FR-004**: 项目进入只创建必要初始终端；目录变化不自动改归属，原生新 tab/分屏继续属于当前工作区，手工终端不因名称相同被自动接管。
- **FR-005**: 首阶段必须在启动或修改服务前拒绝非 Git 项目，退出码为 2，并提示原生临时工作区；无效路径按现有参数错误约定处理。
- **FR-006**: 系统必须提供 `work open ROLE` 和显式 `--new`，支持 shell、edit、build、debug、pi、codex、dsh；两种形式都必须在已确认项目归属的 Herdr 终端内使用。上下文缺失或不明时必须拒绝，提示先运行 `work enter PATH`，不自动创建、启动或连接工作区，不从当前目录、最近项目或全局活动项推断归属；上下文已确认后，只有已确认某用途不存在时才能默认创建。
- **FR-007**: 复用必须只聚焦，不发送命令或控制输入、不修改目录、不重启或中断程序，也不以 idle 等状态判断可重用或可关闭。
- **FR-008**: `--new` 必须创建独立实例且不替换已有可确认默认实例；若冷恢复后无可确认默认实例，显式新增可以为该用途建立新默认实例，其他用途的未知状态不能自动解除。
- **FR-009**: 冷恢复后用途身份未知时，普通打开必须报冲突并以退出码 4 结束，不新建、接管或关闭原终端；用户可以原生导航或明确请求新增。
- **FR-010**: 用途显示必须保持稳定；shell/build/debug 不推断任务命令，用户仍可在正常终端中自行编辑、构建和调试。
- **FR-011**: 进入项目必须根据显式路径及所选主环境确认目标；打开用途必须确认当前调用终端、所属项目与所选主环境。移动、关闭、过期标识或别处焦点变化不能导致操作落到错误目标，缺失上下文不能以全局活动项目替代。
- **FR-012**: 同一主环境的客户端必须按已声明的共享活动工作区和尺寸规则工作，一个客户端切换项目会影响该主环境的其他客户端；外部进入不能静默嵌套旧复用器，不得承诺未验证的独立客户端焦点。
- **FR-013**: 首轮支持的客户端必须具备可用的中文、多行输入、Shift+Enter、编辑器组合键、前缀原样输入、分屏缩放和显式本地复制路径；远端程序不得主动查询本地剪贴板，用户显式粘贴保持客户端原有行为。
- **FR-014**: 客户端或远程连接断开、启动 shell 退出时，仍运行的服务必须保留原任务；服务停止后的布局恢复不能自动重放历史任务或选择最近 Agent 会话。
- **FR-015**: Herdr 配置必须是显式可选管理组件，只拥有声明文件；未选择组件的机器、已有恢复记录、私人状态和非受管文件必须保留原有边界。
- **FR-016**: 配置操作必须支持事前预览、已有文件的显式采用、冲突提示、无变化稳定性、中断恢复和所拥有文件的回退；不得通过停止活动实例或覆盖私人目录完成部署。
- **FR-017**: 初始配置必须保留 C-x 前缀习惯、原生导航和安静状态显示，默认关闭声音、弹出通知、Agent 自动恢复、后台版本/规则检查及实验历史；加载结果必须可核验，不能只证明配置文件存在。
- **FR-018**: 编辑器用途必须启动用户已经选定的独立 Avalon 入口，Agent 用途必须使用明确准备的既有 Pi/DSH 配方或独立 Codex 入口；全部工作目录必须是目标工作副本，保留原有配置、账号与状态身份。
- **FR-019**: 日常项目进入和用途启动不得隐式安装、部署、下载、改锁或替换运行时；工具未准备、身份不匹配或启动失败必须明确报告，不能静默切到其他配方。
- **FR-020**: 路径和启动参数必须按字面含义处理；不能让空格、中文、引号或命令含义字符造成额外执行，不能把启动文本送入复用中的终端。
- **FR-021**: Avalon 审查必须保持用户显式刷新、独立评审和选择交接；只能交接所选文件给明确目标，不自动广播、不开放整个状态目录，关闭审查不删除已保存导出。
- **FR-022**: 独立 Codex 的 daemon 使用策略必须明确且不影响 Pi 委托、全局启动入口或已有活动 daemon；无法证明的会话关联不能用于自动恢复或发送操作。
- **FR-023**: 状态增强必须可关闭、按实例单独验收且不依赖额外权限；并发实例、子任务和延迟状态不得错误关联另一根会话，无法确认时不得猜测。无法安全启用时保留关闭，核心终端操作不受影响；状态与通知不得调度任务、判定完成或自动清理终端。
- **FR-024**: 集成必须使用未修改的官方工具与公开能力，不能通过修改宿主、增加常驻管理服务、任务系统或额外持久终端管理清单绕过能力限制；终端控制权限不能被当成仅上报状态权限。
- **FR-025**: 首次安装选版和显式升级前必须核对官方较新稳定版；暂留旧版必须记录原因、缺证和重评条件，不默认采用预览版，不永久固定本轮候选。
- **FR-026**: 每次候选必须分别记录发行/资产身份、实际运行版本、有效配置、检测规则及集成；兼容按所需公开能力和相应验收判断，不能只凭版本相同或更大认定可用。
- **FR-027**: 基准必须提供可重放的虚构项目与操作负载、明确测量口径及可比较报告，覆盖项目规模、操作等待、空闲、持续输出、全部断开客户端及按风险要求的持续增长；真实 Agent 成本必须分开。
- **FR-028**: 已有通过基线时必须在相同环境按固定负载比较候选，分别辨明程序变化和配置/规则/集成变化；比较前冻结采样与评价门槛，正确性错误、必需数据缺失或门槛未校准不得判通过。
- **FR-029**: 首轮没有基线时只能记录真实测量并按验收建立基线，不得虚构旧版对比；附加指标缺测必须单列未验证，不自动阻塞已有必要证据支持的范围，也不扩大权限。
- **FR-030**: 候选必须先独立评估、完成适用客户端验收并用新工作试用，再显式切换未来启动入口；保留活动旧实例，不默认实验性交接，磁盘更新不能被描述为存量服务已升级。
- **FR-031**: 回退必须分别验证程序选择、受管配置和原生持久状态，不能假定旧程序兼容新版状态；只切回入口不能宣称迁移或恢复已有进程，测试副本不能替代或破坏唯一原件。
- **FR-032**: 运行时必须遵循工程及各工具声明的兼容范围和已准备环境，不因本机观察到的补丁版本不同而拒绝其他受支持环境，也不据最低版本声明推定所有未来版本已经验收。
- **FR-033**: 验收必须分别记录隔离检查、原生运行、真实客户端与 Agent 结果及适用组合；已完成、进行中、失败待决策、环境不足未验证必须区分，未执行不能写成通过，真实失败不能改记缺环境。
- **FR-034**: 默认验证不得启动第三方宿主或接触真实账号、会话和密钥；原生、真实客户端及真实 Agent 验收必须按既有授权边界独立执行，公开材料只包含虚构数据与脱敏证据。

### Key Entities *(include if feature involves data)*

- **项目工作副本**：用户明确选择的代码工作目录，具有规范路径；同一仓库的多个副本分别归属。
- **主工作环境**：用户选择的终端服务范围，包含工作区和已声明的客户端共享行为。
- **项目工作区**：工作副本在该主环境中的组织单位，包含普通终端及可选 Agent 终端。
- **用途实例**：编辑、构建等稳定用途对应的终端，区分可确认默认实例、显式新增实例和归属未知的恢复终端。
- **受管配置目标**：用户授权 Rotom 管理的声明文件及其采用、冲突、恢复和回退边界。
- **工具启动选择**：既有编辑器环境或 Agent 配方的明确选择，以及应保留的工作目录与身份。
- **候选与通过基线**：待评估版本组合及最后完成对应范围验收的版本组合，包含可复现身份。
- **基准与验收记录**：所用负载、环境类别、样本、结果、门槛和未覆盖范围，支持推广或保留旧版的决策。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 三个项目各含三个工作副本、合计 27 个终端时，100 次重复进入及一组 10 次并发进入产生零重复项目、零错误归属；切分支和访问外置目录后结果不变。
- **SC-002**: 对持续工作终端重复打开同用途 100 次，新增输入、任务重启及非授权新增终端均为零；10 次显式新增均产生独立实例且不替换默认实例。在项目上下文缺失和不明时，各执行 10 次普通或显式新增用途请求，创建、启动、接管与自动连接工作区的次数均为零。
- **SC-003**: 所声明支持的客户端组合全部通过中文、多行输入、组合键、显式复制粘贴和 20 轮缩放/切换验收，错误输入或错误目标事件为零。
- **SC-004**: 客户端退出、远程断连和启动 shell 退出三类检查中，仍运行服务内的持续测试任务全部保留原进程；主动停止服务后的布局恢复不被误报为原任务存活。
- **SC-005**: 连续五次无变化部署不重写目标或轮换备份；已有文件采用、新文件部署、中断恢复和回退场景均只影响声明拥有的目标，非受管数据损失为零。
- **SC-006**: 所选编辑器及 Agent 启动验收均进入正确工作副本并保留既有身份；发生额外安装、部署、账号迁移或错误交接的次数为零。
- **SC-007**: 每份候选评价都包含明确基线或无基线说明、比较范围、实际输入、有效样本、预先冻结门槛及逐项结果；缺失必需证据、未校准门槛或未执行项被误判通过的数量为零。
- **SC-008**: 存在可比基线时，候选在三组有效重复对照和累计至少 600 次暖操作中满足预先冻结的必需预算与回归门槛；没有基线时只报告首轮测量与校准结果，不声称升级回归通过。
- **SC-009**: 每次推广与回退演练中，存量长任务意外退出、错误状态覆盖及未授权迁移次数为零；已知不兼容或无法证明的状态回退会明确停止。
- **SC-010**: 关闭全部状态增强时，项目进入、人工用途终端、编辑器与 Agent 启动的核心验收场景仍全部可用；状态提示触发自动任务操作或完成判定的次数为零。

## Assumptions

- 目标用户是独立管理服务器工作环境的开发者，普通人工终端与可选 Agent 在同一项目内协作；项目组织不承担任务调度职责。
- 首轮目标为实际测试过的 Linux 服务器与远程客户端组合，一台服务器选择一个主工作环境。相同主环境共享活动项目是已知限制，不要求各客户端独立停留在不同项目。
- 首阶段自动项目入口只接纳 Git 工作副本；非 Git 目录使用原生临时工作区。用途入口依赖已确认的 Herdr 项目上下文，外部先显式进入项目；工作目录变更不追踪任务含义，也不自动猜测外置目录映射。
- 日常编辑器与 Agent 启动所需环境已由用户明确准备。编辑器及 Agent 工具本身的功能修改、账号管理和语言服务升级不属于本特性。
- Agent 启动属于现有工作流衔接；状态增强为可选后续能力，任何状态集成缺失都不自动阻止人工终端核心上线。
- 冷恢复仅保留能够证明的项目与布局事实；用途身份未知时默认拒绝操作，显式新增是已选定的恢复路径，不新增自动猜测或接管机制。
- 已有选版审计和本机版本观察不是功能、性能或平台通过证据。性能绝对预算及回归余量在测量校准后、评价候选之前冻结，不在本规范中捏造实测数值。
- **依赖**：用户准备的受支持工具、明确的项目访问权限、既有配置管理与启动契约，以及原生交互和真实账号验收所需的对应环境与授权。
- **范围外**：任务调度与完成判断、新侧栏或长期运行的管理服务、额外持久终端管理清单、跨平台软件包管理器、自动安装市场插件、自动迁移活动进程、跨机器连接入口和未验收的平台支持声明。
- **规范关系**：本文件是本特性的用户需求基线，遵守 [宪章 2.3.0](../../.specify/memory/constitution.md)；已有 [设计与证据材料](../../openspec/changes/herdr-native-workspaces/proposal.md) 供后续计划参考，不将其中的实现建议或历史版本自动当作需求或通过证明。
