# Feature Specification: 同步代理与终端工具配置

**Feature Branch**: 未创建；功能目录独立于 Git 分支
**Created**: 2026-09-27
**Status**: Draft
**Input**: User description: "termcfg 管理代理，终端，tmux等功能的同步，以备份源文件和文件覆盖的方式来同步功能，并检查本地环境的合法性"

## Clarifications

### Session 2026-09-27

- Q: 你说的“备份源文件”，具体希望同步前备份哪一份文件？ → A: 备份目标位置的旧文件。
- Q: 首版 `termcfg` 的“代理同步”应管理到哪一层？ → A: 包含 mihomo mgr、mihomo core、代理配置和服务管理。
- Q: 如果现有代理配置含订阅地址或密钥，`termcfg` 应怎样同步配置并备份旧文件？ → A: 只备份并覆盖非秘密代理配置；私人订阅与密钥保留在独立文件，由 mihomo mgr 管理。
- Q: 同步代理配置后，`termcfg` 应自动让正在运行的 mihomo 服务使用新配置吗？ → A: 同步只改文件并提示待生效；用户另行显式重载或重启服务。
- Q: `termcfg` 应怎样处理用户现有的 `~/.zshenv`？ → A: 先备份目标旧文件，再整文件同步覆盖；原文件含有不宜直接覆盖的非秘密内容时告警并询问是否继续。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 检查后安全同步所选组件 (Priority: P1)

用户选择代理、终端 shell 和 tmux 中需要的组件，先查看本机条件与逐文件覆盖预览，再确认同步。代理组件覆盖 mihomo mgr、mihomo core、非秘密代理配置与服务管理；core 作为锁定的版本化运行包由显式 `sync` 准备，配置文件由 `apply` 复制覆盖。管理器先备份目标位置的原文件，再把选定公开配置来源复制到目标；未选组件保持原样。

**Why this priority**: 预先识别不兼容环境、覆盖范围和备份结果，是安全文件同步的基础。

**Independent Test**: 在隔离目标目录中放置已有配置，只选择一个组件，验证环境检查、预览、备份、覆盖和未选组件不变。

**Acceptance Scenarios**:

1. **Given** 必要条件均满足且目标不存在，**When** 用户预览并同步，**Then** 仅创建所选组件声明的文件，目标内容与选定来源一致。
2. **Given** 目标已有普通文件且用户明确同意接管，**When** 用户同步，**Then** 每个旧文件先有可恢复的私人备份，随后才被来源内容覆盖。
3. **Given** 用户只选择 tmux，**When** 用户同步，**Then** 代理和 shell 的文件及运行数据不变。
4. **Given** 必要条件缺失或路径不安全，**When** 用户尝试同步，**Then** 写入前停止，报告组件、原因和修复建议。
5. **Given** 用户选择代理组件，**When** 用户预览并同步，**Then** 预览涵盖管理器、核心程序和非秘密代理配置，且能查看服务的可管理状态；私人订阅和密钥文件不列为覆盖目标。
6. **Given** mihomo 服务正在运行，**When** 用户同步新的代理配置，**Then** 服务保持原状，结果明确提示配置待生效，不自动重载或重启。
7. **Given** `~/.zshenv` 含有用户自行添加的非秘密内容，**When** 用户选择 zsh 同步，**Then** 预览提示这些内容会被覆盖；用户确认后先备份原文件再整文件覆盖，用户拒绝时本次 zsh 同步停止且所有 zsh 目标不变。

---

### User Story 2 - 识别漂移并恢复上一版 (Priority: P2)

用户更新配置后可以恢复最近一次成功配置同步前的受管配置状态。用户在目标文件上的后续改动不得被静默覆盖；首次接管前的原文件也能恢复。mihomo core 的软件版本切换不属于配置回滚。

**Why this priority**: 错误的 shell 配置可能影响下一次登录，文件覆盖必须有可靠的撤销路径。

**Independent Test**: 对已有文件做首次接管、后续更新和恢复，验证原文件、权限、幂等性与冲突处理。

**Acceptance Scenarios**:

1. **Given** 首次接管前存在原文件，**When** 用户恢复，**Then** 原内容和必要权限恢复，其他文件不变。
2. **Given** 来源与目标已一致，**When** 用户重复同步，**Then** 不改写目标，也不轮换备份。
3. **Given** 用户在同步后修改了受管文件，**When** 用户更新或恢复，**Then** 操作报告冲突并保留用户改动与备份。
4. **Given** 多文件同步中途失败，**When** 用户查看状态，**Then** 能区分已完成、未完成和待恢复目标，不会看到虚假的整体成功。

---

### User Story 3 - 查看环境与组件状态 (Priority: P3)

用户无需覆盖文件，就能了解平台、目标目录、现有文件、必需程序和可选能力，并看清文件已同步与运行服务可用之间的区别。

**Why this priority**: 代理、zsh 与 tmux 的运行前提不同，逐组件诊断可减少部署后的故障排查。

**Independent Test**: 在隔离环境分别模拟必要程序缺失、可选程序缺失、目标冲突与已部署漂移，核对结果和建议。

**Acceptance Scenarios**:

1. **Given** 所选组件缺少必要程序或平台不受支持，**When** 用户检查环境，**Then** 报告不能同步或不能使用的具体原因；其他合格组件仍可单独处理。
2. **Given** 只缺少可选能力，**When** 用户检查环境，**Then** 显示功能降级，不把基础配置误报为不可用。
3. **Given** 文件已同步但代理核心未运行，**When** 用户查看状态，**Then** 分别显示文件部署状态和服务状态，并能选择显式的服务操作；未检查的事实标为未检查。
4. **Given** 代理服务已停止且环境检查通过，**When** 用户显式启动服务，**Then** 报告启动结果和新的服务状态；文件同步命令本身不冒充此操作。
5. **Given** 新代理配置已同步且仍待生效，**When** 用户显式重载或重启服务，**Then** 报告操作结果；只有确认服务已加载新配置才标为已生效，否则保留待生效或未确认提示。

### Edge Cases

- 目标是目录、符号链接、硬链接或非当前用户所有；父目录不安全、权限不足或路径在预览后发生变化。
- 旧 `starter` 留下链接、管理片段或时间戳备份；这些痕迹不等于本管理器的所有权证明。
- 现有文件可能含凭据或私人订阅地址；不得将其复制到普通配置备份或作为受管非秘密配置覆盖。
- `~/.zshenv` 含机器专属变量或用户编辑内容；预览必须标明整文件替换影响，不能把告警后的沉默当作同意。
- 公开来源缺失、损坏、权限不合理，或依赖本机绝对路径；必须先发现再写入。
- 目标与期望内容一致但没有所有权记录；不得无提示地视作已受管。
- 备份空间不足、写入中断、多文件部分成功、组件间目标重叠。
- 现有 shell、tmux 和代理进程可能继续使用旧配置；文件同步与服务状态必须分别报告，代理配置待生效时给出显式操作提示。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 用户 MUST 能分别选择代理组件、zsh 终端配置和 tmux 配置；代理组件 MUST 涵盖 `mihomo-mgr`、以显式锁和 `sync` 安装的版本化 mihomo core 运行包、由 `apply` 覆盖的非秘密代理配置和服务管理。
- **FR-002**: 系统 MUST 提供只读预览，逐文件列出所选来源、目标、拟新增/覆盖/保留的操作、备份安排、环境检查结果及冲突。
- **FR-003**: 系统 MUST 在覆盖前检查当前用户、目标目录与文件类型/权限、目标是否可安全写入、来源完整性，以及所选组件必需的本地程序与平台条件。
- **FR-004**: 环境检查 MUST 区分阻止同步的必要条件、只影响可选功能的条件和未执行的运行检查；必要条件不满足时不得修改该组件目标。
- **FR-005**: 系统 MUST 以文件内容复制覆盖受管目标；部署结果不得依赖指向来源仓库的符号链接。
- **FR-006**: 单次 `apply` 覆盖前，系统 MUST 先完成该调用中**所有选中组件的全部既有配置目标**的可恢复备份；普通文件保存内容与必要元数据，显式接管的旧链接保存链接本身。任一备份失败时不得覆盖该调用中任何目标。版本化 core 运行包由 `sync` 安装，不进入配置备份或配置回滚。
- **FR-007**: 首次接管现有文件、旧 `starter` 链接或管理片段 MUST 在预览中明确列出，并要求用户显式选择接管；内容相同也不能自动取得所有权。
- **FR-008**: 系统 MUST 记录每个受管文件的组件、来源身份、应用前后状态和恢复状态，以发现漂移；记录不得包含文件正文或秘密值。
- **FR-009**: 目标已与预期一致时 MUST 不改写；没有实际变更的同步 MUST 不创建或轮换上一版备份。
- **FR-010**: 受管目标被用户改动后，更新与恢复 MUST 保留目标及备份并报告冲突，不得静默覆盖。
- **FR-011**: 用户 MUST 能按组件恢复最近一次成功配置同步前的受管配置状态；首次接管可恢复原文件，原本不存在的目标只在仍归本管理器拥有且未漂移时移除。配置回滚 MUST NOT 降级 mihomo core 软件版本或迁移数据库。
- **FR-012**: 多文件同步 MUST 在写入前复核预览依据；中断或失败时 MUST 保留可识别的恢复信息和明确下一步，不得报告整体成功。
- **FR-013**: 系统 MUST 显示校验、备份、覆盖和复核的进度；失败信息 MUST 指出组件、目标和原因，不输出凭据、私人订阅 URL 或文件正文。
- **FR-014**: 系统 MUST 能以显式 `lock` 和 `sync` 准备版本化 mihomo core，以 `apply` 部署非秘密代理配置和 `mihomo-mgr`，并提供显式的代理服务状态查看及启动、停止、重载或重启操作；`sync` 更新所选 core 版本与 `apply` 更新配置时 MUST 分别记录待生效原因，不自动操作服务。新 core 或配置待生效时 MUST 提示用户；服务操作的结果 MUST 单独报告。
- **FR-015**: zsh/tmux 会话 MUST 不被同步自动重载或关闭；插件联网获取 MUST 由显式 `lock`/`sync --component zsh|tmux` 完成，并显示来源、版本与进度，不能在配置加载或 `apply` 时隐式联网。
- **FR-016**: 公开来源 MUST 可追溯到具体版本或内容身份，并随项目分发；同步后的使用不得依赖旧 `starter` 工作目录。
- **FR-017**: 未选组件、用户维护的私人数据和未声明目标 MUST 保持原样；两个组件不得同时声明同一目标。
- **FR-018**: 现有目标疑似含秘密时，系统 MUST 在接管前要求用户将私人值迁至独立文件；无法确认目标是非秘密配置时 MUST 拒绝自动备份和覆盖，不得把正文写入日志、公共配置或普通备份。
- **FR-019**: 系统 MUST 按组件区分来源可用、环境合格、核心与配置文件已同步、文件漂移、待恢复、代理服务运行状态，以及 core 版本和配置各自的待生效原因；不可观测项 MUST 标为未检查。
- **FR-020**: 默认验证 MUST 使用隔离目标目录、虚构配置、阻断网络与假进程，不改动真实 HOME、tmux 会话、mihomo 服务或订阅。
- **FR-021**: 代理配置 MUST 分为可同步、可备份的非秘密配置和由 `mihomo-mgr` 管理的独立私人文件；订阅内容、凭据、路由草稿与发布状态、日志和统计 MUST 留在私人侧，不得进入普通备份、同步记录、摘要、进度或错误输出。旧目标须先通过非秘密准入，才可计算用于普通同步记录的内容摘要；无法判定时不计算或输出该摘要。
- **FR-022**: 选择 zsh 组件时，系统 MUST 将 `~/.zshenv` 作为整文件目标。若旧文件有用户添加的非秘密内容，覆盖前 MUST 给出脱敏影响提示并等待用户明确选择；用户确认后按 FR-006 先备份旧文件再覆盖，拒绝时本次 zsh 同步的所有目标保持不变。疑似含秘密的旧文件仍受 FR-018 限制，不能仅靠确认绕过。
- **FR-023**: 首次初始化 MUST 在一次明确的组件选择中展示将启用的组件和默认值，并提供可安全修改已有机器选择的入口；交互式 `apply` MUST 自行展示预览并完成必要确认，不要求用户手工复制 `plan_id` 或逐个输入目标 ID。非交互执行仍 MUST 绑定只读预览身份及明确接管选择。
- **FR-024**: `lock`、`sync` 和代理服务操作 MUST 有有界等待、可见阶段与定期进度；超时或中断 MUST 报告已完成阶段、未完成项、是否修改配置/包/服务及可执行的重试或恢复命令。普通输出不得含秘密，结构化最终结果 MUST 可与进度分开解析。
- **FR-025**: `doctor` MUST 给出每组件及整体的可执行/被阻断结论与下一条建议命令；结构化输出 MUST 提供明确就绪字段，脚本 MUST 可选择让阻断项产生非零退出码。`rollback` MUST 有只读预览入口，供非交互调用取得匹配的 `plan_id`。
- **FR-026**: 修改同一机器配置、运行包选择、同步状态或服务租约的操作 MUST 在读取可变状态前取得该机器的独占活动锁，并持有至提交或留下可恢复记录；锁被占用时 MUST 在写入前返回活动实例冲突，不得终止持锁进程。
- **FR-027**: 版本化 core/插件运行包 MUST 与秘密及私人配置分开存放；暂存、目录、普通资源和可执行入口分别声明当前用户属主与必要权限，并在激活前后验证，不得用配置文件的 `0600` 模式破坏可执行入口。
- **FR-028**: 修改仓库共享依赖锁的 `lock` MUST 使用独立于机器活动锁、路径命名空间不相交的仓库级独占锁，并在提交前复核开始时的旧锁身份；同一仓库并发更新冲突 MUST 在覆盖前返回 4。`sync/apply` MUST 读取完整锁快照并在依赖该快照的本机状态提交前复核，防止与维护者更新交错；锁冲突不得静默改选版本或改写 HOME 目标。

### Key Entities *(include if feature involves data)*

- **组件**：可单独选择的同步单元，包含公开来源、必要/可选环境条件和目标文件清单。
- **来源文件**：项目分发的非秘密内容及版本身份；同步时保持不变。
- **目标文件**：机器上的预定位置，可处于不存在、未受管、已受管、漂移或冲突状态。
- **备份**：覆盖前目标的可恢复上一版及必要元数据，由用户私人保管，与公开来源和运行数据分离。
- **同步记录**：组件、目标、所有权、来源身份、应用前后状态和恢复状态；不保存秘密值。
- **环境检查结果**：必要条件、可选条件、未检查项及可操作建议。
- **代理服务**：mihomo core 的已停止、运行中、异常或未检查状态，以及用户显式请求的服务操作结果。
- **私人代理数据**：订阅、凭据和运行状态；由 mihomo mgr 保管，与可同步配置分离。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 覆盖前，100% 的目标都在预览中显示位置、拟执行操作和是否有可恢复备份。
- **SC-002**: 三种组件分别独立同步时，未选组件的文件和运行数据变更数均为 0。
- **SC-003**: 在隔离的首次接管、重复同步和更新场景中，成功恢复均得到同步前的内容与必要权限；用户改动目标后的静默覆盖数为 0。
- **SC-004**: 必要环境缺项、来源损坏或单次 `apply` 中任一配置目标备份失败时，该调用的目标内容变化数为 0，错误能定位到组件和失败条件。
- **SC-005**: 多文件中断后，每个目标都有明确状态及下一步恢复指引；虚报成功次数为 0。
- **SC-006**: 用户在本地离线环境中用不超过 3 条命令，即可获得三组件逐项预览与环境结论。
- **SC-007**: 默认验收过程对真实 HOME、代理进程、tmux 会话及外部网络的改动次数为 0；服务操作只在独立、显式的验收步骤中验证。
- **SC-008**: 在代理服务运行中同步新配置的隔离验收场景，自动重载或重启次数为 0，且 100% 的成功同步结果提示配置待生效。
- **SC-009**: 在含用户自定义非秘密内容的 `~/.zshenv` 验收场景中，未经明确确认的覆盖次数为 0；确认后的成功覆盖均能恢复原文件内容和必要权限。
- **SC-010**: 隔离验收中，交互式首次 `apply` 不需手工复制 ID；常规目标最多一次总体执行确认，存在自定义非秘密 `.zshenv` 时最多再增加一次专门确认；非交互回滚可先只读取得回滚 `plan_id` 再执行。
- **SC-011**: 隔离的慢下载、服务启动、超时和中断场景中，长操作至少每 2 秒报告阶段或心跳，均在声明的期限内结束并给出脱敏的失败位置、已发生副作用与下一条命令；`--json` 最终结果保持可独立解析。
- **SC-012**: 两个并发操作针对同一机器进行 `apply/rollback/sync` 或服务状态修改的隔离验收中，至多一个取得写锁；另一个在写入前返回 4，目标、备份和事务记录没有交错或损坏。
- **SC-013**: 两个维护者操作并发更新同一仓库锁，或 `lock` 与 `sync/apply` 并发时，旧锁身份失效的一方在覆盖或本机选择提交前返回 4；共享锁无丢失更新，HOME 目标、已选 core 和待生效状态不基于过期锁提交。机器 ID 即使与仓库锁名称相同，两类锁也不指向同一文件。

## Assumptions

- 同步前只备份**目标位置的旧文件**；仓库来源保持不变并记录身份，不额外备份仓库来源。
- 首版“代理”包括 `mihomo-mgr`、mihomo core、非秘密代理配置和服务管理；私人订阅、凭据与运行数据留在独立文件，由 mihomo mgr 管理。
- 首版同步 zsh/tmux 的完整公开配置与辅助脚本，并在选择 zsh 时将 `~/.zshenv` 纳入整文件覆盖；该文件中的私人值须先迁出。代理私人运行目录继续由 mihomo mgr/用户维护。
