**Feature Branch**: `main`（当前分支；未配置创建分支的扩展钩子）

**Created**: 2026-09-16

**Status**: Completed（2026-09-24 按用户修订范围验收通过；[关闭报告](../../docs/acceptance/pi-spec-closure-20260924/README.md)）

**Input**: User description: "整理pi的当前配置和starter里的pi配置相关的同步功能，梳理清楚功能处理好各功能的统一性和完整性连通性之后，迁移到agentcfg体系里，最终基于agentcfg体系在任意机器上构建完整的能力。要考虑pi功能的完整性，比如task keeper应该适配新subagent版本进行改造，有一些codex subagent是否还需要保留，agentcfg的架构体系是否适合等等问题。"

## User Scenarios & Testing *(mandatory)*

### 本 spec 的最终验收范围（2026-09-24）

按用户明确决定，本 spec 交付全部软件迁移与 Linux x86_64 四配方的 mock/native、双路径冷重建；另外三个平台实机及所有真实账号/服务 live 验收移至独立后续工作，不阻塞本 spec 完成。
本文场景的功能行为要求保留，当前通过声明限定于上述平台和层级。完整修订及原任务去向见 [范围修订](scope-change-20260924.md)；其他平台与 live 仍为未验证，不记作通过或未选。

### User Story 1 - 确定完整能力基线与迁移决策 (Priority: P1)

作为维护者，我需要对照当前 Pi 环境、starter 的配置与同步行为，知道实际拥有、正在使用、
尚未连通及已经废弃的能力，先确定统一后的能力清单和管理边界，再迁移。

**Why this priority**: 当前包声明、磁盘内容、文档和已验证能力不同；直接复制会遗漏能力或保留失效入口。

**Independent Test**: 用含有来源模板、用户覆盖、旧包残留和缺失资源的样例完成盘点，
逐项追溯来源与处置，不改变原环境，也不需要启动 Pi。

**Acceptance Scenarios**:

1. **Given** 同一能力出现在模板、现用配置和旧安装目录中，**When** 生成基线，
   **Then** 分别记录声明、存在、加载验证和可用验证状态，不将磁盘存在视为正在使用。
2. **Given** 某本地插件依赖另一个技能或子代理框架，**When** 审查迁移清单，
   **Then** 能从入口追溯配置、依赖、执行者、结果与验收，缺少任何环节都列为缺口。
3. **Given** 重复角色、未声明用户资源或仅在旧文档中出现的功能，**When** 确定处置，
   **Then** 每项都有保留、改造、合并、替代、可选或排除的决定及理由；用户定制不会被默默删除。
4. **Given** agentcfg 某个边界不能承载目标能力，**When** 完成架构适用性评估，
   **Then** 明确需要扩展的管理能力、兼容影响及验证方式，解决阻断后才开始依赖该结论的实现。

### User Story 2 - 在新机器上构建同一套能力 (Priority: P1)

作为用户，我希望在一台没有 starter、Neovim 同步环境或旧 Pi 缓存的受支持机器上，
仅依靠 agentcfg 的配置来源、锁定依赖、机器设置和自己的登录完成可用环境建设。

**Why this priority**: 跨机器完整复现是迁移的最终价值，不能依赖原机器碰巧存在的目录和软件。

**Independent Test**: 在全新目录中按交付文档构建选定能力集，比较其功能清单和就绪状态；
默认验证使用替身，原生加载及服务调用分别在明确授权后验证。

**Acceptance Scenarios**:

1. **Given** 环境只有文档声明的工具链、可用依赖源和 agentcfg 仓库，**When** 用户配置机器参数并完成准备、部署与启动，
   **Then** 所选技能、插件、角色、提示模板、主题和服务入口均可定位并按声明使用，无需修改生成文件。
2. **Given** HOME、仓库、业务项目路径与原机器不同，**When** 构建同一配置，
   **Then** 能力与依赖身份一致，只有明确声明的机器参数不同，不再读取 starter 或旧 Pi home。
3. **Given** 尚未登录、未配置代理或缺少可选外部工具，**When** 检查状态，
   **Then** 分别显示待登录、机器依赖缺失或可选能力未启用；无关能力可用，必需能力未就绪时不宣称完整可用。
4. **Given** 只执行配置验证、预览或部署，**When** 环境缺少依赖，
   **Then** 不隐式安装或启动宿主；用户通过明确的依赖操作准备后再继续。

### User Story 3 - 在新子代理体系中完成受管长任务 (Priority: P1)

作为用户，我希望 Task Keeper 在统一后的子代理体系中完成调查、修复、真实检查、必要审查和可选第二视角，
并准确处理用量、预算、等待、暂停、恢复、停止和一次性定时，而不是只显示已安装。

**Why this priority**: Task Keeper 的旧集成依赖另一套子代理契约，是完整迁移的必需部分。

**Independent Test**: 通过受控执行者和虚构服务单独验证任务生命周期、证据及预算；
最终再对选定原生组合执行独立授权的集成验收，不依赖其他可选插件全部完成。

**Acceptance Scenarios**:

1. **Given** 用户已启用并配置 Task Keeper 的模型、角色和项目检查，**When** 提交调查或修复，
   **Then** 任务沿声明的角色分工运行；修复使用独立候选工作区并完成真实检查与必要审查，原工作区不被自动合并。
2. **Given** 启用第二视角且候选内容发生修改，**When** 两个视角提出并处理分歧，
   **Then** 复查当前候选和证据，在有限轮次内得出可核实结果或阻塞原因，旧候选的通过不能覆盖新改动。
3. **Given** 子任务遭遇限流、超时、服务失败或预算耗尽，**When** 处理等待、重试和恢复，
   **Then** 保留原任务身份与累计消耗，在所有请求前执行预算约束，不重复启动同一执行，不擅自更换供应商。
4. **Given** 用户暂停、恢复或停止任务，**When** 系统报告状态，
   **Then** 区分停止请求已接受、执行已结束和资源已回收；无法确认终止时保持未知或阻塞，不释放冲突保护；原控制者崩溃后，用户可在归属核实后明确请求停止旧执行，不必重新获得失效控制者的权限。
5. **Given** 子任务尝试突破角色权限、使用未声明工具或从父上下文获得额外权限，**When** 执行该动作，
   **Then** 动作被拒绝并产生可核实原因；不以只读提示词或父界面权限配置代替实际限制。
6. **Given** 用户建立统计分组或 Pi 内一次性定时任务，**When** 查看统计或到期执行，
   **Then** 分组不清空任务预算，定时任务不重复触发，未执行和过期状态明确；退出 Pi 后不承诺唤醒。
7. **Given** 所选子代理组合缺少所需恢复、终止或权限能力，**When** 准备受管任务，
   **Then** 在执行前阻止不满足条件的任务并说明缺口，不能仅修改版本声明或长期禁用 Task Keeper 后声称迁移完成。

### User Story 4 - 安全切换与日常维护 (Priority: P1)

作为已有 Pi 用户，我希望先查看差异再切换管理方式，以后统一更新配置、捕获允许的原生偏好、修复依赖和回滚，
同时保留账号、会话、用户修改以及现有 DSH 环境。

**Why this priority**: 迁移与维护必须保护既有工作，失败后能够恢复并继续操作。

**Independent Test**: 在临时环境中放入旧同步标记、定制文件和模拟运行状态，
分别验证预览、冲突、重复部署、中断与回滚；用哨兵确认旧环境和 DSH 未被写入。

**Acceptance Scenarios**:

1. **Given** 旧同步器管理着全局 Pi 配置，**When** 创建迁移预览，
   **Then** 展示受管范围、配置差异、行为变化及机器依赖，不修改旧环境；切换后每个目标只有一个写入管理者。
2. **Given** 用户和公共来源都修改了同一受管值且结果不同，**When** 部署，
   **Then** 报告冲突并保留双方内容；单侧原生漂移不被静默覆盖或接纳为新基线。
3. **Given** 已成功部署，**When** 重复部署、模拟中断或执行回滚，
   **Then** 无变化不轮换备份，失败可恢复，回滚仅恢复上一轮受管配置，不恢复或删除账号、会话、任务数据和未知文件。
4. **Given** 父 Pi 已退出但其受管子任务仍活动或终止状态未知，**When** 请求影响它的更新或恢复，
   **Then** 阻止不安全操作并报告原因，不以父进程退出认定整个实例空闲。
5. **Given** 用户修改支持捕获的主题或模型选择，**When** 请求采纳，
   **Then** 生成可审阅的非秘密来源修改提案；不支持的选择明确失败，不全量导出原生配置。

### User Story 5 - 统一委托入口并保留有价值的可选能力 (Priority: P2)

作为用户，我需要通过完善后的 model-delegate 统一执行 Pi 模型和真实 Codex 委托，
明确它与普通子代理、Task Keeper 的职责。迁移后不再维护 codex-delegate 或七个独立 Codex 角色，
保留各角色用途，并在新入口补齐所需写入、观察、控制和结果验证能力。

**Why this priority**: 统一并不意味着按目录全量保留或统一删除，必须以实际用户用途和完整调用链决定。

**Independent Test**: 对旧角色和调用方逐项建立 model-delegate 替换映射，
用 Pi/Codex 假执行者验证路由、只读/显式写入、恢复与凭证；从新环境排除旧执行器后再次运行，
证明新入口独立可用，关闭 Codex backend 时其他能力仍成立。

**Acceptance Scenarios**:

1. **Given** 旧 Codex 角色与新子代理或第二视角用途重叠，**When** 完成处置评估，
   **Then** 七个角色均停止独立注册，原用途映射到 model-delegate 的用途模板；
   用户指定 Codex 时显式选择 Codex backend，不能悄悄改用普通 Pi 模型。
2. **Given** 用户明确选择真实 Codex 执行，**When** 委托返回，
   **Then** 结果对应本次请求、工作目录和执行凭证；失败、空结果、超时或过期凭证不会被其他模型输出冒充成功。
3. **Given** 未启用 Codex 可选能力或机器缺少其依赖，**When** 使用普通子代理与 Task Keeper，
   **Then** 不依赖 Codex；调用 Codex 专属入口时得到明确的未就绪说明。
4. **Given** 技能、扩展、包或项目配置提供同名角色、提示或控制行为，**When** 形成最终能力集，
   **Then** 能看见选定来源、优先级或冲突；权限、重试、循环保护、代理和通知不会因重复加载而失效或执行两次。
5. **Given** 用户明确授权在隔离候选工作区执行 Codex 写入，**When** 使用 model-delegate 提交并观察该任务，
   **Then** 写入范围、进度、停止、恢复和结果均由新入口处理；未授权写入、并发写入冲突与重复重试被拒绝。
6. **Given** 新安装环境完全没有旧技能、run-codex.sh 或七角色注册，**When** 运行迁移后的技能、工具、提示、控制与多模型比较，
   **Then** 所有保留用途可由 model-delegate 独立完成，运行时不会回退查找旧执行器。

### User Story 6 - 升级与诊断仍可复现 (Priority: P2)

作为维护者，我希望新增机器或升级 Pi、子代理和插件时，知道哪些能力仍兼容、哪些需要重新验证，
并能通过同一套来源维护配置，不重新依赖 starter 的历史操作经验。

**Why this priority**: 一次性迁移无法满足长期跨机器构建，必须交付可维护的能力与证据边界。

**Independent Test**: 替换一个不兼容或损坏依赖，验证诊断、拒绝启动、修复、升级说明与证据失效行为。

**Acceptance Scenarios**:

1. **Given** 依赖损坏、角色缺失、模型绑定失效或外部服务不可达，**When** 检查就绪状态，
   **Then** 定位到具体能力和配置来源并提供下一步操作，不泄露秘密，不用“包已安装”概括所有状态。
2. **Given** 升级了子代理或插件组合，**When** 审阅升级，
   **Then** 能看到依赖与行为差异、需要重新运行的验收和回退边界；旧组合的通过记录不自动证明新组合通过。
3. **Given** 新机器维护者仅持有交付文档，**When** 增加技能、调整角色、切换模型或禁用可选插件，
   **Then** 能修改唯一受管来源并完成验证与部署，不需编辑原生产物或回到 Neovim 执行同步。

### Edge Cases

- 模板、当前配置、安装目录和同步标记相互矛盾；旧文档遗漏 Task Keeper 或新增包。
- 同时存在两个不同来源的子代理包；旧版本残留不代表允许同时加载。
- 本地包指向 starter 源目录，完整镜像却是另一版本；技能有多个副本或引用包外脚本。
- 项目级角色或配置覆盖全局定义，或隐式扫描其他工具的技能目录后扩大子任务能力。
- 同名提示、循环保护、权限、恢复或调度插件重复注册；可选网络插件影响预算统计或模型请求。
- 当前私有模型、MCP 服务、代理端口或外部命令在新机器上不存在，凭据只在原机器持有。
- Task Keeper 默认未启用或缺少项目检查绑定；配置存在与完整就绪必须分别报告。
- 子任务报告 completed/stopped，但没有完整结果或仍有外部操作；结果被回收、过期或属于旧运行。
- 暂停/恢复跨越配置或版本变更；不能恢复时需要新的执行身份，但不能清空原预算与失败记录。
- 父进程退出、并发部署、源端删除资源、符号链接越界、备份损坏或恢复期间再次中断。
- 未知字段来自严格框架输入或非受管原生设置；前者拒绝，后者保留，不混淆两类规则。
- 空数组和 false 表示显式禁用；不能被缺省值覆盖或在迁移时变成继承旧能力。
- 不同机器路径、工具链或平台不兼容；允许范围与实际通过范围不同，不能扩大支持声明。
- 未授权真实宿主或账号验收时，只能记录未执行；不能把默认隔离测试结果当作真实联通证据。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 必须建立当前 Pi、starter 配置来源与同步行为的联合清单，区分来源声明、当前选择、磁盘存在、实际加载和功能验证五种事实；不可观测项标为未验证。
- **FR-002**: 每个清单项必须记录用途、来源身份、依赖、当前状态、目标归属、处置决定、理由及验收场景，覆盖配置、技能、角色、插件、提示、主题、服务和外部工具。
- **FR-003**: 必须识别当前环境独有、已禁用、过期、重复及未声明资源；对用户定制生成显式处置提案，不能自动删除或遗漏具有用户用途的能力。
- **FR-004**: 必须给出每项保留能力从用户入口、配置、依赖、执行到结果与证据的连通关系；所有必需环节缺口必须在完整交付前关闭。
- **FR-005**: 实现前必须评估 agentcfg 对配置表达、资源发现、依赖重建、秘密与身份、启动与子任务、备份恢复、诊断、跨平台和 DSH 兼容的适用性；每项给出复用、扩展或不适用结论、理由和验证条件，阻断项不得由直接写原生目录绕过。
- **FR-006**: 迁移必须形成确定的能力基线，列出必需、可选和排除项；Task Keeper 的新子代理适配属于必需项，不能通过排除或长期关闭它降低完成标准。可选项一经选择也必须满足完整性验收。
- **FR-007**: 交付的公共来源必须自包含且可追溯；在不同目录部署后不依赖 starter、Neovim、旧 Pi home、未声明全局缓存或本机临时补丁，相关技能及插件的来源与许可说明必须保留。
- **FR-008**: 所需工具链、外部命令、代理、MCP 服务和机器路径必须作为明确前提或机器配置列出；不得把原机器的端口、模型、账号、私有服务或隐式全局扫描当成通用默认。
- **FR-009**: Pi、本地及远程插件、技能分发包与运行所需传递依赖必须具有可核验的固定身份和完整获取方式，源不可达、完整性不符或必要包缺失时必须明确失败，不退回未锁定版本。
- **FR-010**: 必须维持 agentcfg 现有校验、渲染、预览、依赖准备、部署、诊断、启动、捕获及回滚的职责和退出码；离线操作不隐式安装，依赖操作不启动宿主，启动不隐式部署。
- **FR-011**: 主模型、角色模型、第二视角、工具服务、重试与预算策略必须能追溯到一致的配置来源；同一语义的重复设置必须有明确优先级，不允许各插件静默选择互相矛盾的值。
- **FR-012**: 必须严格拒绝未知框架字段、无效引用和不支持的能力组合，保留空数组及 false 的禁用语义；不支持的原生字段映射必须可定位，不能静默丢弃或生成假配置。
- **FR-013**: 必须迁移所选技能和插件的完整运行资源、相对引用及必要执行权限，并验证其可发现和可调用；复制期间不得运行技能脚本或加载插件。
- **FR-014**: 必须明确公共、工具、机器、实例和项目级资源的发现范围、优先级和覆盖规则；外部技能引用必须显式选择，不能因新机器的环境目录不同改变承诺的默认能力。
- **FR-015**: 同一会话必须只有一个选定的子代理管理者；同名角色、工具、提示或重复插件注册必须在检查阶段得到明确选择或冲突结果，旧包残留不能自动参与运行。
- **FR-016**: 规则、技能、提示和文档中的委托指令必须与实际选定能力一致；替换旧入口后必须同步关联引用，不能留下建议调用不存在角色或工具的内容。
- **FR-017**: 秘密、OAuth、trust、会话、任务历史与运行缓存不得作为公共配置迁移；诊断和差异不得暴露秘密，账号接入必须使用用户自己的本地凭据或独立登录。
- **FR-018**: 每个工具和 profile 必须隔离配置、身份、运行状态、依赖管理、备份与锁；Pi 及其所选扩展在实例目录之外的写入必须有明确所有权，不能默认接管用户全局目录。
- **FR-019**: 迁移前必须提供受管目标、差异、行为转换、用户定制和外部依赖的可审阅预览；默认保留旧来源及原环境，切换方案必须避免新旧管理器同时写同一目标。
- **FR-020**: 部署必须沿用三方比较与冲突规则，保留原生单侧漂移，不能将保留漂移自动变为基线；非受管字段与未知用户文件必须保留。
- **FR-021**: 必须提供上一轮受管配置备份、无变化幂等、失败恢复及回滚；不将软件降级、账号或任务数据库恢复混入配置回滚，不在迁移中清理旧运行数据。
- **FR-022**: 活动及终止未确认的受管子任务必须纳入实例变更保护；不能仅因父进程退出而更新其仍使用的资源，也不得终止用户进程来取得写权限。同一工作区的写入保护必须跨实例/profile生效，路径别名或不同HOME不能绕过；原执行终止未确认时不得重新授予写权限。分配意图必须早于共享写入预留持久化，明确启动提交边界，并覆盖预留中崩溃且执行尚未创建的回收。
- **FR-023**: 新子代理体系必须覆盖已选择的只读调查、审查与 Task Keeper 受管执行用途；只读试用配置必须保留为明确的能力子集，不能代表整个迁移已完成。
- **FR-024**: Task Keeper 必须适配选定新子代理组合的实际能力与生命周期；必须核对实际加载身份与所需权限、结果、终止和恢复能力，缺少条件时在执行前拒绝，不只放宽版本限制。
- **FR-025**: Task Keeper 必须保留任务统计、受管调查与修复、独立候选工作区、真实项目检查、必要审查及可选有界第二视角；完成必须绑定当前候选证据，不能自动合并原工作区。
- **FR-026**: 任务与子任务必须统一累计请求、轮次、用量及可确定的费用；未知费用标为未知，重试、恢复、切换统计分组不能重置任务预算或重复计数。
- **FR-027**: 等待、重试和故障切换必须遵守用户选择的模型路线、授权与请求前预算约束；主任务、子代理与其他插件不能重复接管同一次恢复，也不能产生未计入约束的辅助模型请求。
- **FR-028**: Task Keeper 必须支持可区分的等待、运行、暂停、恢复、失败、未知与终止状态，保留本次执行身份；停止回执不能代替资源终止证据，不兼容恢复必须明确改为新执行并保留原预算和审计关联。原监督者已失效且目标归属可证实时，用户必须能明确授权停止该旧执行；该恢复权限仅用于撤销和停止，不自动接管继续执行或解除未知状态。
- **FR-029**: 子任务必须实际执行角色工具、可读写范围、父侧适用拒绝规则和嵌套限制，不得通过上下文继承或辅助执行绕过；必要保护不可实现时阻止该受管能力，不能静默降级为提示词约束。普通父会话仍可在其明确授权的业务工作区实施；候选执行对源工作区的禁写限制不得误用于全部普通会话。权限规则必须有固定字段、匹配方式、拒绝优先级和父规则转换规范；不可转换输入明确失败，不能由实现者自行放宽。
- **FR-030**: 必须保留 Pi 活动期间的一次性定时与其取消、过期及去重行为；不承诺退出 Pi 后自动唤醒或周期调度，多个调度入口不能重复执行同一任务。
- **FR-031**: 必须交付可复现的 Task Keeper 启用与绑定流程，检查模型、项目验证、角色及能力条件；默认关闭可以作为安全初始状态，但完整验收必须包含启用后的实际流程。
- **FR-032**: 必须将七个旧 Codex 角色收敛为 model-delegate 统一入口的用途模板，退出独立角色注册；Pi 与真实 Codex 由明确的执行者选择区分，给出每个旧角色、工具和技能入口的新映射。Codex backend 可以按配方选用，model-delegate 的替换工作属于必需交付。
- **FR-033**: model-delegate 的各执行后端必须关联本次请求、工作目录、终态和完整结果凭证，区分执行成功与审查通过；部分输出、超时、取消、空结果、错误模型或旧凭证不得冒充成功，也不能自动换用别的执行者。
- **FR-034**: 必须评估并处理子代理、Task Keeper、循环保护、权限、自动确认、网络代理、压缩、通知与其他所选插件的相互作用；每种有控制冲突的组合必须明确单一责任者或拒绝同时启用。
- **FR-035**: 用户必须能够分别查看资源已声明、已部署、依赖已准备、加载已验证、账号待接入、运行已验证、未执行及阻塞原因，不能用单一“已安装”状态代表功能可用。证据不足或部分失败时仍须能生成完整状态报告，报告成功与交付验收通过是独立结果。
- **FR-036**: 诊断必须定位到相关能力、受管来源和补救动作；离线诊断不调用模型，联网诊断及真实账号验证保持独立，所有错误遵守现有秘密和退出码契约。
- **FR-037**: 必须通过 agentcfg 来源维护主题、模型、角色、技能和插件选择；支持捕获的原生偏好只能生成经过验证的非秘密提案，交付新机器与升级维护文档。
- **FR-038**: Pi 接入不得改变 DSH 已有配置、依赖、启动、备份及退出码行为，必须验证两种工具和多个 profile 共存的隔离与兼容性。
- **FR-039**: 必须发布机器前提、平台与架构支持矩阵，区分允许安装、通过隔离测试、通过原生加载和通过服务调用；未验证组合不能宣称完整支持。验收范围区分必需、已选可选和未选项；缺账号、机器或授权不能改记为未选择，不得因失败自动缩减范围。
- **FR-040**: 默认验收必须使用临时环境、网络阻断、假宿主、虚构服务和哨兵；真实宿主与真实账号验收必须独立明确授权，历史报告、退出零或测试替身不能替代本次相应证据。
- **FR-041**: 完整交付必须在声明支持的每种平台上，用至少两个不同 HOME 和仓库路径的干净环境证明所选能力可重建，并验证每条必需能力链；不允许复制旧 home、缓存或手工补丁来通过验收。
- **FR-042**: 升级宿主、子代理、插件或关键机器契约时必须展示差异并使受影响旧证据失效，重新验证相应能力；与旧运行不兼容的恢复、数据或回退限制必须在切换前说明。
- **FR-043**: 必须完善 model-delegate，保留 Pi/Codex 的只读调查、审查、显式模型选择、取消及恢复，并补齐替换所需的隔离工作区写入能力；写入必须经显式授权，不自动重试，不与其他实例/profile中同工作区的活动写任务冲突，原任务未知状态仍保持互斥。
- **FR-044**: 统一入口必须提供可持续观察的长任务控制、后台启动确认、增量进度、等待终态及未知启动处理；结构化任务上下文、反馈与当前请求/候选关联，不得因替换丢失约束、伪造进度或将未验证反馈当成事实。
- **FR-045**: 必须适配所有相关技能、Pi工具桥、角色用途模板、提示、规则、配置、锁、登录、权限、网络、活动监督、文档和测试；批量委托沿用唯一上层编排责任，不能引入第二个调度者或绕过 Task Keeper 的预算门控。
- **FR-046**: 迁移后的发布来源、锁依赖、技能发现、工具注册和运行路径不得依赖 codex-delegate、run-codex.sh 或七个旧独立角色；在它们完全缺席的干净环境中通过替换验收。旧机器来源和历史数据保留，不能为退出新体系而删除用户原环境。

### Codex 原生执行边界（2026-09-17继续实施修订）

FR-029/FR-043按实际执行器区分授权保证：Pi受控工具和Task Keeper为agentcfg-tools，逐工具复核；
普通Codex委托为native-sandbox，使用官方CLI原生工具，按整次运行授权。execution_boundary与
execution_policy_digest由可信适配器写入请求/收据，不接受模型覆盖。显式native_execution.allow_shell
才授权沙箱内动态命令；不能从tk_read或某个command_ref的allow推导原生命令权限。

原生授权仍受可表达的文件范围、父deny、秘密/源checkout保护、独立候选与跨实例写租约约束；
无法无扩权映射的规则在启动前失败。取消、超时或策略失配停止整个执行，直到物理终止前保持保护；
停止窗口内可能继续发生原授权内操作，不承诺下一条内部工具动作即时撤权。

2026-09-18 用户确认保留官方 CLI，并接受无法核验系统／企业配置时拒绝执行的兼容性缺口。
每次启动检查系统来源、macOS 受管偏好和实例账号类别；组织、未知或无法核验的组合保持不支持，
不自动修改管理员配置或换账号。稳定受信机器及账号是运行前提，独立预检不提供原子配置绑定。
该限制进入执行策略身份、诊断与支持矩阵，已选账号／服务及平台验收范围继续保留。
Task Keeper预算与逐工具门控保持不变，不允许用外部Codex绕过。

FR-033的原生结果验证使用冻结授权、当前请求/候选/运行时、原生完成事件、非空产物和物理终止证明，
不要求Codex生成agentcfg工具操作日志。候选结果快照不代替沙箱对越界写入的防护。

### Key Entities *(include if feature involves data)*

- **能力项**：用户可使用的一个功能，关联入口、配置、资源、依赖、控制责任、结果和验收证据。
- **迁移基线**：源配置与当前环境的有日期快照、差异、逐项处置和目标能力集；不含秘密与运行历史正文。
- **能力配方**：必需能力与用户选择的可选能力组合，包含依赖关系、兼容条件及禁用含义。
- **机器绑定**：具体机器的路径、工具、网络与凭据引用；与公共配置分离。
- **受管实例**：指定工具与 profile 的配置、身份、依赖、备份、活动保护和运行状态边界。
- **角色与委托策略**：职责、模型路线、权限、上下文、预算和执行者选择，以及旧入口的替代关系。
- **统一委托执行**：model-delegate 的后端、用途、运行身份、工作区授权、控制状态、进度与结果凭证；与上层编排和 Task Keeper 任务关联但不重复拥有调度权。
- **受管任务与执行尝试**：任务、子任务、候选成果、消耗、暂停恢复、定时状态和每次执行身份的关联。
- **兼容与验收记录**：精确能力组合、机器条件、场景、结果、证据和未验证范围；版本变化后可识别失效。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 联合清单中 100% 的资源与用户能力具有来源、处置和目标或排除理由；必需能力中没有未决依赖或无验收入口的项目。
- **SC-002**: 本 spec 验收平台 Linux x86_64 上，四配方各至少两个 HOME 与仓库路径不同的干净环境按同一文档完成重建，所选能力清单一致，需编辑的生成文件数为 0；其他平台验证转入后续清单。
- **SC-003**: 本 spec 固定范围内 100% 必需和所选能力具有 mock/native 从用户入口到结果的通过证据；仅安装、仅发现或未执行不抵扣验收。真实账号/服务 live 的通过声明留待后续独立验证。
- **SC-004**: 受管任务的调查、修复、必要审查、第二视角、限流等待、预算耗尽、暂停恢复、停止、一次性定时和结果丢失这 10 类场景全部产生可核实的预期结果，错误报告成功的次数为 0。
- **SC-005**: 在预算和权限负向场景中，超过配置额度的模型请求、越权动作、重复恢复执行及因统计分组重置预算的次数均为 0；无法确认终止时误报资源已回收的次数为 0。两个profile并发申请同一工作区时最多一个写授权成功；控制者崩溃后的显式停止不得误终止非目标进程。
- **SC-006**: 迁移、重复部署、冲突、失败恢复和回滚场景中，旧环境、账号、秘密、任务历史及非受管文件的非预期变更为 0，公开配置和诊断中的秘密泄露为 0。
- **SC-007**: 同一输入连续两次部署，第二次实际受管变更与备份轮换次数均为 0；每个声明的恢复故障点均能恢复到可解释状态，且不丢失用户修改。
- **SC-008**: 每个旧委托角色和入口都有保留或替代决定，默认会话的重复子代理管理者为 0；真实外部委托的失败、空结果或旧凭证被标为成功的次数为 0。
- **SC-009**: 既有 DSH 回归及工具/profile 隔离场景全部通过；原有有效配置需要为 Pi 接入而强制修改的数量为 0。
- **SC-010**: 交付时所有架构评估阻断项均关闭，本 spec 的 Linux x86_64 mock/native 范围内必需能力的未验证机器前提为 0；维护者仅凭交付文档即可完成增加技能、调整角色、切换模型和禁用可选插件这 4 项操作，无需使用旧同步器。

- **SC-011**: 七个旧 Codex 角色与全部登记的旧调用方100%完成映射；新发布环境中旧技能、执行器、工具和独立角色的可执行依赖或注册数为0，旧入口缺席时替换场景全部通过。
- **SC-012**: 统一委托的只读调查、审查、显式写入、后台启动、增量观察、取消、恢复、终态等待、多模型比较及反馈关联这10类场景全部有对应通过证据；不支持写入的后端必须明确拒绝且零越权。

## Assumptions

- 本特性面向仓库维护者和在多台机器上使用个人 Pi 环境的用户；“任意机器”指符合公开前提及已验证支持矩阵的机器。本 spec 验收 Linux x86_64，其他 Linux/macOS 目标保留实现并转至后续验证；不包含原生 Windows 或所有未知工具链的无条件兼容承诺。
- 当前 Pi 默认指本机 `~/.pi/agent` 及其显式资源引用；starter 来源固定为用户提供的 `/data/1/weixiaoxian.wxx/dev_tool/starter`。这些是调查入口，不是迁移后运行依赖。其他机器数据未提供，不视为已调查。
- 当前新版子代理调查基线为 `@tintinweb/pi-subagents@0.19.0`，旧 Task Keeper 依赖为 `pi-subagents@0.63.0`。这些是已观察到的来源身份，不代表最终选版或最新版本承诺；规划必须选择并验证能满足必需能力的明确组合。
- 默认以现用的新子代理家族为迁移方向，不继续并载旧管理者；若当前固定版本无法满足必需契约，规划必须给出升级、适配或替代方案与影响，不能将旧试用的限制自动当作最终豁免。
- “完整”按逐项确定的能力基线衡量，不要求无条件保留每个旧文件或启用所有上游功能。普通只读委托和受管长任务属于必需用途；Codex backend 作为可选能力；model-delegate 完整替换和七角色模板化属于必需交付。
- 不强制为只读或未配置用户开启 Task Keeper；本 spec 通过已完成绑定的虚构服务配置验证真实 native 受管流程，真实模型调用转入后续 live。复杂工作流、任意模型执行图、周期调度、退出后的唤醒和跨机器迁移会话/任务数据库不在范围内。
