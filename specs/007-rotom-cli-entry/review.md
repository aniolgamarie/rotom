## 审阅范围与方式

主代理负责需求、默认值和作用域决策、生成产物的计划/日志/恢复边界，以及最终验收。scout 核对当前源码事实与工作区绑定；独立 review 代理阅读方案和相关源码，返回具体反例和修订建议。各代理均未写应用代码、读取真实账号/会话文件、运行第三方宿主或执行功能测试。

本记录审查的是方案能否作为实施依据，不代表所设计的功能已实现、离线测试已通过或平台/账号已验收。代码写入、生产部署、现有入口切换、提交和合并不在本次工作范围。

## 整体用户旅程审查与优化

用户要求整体 review 后，本轮按首次安装、日常启动/恢复、维护后回原 pane、非交互失败四条旅程重新检查跨章节行为。scout 提供阶段/作用域/命令契约的一致性证据，独立 reviewer 检查产品路径与驻留生命周期；主代理作取舍并保持文档单一写入者。

| 编号 | 优先级与发现 | 已选择的修订 |
| --- | --- | --- |
| O1 | P1：驻留 manager 更新 checkout 后仍可能执行旧模块，读取新配置不等于重载管理代码 | 记录管理源码/控制协议身份，首版变化时拒绝旧进程原地恢复并转新位置；无租约 re-exec/handoff 后续单独验证，禁止混用新旧模块 |
| O2 | P1：no-input 维护在部分停止、超时和计划变化时缺少明确结束与结果契约 | 等待预算默认 30 秒、上限 300；到期保留逐项事实并结束后续步骤；返回批次、原操作结果、review_required 和带完整 scope 的下一步，不自动强杀 |
| O3 | P1：只读 plan 后仅传摘要，无法还原原来 operation/目标集合 | stop 带回同一 scope、operation、显式 run 选择并重新计算快照；dry-run 不落批次，接受后才持久化；批次后的新计划使用明确的重新接受 |
| O4 | P2：旧单次启动不会在第一次更新时自动获得驻留能力 | 停止前说明本次位置能力；旧进程不能在线转驻留，采用新契约需新实例/rebind；无法保留原位置时允许保留运行或预先换恢复位置 |
| O5 | P2：首阶段混合静态 resume 接口与实际恢复，M2/M3 的数字顺序又与依赖不一致 | 第一阶段只计入口/静态 help；第二阶段完成 DSH 索引和当前终端实际恢复；M1–M5 按能力依赖推进，不等待三工具同时完成；空接口不算 R8 交付 |
| O6 | P2：完整命令的 no-input 确认路径、未给工具的 session ID 分支不够确定 | 每个动作声明非交互批准策略，缺少等价路径退出 2；会话只在已限 scope 中解析，无匹配/歧义按 TTY 规则补 scope 或返回 2 |
| O7 | P3：首次安装依赖尚未部署的入口、根菜单不直接列 resume | 加入 checkout 自举至受管 zsh 的步骤表；恢复会话进入根任务导航，未准入明确说明，不新增安装向导 |
| O8 | P3：动态补全来源和状态含义不完整，容易复制执行逻辑 | 列全 kind/数据范围，公开会话索引复用；作用域矩阵进入注册表验收；运行/会话/位置能力分别显示，普通 stop/resume 与维护共用执行契约 |

O1–O6 是对应能力实施前需明确的契约，O7/O8 是同时吸收的范围与体验改进。此处的“已选择”指方案修订，不是代码已实现。整体审查不要求重复全量源码调查或真实操作，之前的 D/M 修订仍有效。

修订后的独立复核确认：只读计划重建、脚本部分结果、旧实例采用驻留、管理代码变化边界和阶段依赖均已闭环，没有新增必须修改的文字问题。方案可以作为分阶段实施依据；公开会话通道、writer 排他、退出证明、驻留/PTY 与维护能力仍需原型和真实验收。

整体建议：先交付统一入口，再交付 DSH 可用的 session ID 与实际 resume；然后做停止/维护，原位置及自动继续各自准入。保留现有 agentcfg 管理层和原生所有权，避免为所有工具一次搭建通用执行平台。管理代码变化时首版降级到新位置，比把无缝接续作为基础完成条件更容易给出可验证结果。

## 保留的关键判断

- 新 `rotom run TOOL` 负责按工具选配方；`rotom agent` 和既有工作区实例继续使用各自已定义的默认及固定绑定。不会为“统一”而覆盖它们。
- 第一次入口部署可以预览当前 checkout，已有绑定默认保持；从另一个 worktree 执行部署不自动更换日常入口。
- 动态 checkout 绑定属于新增受管产物。仅增加 PATH 或写一个未受管的脚本不足以完成这一交付；精确字节、计划快照、journal、接管、恢复和回滚必须一起验收。
- `agent usage` 的 `--help` 继续属于原生尾部。其它各级业务 help 不读取偏好、机器、凭据或会话。
- OMP 的普通短启动在首阶段；工作区 OMP type 属于独立扩展。已实现的配置化工作区并未自动提供这个 launcher。
- 不使用无参数菜单选择来替代部署接管、plan ID、工作区关闭 scope 或上游能力检查。
