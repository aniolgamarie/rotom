# Feature Specification: 公共治理对齐与 Pi Base/Pro 重建

**Feature Branch**: `design/pi-toolkit-reboot`

**Created**: 2026-10-18

**Status**: Draft（规格质量审查不代表实现或运行验收）

**Input**: User description: "退役仓库内整套旧 Pi 集成，重新构建 Base/Pro；通用配置、完整依赖锁、部署所有权和恢复与 DSH/OMP 对齐，公共模块共用，Pi 独立部分重新思考重建。配置与插件参考社区实践并适配当前稳定版本；状态栏信息量与原自建栏基本对齐。先完成方案与规格，在 reboot 分支工作。"

## Clarifications

### Session 2026-10-18

- Q: 首版是否需要允许同一个 Pi 配方（例如 pi-base）在多个终端同时运行独立主会话？ → A: 允许同配方多个主会话并行，各自独立记录归属；所有相关主会话及后代确认空闲后，才允许维护共享资源。
- Q: 同一 Pi 配方有多个主会话并行时，“最多两个调查子任务”的上限应按每个主会话分别计算，还是所有主会话合计计算？ → A: 每个主会话分别最多两个调查子任务，各主会话独立计算；两个主会话最多可同时运行四个调查子任务。

### Session 2026-10-19

- Q: 社区调查插件尚不能强制满足首轮边界时如何交付？ → A: 继续只用社区插件，Pro等上游完善；不自建调查执行插件，不降低原边界。T064–T071及完整feature门继续开放。
- Q: 权限来源不可查询、速度算法和窄屏布局的差异能否接受？ → A: 可以，按说明交付：详情写明“宿主未提供可查询的权限状态”，此项不代表权限保护；速度采用当前分支输出均值，窄屏部分统计放在详情。
- Q: Brave/Cursor缺各自凭据或OAuth时本轮如何处理？ → A: 本轮交付已验模块，Brave/Cursor延后真实账号验收。保留其已有接线、失败和未验证记录，不当作认证通过。
- Q: 如何补齐真实工具场景并避免模型读取秘密？ → A: 明确授权一次有界真实工具测试，最多12次工具调用，仅临时合成文件、检索和固定printf命令；使用相对合成文件名，其他工具/路径执行前拒绝，不向模型提供密钥正文、真实项目或私人数据。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用一致的管理方式维护三种工具 (Priority: P1)

作为同时使用 DSH、OMP 和 Pi 的维护者，我希望三者遵循一致的配置、依赖、部署和恢复规则，
公共能力只维护一份；Pi 的重建不会损坏另外两种工具，也不会将工具特有行为强加给它们。

**Why this priority**: 公共治理是新 Pi 的基础，也是避免以后维护三套重复逻辑的主要收益。

**Independent Test**: 在临时环境中，对三种工具分别执行相同类别的配置维护操作，
比较结果、冲突及失败行为，确认各自数据互不改写；不需要启用任何 Pi 增强模块。

**Acceptance Scenarios**:

1. **Given** 三种工具各有自己的配置与实例，**When** 预览或部署同一项公共规则变更，
   **Then** 三者遵循相同校验、覆盖及所有权规则，差异仅来自已声明的原生能力。
2. **Given** 用户修改了原生配置，**When** 部署来源更新，**Then** 非受管内容保留，
   单侧漂移不会被覆盖或自动接纳，双方修改且结果不同时报告冲突。
3. **Given** 依赖损坏、部署中断或仍有活动实例，**When** 请求维护，**Then** 分别报告
   所需修复、配置恢复或活动冲突，不自动安装、登录、终止进程或覆盖未知状态。
4. **Given** 只更新 Pi 的一个配方，**When** 操作完成或失败，**Then** 其他工具与配方的
   配置、账号、会话、依赖状态和备份均无非预期变更。
5. **Given** 同一 Pi 配方已有一个主会话运行，**When** 用户在另一终端启动第二个主会话，
   **Then** 允许并行且各自运行归属和会话记录独立；一个会话退出不会清除另一个的活动记录。
   维护共享资源必须等待所有相关主会话及后代确认空闲，未知状态继续阻止受影响维护。

### User Story 2 - 独立构建并日常使用 Base (Priority: P1)

作为用户，我希望在没有旧 Pi 环境的机器上，使用官方 Pi 完成阅读、检索、修改代码、运行命令、
选择模型和继续会话；只为实际使用的能力承担配置与启动负担。

**Why this priority**: Base 是可独立交付的日常工具，不应等待协作、订阅或外部研究模块就绪。

**Independent Test**: 在两个路径不同的全新样例环境中，按同一使用说明准备和部署 Base，
检查资源与就绪状态；原生交互和模型调用在分别获得相应授权后独立验证。

**Acceptance Scenarios**:

1. **Given** 只有声明的前提、公共来源和用户自己的机器绑定，**When** 构建 Base，
   **Then** 无需旧 home、旧同步器或手工修改生成文件，能得到相同的选中能力和依赖身份。
2. **Given** 用户处理一个简单修改，**When** 开始任务，**Then** 无需强制创建计划、
   Todo、工作树或子代理；需要复杂任务规划时沿用项目现有 SpecKit。
3. **Given** 用户切换模型、继续或分支会话、压缩上下文，**When** 操作结束，
   **Then** 使用原生能力，必要规则与资源仍可定位，选择值不会被冒充为服务端确认值。
4. **Given** Pro 或一个可选模块尚不兼容、没有凭据或未被启用，**When** 使用另一个独立
   Base 实例，**Then** Base 不依赖它；同一配方已明确启用的必需项缺失则如实阻止相关使用。

### User Story 3 - 可审阅地退出旧 Pi 集成 (Priority: P1)

作为已有 Pi 用户和仓库维护者，我希望明确看到旧实现的去向，新组合能独立运行，
并保护现有账号、会话、原生定制和仍在运行的工作。

**Why this priority**: 整套退役是此次重建的明确目标；删除旧代码与删除用户数据必须有不同边界。

**Independent Test**: 使用含旧资源、共享消费者、非受管文件和模拟活动状态的样例，
验证退役清单、切换预览、阻止冲突和恢复；在旧 Pi 专属实现缺席时检查新组合的独立性。

**Acceptance Scenarios**:

1. **Given** 一个旧文件同时被公共流程或另一工具使用，**When** 评估删除，**Then**
   先记录消费者与替代方案，公共用途仍由共用能力承接，不按文件名直接删除。
2. **Given** 旧 Task Keeper、AgentManager、model-delegate 及其资源仍在仓库内，
   **When** 完成退役，**Then** 它们退出新运行、分发与资源发现路径；引用均有去向，
   不因旧规格曾要求完整迁移而重建旧任务执行平台。
3. **Given** 旧实例仍活动或其归属无法确认，**When** 请求切换或清理，**Then**
   阻止受影响的不安全操作，不自动停止实例、不删除账号会话，也不将父进程退出当作全部结束。
4. **Given** 切换中断或用户需要配置回退，**When** 执行恢复，**Then** 可恢复受管配置，
   保留非受管新增内容，并明确软件、数据库和任务执行不属于配置回滚范围。

### User Story 4 - 从状态栏理解当前执行与用量 (Priority: P2)

作为日常 Pi 用户，我希望新界面的信息量与原自建状态栏基本对齐，能辨认模型、活动状态和
上下文风险，也能在需要时查看用量、缓存、费用与会话时间；未知数据不能制造确定性的错觉。

**Why this priority**: 状态栏是用户明确要求的体验目标，不能因精简插件而悄悄删去。

**Independent Test**: 使用已知与缺失数据的样例，分别检查宽度为 60、90、130 列的中文显示，
再验证模型切换、会话分支、压缩、取消及窗口缩放后的信息；不依赖 Pro 委派功能。

**Acceptance Scenarios**:

1. **Given** 存在可确认的模型、思考强度、活动和上下文信息，**When** 用户查看窄屏状态栏，
   **Then** 这些高优先级信息仍可辨认；路径只展示项目简称，统计可收拢而不冒充零值。
2. **Given** 服务未上报费用、缓存或上下文窗口，**When** 显示摘要，**Then** 标为未知
   或不可用，不猜测窗口大小、不把累计 token 当作当前上下文，也不将订阅估算称为实际账单。
3. **Given** 用户切换分支、继续会话或使用子代理，**When** 汇总用量，**Then**
   标明统计范围，不重复累计；主会话活动、后台进程存活和任务成功分别表达。
4. **Given** 候选状态栏不能通过公开接口取得所需信息，**When** 决定是否启用，**Then**
   不绕过宿主边界，保留原生回退并列明缺口；未经接受的缺口不能标为信息对齐完成。

### User Story 5 - 通过 Pro 获取有边界的调查协作 (Priority: P2)

作为处理复杂任务的用户，我希望每个主会话掌握自身任务的判断和写入，按需将独立调查交给
该主会话至多两个同时运行的只读子任务，各主会话独立计数，并能分辨返回结果、失败、取消及仍无法确认的状态。

**Why this priority**: 协作应为复杂任务带来直接收益，不能再引入一套任务调度与跨崩溃恢复平台。

**Independent Test**: 以一个独立调查、两个并行调查、越界或递归请求、失败与取消样例验证
协作边界；没有候选满足要求时，验证 Pro 协作保持未就绪而 Base 仍可使用。

**Acceptance Scenarios**:

1. **Given** 用户启用已准入的 Pro 协作，**When** 提交两个独立调查，**Then** 每项结果
   对应各自任务、资源范围和模型选择，主会话负责整合与写入，子任务不得再次委派。
2. **Given** 当前主会话已有两个调查运行，或请求涉及写入与后台执行，**When** 再请求执行，**Then**
   超出首轮范围的请求不会进入执行；角色名称或提示词不能作为已强制限制的证据。
3. **Given** 子任务失败、没有完整结果或用户请求取消，**When** 返回状态，**Then**
   分别报告任务结果、取消请求、可确认的进程状态与副作用，不自动重做可能有副作用的操作。
4. **Given** 候选无法限制可达工具、资源发现、并发或递归，**When** 做准入判断，**Then**
   该组合不被标为已支持，不通过修改宿主或恢复旧执行平台来补足。
5. **Given** 同配方的两个主会话分别启用已准入 Pro 协作，**When** 各自提交两个调查，
   **Then** 允许合计四个调查并行，结果分别归属其主会话；某一主会话的第三个调查不进入执行，
   不借另一个主会话的空闲名额突破自己的上限。

### User Story 6 - 按需选择模块并维护升级 (Priority: P3)

作为用户与维护者，我希望根据实际需求选择文档、搜索、浏览器、订阅桥、诊断、结构查询或
进程工具，知道数据会发到哪里、有哪些本地状态，以及升级后哪些能力仍有有效证据。

**Why this priority**: 增强能力的收益与依赖成本因环境而异，不宜成为 Base 或 Pro 的隐式前提。

**Independent Test**: 对一个模块独立执行选择、准备、启用、失败、禁用和卸载场景，
核对同类能力所有者与其他模块的状态；无需一次启用全部候选。

**Acceptance Scenarios**:

1. **Given** 某类能力有多个热门方案，**When** 维护者选型，**Then** 比较原生方案与候选的
   实际缺口、公开接口、依赖、维护成本及退出路径，不用热度或版本更晚代替兼容证据。
2. **Given** 模块未启用，**When** 启动日常组合，**Then** 不因已获取资源而加载其扩展、
   连接服务或启动后台工作；隐藏界面不等于禁用模块。
3. **Given** 模块需要账号、网络或浏览器状态，**When** 用户显式启用，**Then**
   数据接收方、认证来源、费用路线、缓存与进程归属明确，不静默切换提供方或复用其他账号。
4. **Given** 宿主或模块升级，**When** 维护者审阅变更，**Then** 精确版本、配置变化、
   重新验证范围和回退限制可定位，旧组合通过不会自动成为新组合通过。

### Edge Cases

- 框架输入包含未知字段或不支持的能力；原生配置却含未知的非受管字段，二者不得同样删除。
- 空数组、false 和显式禁用被缺省值覆盖，导致旧扩展或项目资源重新进入发现路径。
- 缺锁、依赖内容损坏、来源不可达、安装中断或旧缓存恰好掩盖缺失资源。
- 宿主在信任项目、恢复会话或发现资源时尝试扩大工具集合或自动获取依赖。
- 同名资源由公共、实例和项目同时提供；主题覆盖、重复服务和重复 hooks 改变行为。
- 部署与维护并发、受管值双向修改、链接越界、备份损坏或恢复期间再次中断。
- 父会话已退出，后代进程仍存活；进程归属未知，或取消回执先于实际退出。
- 同配方多个主会话并行，一个退出而其他会话或其后代仍活动；启动、退出与共享资源维护相互竞争。
- 只读角色可通过命令、外部服务或继承工具写入；嵌套任务绕过并发限制。
- 多个主会话同时申请调查，错误共用全配方计数或相互借用名额；取消或未知退出过早释放本会话名额。
- 子任务返回空结果、截断结果、错误模型或过期输出；请求模型与实际确认模型不一致。
- 模型切换、压缩、分支和继续会话使统计重置或重复累计；订阅账户没有可确认费用。
- 极窄窗口、中文宽字符、长模型名、长分支、SSH/tmux 缩放、粘贴、取消和退出导致显示陈旧。
- 新组合需要的资源只在旧 Pi home 或开发机路径存在；两个配方意外共享会话或缓存。
- 平台、账号或授权缺失，造成尚未验收；不能通过改称未选择或忽略失败获得支持声明。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 必须交付旧集成处置清单，覆盖配置、同步行为、插件、技能、角色、提示、主题、
  依赖、测试、文档和状态所有权；每项记录来源、消费者、替代/重建/删除决定及理由。
- **FR-002**: 必须先形成 DSH/OMP/Pi 公共治理的差异与验收矩阵；配置校验、覆盖、
  完整依赖治理、部署所有权、配置恢复及实例准入必须共用中性能力，原生差异有明确归属。
  不得为新 Pi 复制公共管理逻辑或仅改名保留旧 Pi 执行平台。
- **FR-003**: 三种工具必须遵循同一公开管理契约；已声明的宿主差异可保留，
  不要求采用相同原生目录、依赖格式或安装方式。公共变更须验证受影响的其他工具契约。
- **FR-004**: 必须分别提供 Base 和 Pro，Base 可独立完成日常编码，Pro 仅增加经准入能力。
  两者共用配置逻辑、资源与官方宿主来源，正常使用同一宿主版本，各有独立完整依赖锁与实例状态；
  Pro 兼容落后时可显式冻结其版本，不得阻塞 Base 或维护宿主分叉。
- **FR-005**: 新组合必须使用未修改的官方 Pi 主交互入口及公开扩展能力。
  不得修改宿主源码、缓存副本或二进制，不得调用私有接缝或以运行时替换绕过限制。
- **FR-006**: Base 必须提供原生文件读写、命令执行、检索、模型与思考强度选择、
  会话继续/分支/压缩以及终端和编辑器偏好；不强制用户为简单任务采用额外规划或协作流程。
- **FR-007**: 公共规则与资源必须同源维护，沿用现有 SpecKit 作为项目规格和任务流程，
  不默认引入第二套计划、Todo 或完整方法论引导。精选技能须保留完整支持资源与许可。
- **FR-008**: 必须严格拒绝未知框架字段、无效引用和不支持的映射，保留显式禁用语义；
  公共、工具、机器、实例及项目资源的发现、优先级和覆盖范围必须可审阅且可复现。
- **FR-009**: 必须分别标明原生设置、模块设置、机器绑定、项目资源及认证/会话状态的归属。
  非受管原生字段和用户偏好不得因原生格式允许扩展或公共配方更新而被全量覆盖。
- **FR-010**: 秘密、原生账号、信任、会话和运行历史必须与公共配置分离。
  秘密不得进入预览、日志、摘要及配置备份；支持捕获的偏好只能生成校验后的非秘密修改提案。
- **FR-011**: 每个工具和配方必须保持配置、账号、会话、缓存、活动状态与备份的明确归属，
  不默认接管用户全局目录。共用来源不授权跨实例共享账号、复制认证文件或改写其他实例。
  同一 Pi 配方必须允许多个独立主会话并行，分别记录每次运行与会话归属；
  同配方可使用本实例原生账号与已部署来源，不因多会话而复制账号或创建新产品配方。
- **FR-012**: 相同非秘密输入必须生成相同受管结果；部署必须保留非受管内容并执行三方比较，
  双向冲突阻止覆盖，保留单侧漂移不得自动接纳为新基线。
- **FR-013**: 无变化部署不得重写或轮换备份；有实际成功变更时仅保留上一轮受管配置。
  中断必须可恢复，回滚须消费备份并保留新增非受管内容，不承担软件、数据库或任务执行回退。
- **FR-014**: 活动或归属未知的实例及相关后代必须阻止影响其资源的不安全维护。
  同配方共享资源仅在所有相关主会话及后代确认空闲后才允许维护；
  单个会话退出不得覆盖或清除其他运行的归属，运行准入与维护竞争必须遵守同一保护。
  管理器不得通过终止用户进程、删除归属记录或放宽路径保护获取维护权限。
- **FR-015**: 配置验证、渲染、预览、部署与默认诊断必须离线且不启动宿主；
  依赖解析、依赖准备、配置部署和启动必须分别显式执行，启动不得隐式更新锁、安装或部署。
  此边界必须覆盖宿主的项目发现和自动安装行为，而非仅约束管理器本身。
- **FR-016**: 宿主、所选模块、技能和必要传递依赖必须具有固定身份、完整来源与完整性证据；
  安装验证成功后方可激活，损坏或缺失时明确失败，不退回浮动版本或未声明全局缓存。
- **FR-017**: 新组合必须在旧集成缺席时独立构建与运行；旧 Pi 专属执行、任务监督、
  调度、逐工具租约、任务数据库和跨崩溃重放机制退出新组合，不将其重建为公共基础。
- **FR-018**: 删除旧仓库资源前必须核对消费者并处置引用；旧来源目录、账号、会话、历史
  数据及用户定制不因仓库退役而被自动删除。切换前提供差异、冲突处理、恢复和单一写入者方案。
- **FR-019**: 状态栏必须对照旧栏的模型/提供方/思考强度、项目与分支、输入/输出、缓存、
  费用、上下文、会话时长、活动状态、速度及权限摘要十类信息，逐项定义含义、来源、刷新、
  缺口与降级。新组合能够通过公开来源确认的原有信息必须保留，不要求复刻错误或私有数据口径。
- **FR-020**: 窄屏必须优先保留可辨认的模型/提供方/思考强度、主会话活动和上下文风险，
  较低优先级统计可收拢或换行；60、90、130 列中文样例及缩放、粘贴、取消和退出均须验收。
  项目显示不得暴露私人绝对路径。
- **FR-021**: 用量与缓存须注明统计范围和分母，累计用量不得冒充当前上下文，
  分支、继续、压缩和子任务不得导致双算；费用、实际模型、权限或窗口不可确认时标为未知
  或不可用，速度必须说明算法，不能将上下文增量称为输出生成速率。
- **FR-022**: 状态栏候选必须满足公开接口要求，不能以关闭显示替代准入。
  无候选满足时可阶段性交付原生界面与缺口清单；信息对齐仅在覆盖要求通过，或未覆盖差异
  获用户明确接受后才能标为完成，不能因候选不兼容静默删除需求。
- **FR-023**: 首轮 Pro 协作对每个主会话仅允许至多两个同时运行的只读调查子任务，由该主会话负责判断、
  写入和验收；各主会话独立计数，不设全配方合计两个的限制，也不得借用其他主会话名额。
  尚未确认退出的活动/未知调查继续占用所属主会话名额；禁止递归委派、后台子任务和写入子任务。
  缺少可核实限制的组合不得准入。
- **FR-024**: 子任务的实际可达工具、资源继承、项目发现、账号和结果归属必须明确验证；
  提示词、角色名称或隐藏工具不构成强制只读或系统隔离。辅助入口不得绕过首轮限制。
- **FR-025**: 委派结果必须对应当前任务与模型选择，分别记录排队、运行、成功、失败、
  取消请求、已确认退出及未知状态；请求模型与可确认实际模型分列。无完整回执不得冒充成功，
  无法确认副作用时不得自动重试，后代仍活动或未知时保留相关维护保护。
- **FR-026**: Pro 候选未满足准入时必须保持协作未就绪并说明缺口，不能恢复旧平台、
  修改上游或仅放宽版本声明；Base 可独立验收，Pro 不能因此被标为完成。
- **FR-027**: 文档、搜索、浏览器、网页抽取、订阅桥、诊断、结构查询、语义分析和会话内
  进程管理均为按需能力，同类能力每个组合只选择一个所有者，不默认同时启用全部候选。
  未选择模块不得加载、连接服务或启动工作；配置回滚与其缓存、进程和账号清理分开处理。
- **FR-028**: 每个选中模块须明确提供方、用途、数据发送范围、账号与费用路线、依赖、
  本地状态、失败和退出行为；不得隐式复用系统凭据、接管个人浏览器或静默切换提供方。
  缺少必需条件时明确未就绪，不把配置或安装存在写成能力可用。
- **FR-029**: 长命令及断线交接必须依赖明确的外部保管方式与项目日志；会话内进程工具
  不得承诺跨重启恢复，停止请求不能冒充全部后代已退出，会话分支不能冒充文件撤销。
- **FR-030**: 插件与配置选型必须比较当时官方稳定能力和社区候选，记录核对日期、
  精确身份、配置依据、许可、收益、重叠职责及维护成本。采用旧版本有明确理由，
  热度、新版本发布和旧版本问题均不能代替当前组合的审阅与验证。
- **FR-031**: 升级必须列出受影响配置、依赖、发现范围、行为和证据，并重新验证相关组合；
  若原生覆盖已有能力，须评估退出重叠模块。不得让浮动来源自动改变已声明支持的组合。
- **FR-032**: 就绪报告必须区分已声明、已准备、已部署、加载已验证、账号待接入、
  运行已验证、未执行、失败和阻塞原因；保留既有管理器错误类别及原生启动后的退出结果。
  缺平台、账号或授权不能自动转记为未选择，也不能自动缩减承诺范围。
- **FR-033**: 验证必须覆盖默认隔离边界、受影响 DSH/OMP 契约和工具/配方共存。
  原生宿主、真实账号与模型调用分别按授权执行；支持声明绑定精确组合、平台、命令与结果，
  未执行不记为通过，历史证据不自动续用。
- **FR-034**: 合入前必须将仍有效的临时设计与来源证据整合至正式规格、设计或支持文档，
  删除临时设计材料并修复引用；历史规格与验收记录保留历史含义，不冒充新组合已通过。

### Key Entities *(include if feature involves data)*

- **公共治理契约**：三种工具共用的配置、依赖、部署、恢复与实例准入规则，以及已声明差异。
- **产品配方**：Base 或 Pro 的必需能力、显式选择模块、完整依赖身份与就绪条件。
- **受管实例**：某工具和配方的配置、账号、会话、缓存、进程与备份所有权边界。
- **退役处置项**：旧资源、行为或入口的来源、消费者、状态归属、处置理由及替代验收关系。
- **模块准入记录**：候选价值、固定来源、公开能力、依赖、数据边界、选择状态和退出方法。
- **状态栏信息项**：数据含义、统计范围、可信来源、刷新时机、显示优先级与未知处理。
- **调查子任务**：所属主会话、范围、模型选择、只读约束、执行状态、结果与可确认副作用；按所属主会话计数，不是新任务平台。
- **验收证据**：候选组合、平台、前提、实际检查、结果和未覆盖范围，可随相关升级失效。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 旧资源与行为清单中 100% 的条目有来源、消费者和处置理由；声明退役完成时，
  新组合中对已退役专属执行机制的运行或发现依赖为 0，未决公共消费者为 0。
- **SC-002**: 三种工具在校验、覆盖、依赖维护、部署冲突、失败恢复、回滚和活动保护七类
  场景中，100% 符合共同规则或已明确声明的原生差异，其他工具与配方的非预期变更为 0。
- **SC-003**: 在每个声明已通过重建验收的平台上，基础组合至少在两个用户目录与仓库位置
  不同的干净环境重建出相同选中能力；所需生成文件手工编辑次数和旧环境依赖数均为 0。
- **SC-004**: 基础组合独立完成读写检索、命令执行、模型切换、会话继续、分支及压缩六类
  用户场景；可选模块未就绪时仍可完成这些场景，简单任务新增强制规划或协作步骤为 0。
- **SC-005**: 十类旧状态栏信息的对照和口径记录覆盖率为 100%；已承诺覆盖的信息在三种
  样例宽度均可辨认或按规则收拢，且不存在未经接受的缺口。缺失值误报为零或确认值的次数为 0。
- **SC-006**: 宣称高阶协作可用前，一个调查、两个并行调查、多主会话独立计数、越界/递归请求、
  失败和取消六类场景全部符合声明；每个主会话同时运行的调查不超过 2 个，
  两个主会话可各运行两个调查且结果归属互不串用；未经允许的子任务写入或递归执行为 0。
- **SC-007**: 每个选择交付的模块在启用、正常使用、缺前提、失败、禁用和退出六类场景
  均有明确结果；未选模块的加载、服务连接和后台工作数为 0，未声明的提供方切换为 0。
- **SC-008**: 冲突、无变化部署、恢复中断、回滚及未知进程场景中，账号、会话、秘密和
  非受管数据的非预期修改为 0；无变化的重复部署产生的变更和备份轮换均为 0。
  同配方至少两个主会话可并行，单个退出后其余活动归属不丢失；仍有相关活动/未知运行时，
  不安全共享资源维护获准次数为 0。
- **SC-009**: 100% 的就绪与支持声明可以定位到精确组合、验证层级和范围；将未执行、
  旧组合或仅静态检查写成运行通过的次数为 0。无法确认任务成功或进程退出时误报成功为 0。
- **SC-010**: 合入候选中临时设计文件及指向已移除临时材料的失效引用均为 0，
  有效需求与必要来源证据在正式交付材料中的承接覆盖率为 100%。

## Assumptions

- 本次命令承接此前已确认的重建意图，只产生一个新规格；继续使用 `design/pi-toolkit-reboot`，
  不创建或切换分支。本轮不安装插件、不改运行实现、不部署、不提交或推送。
- 适用治理为[宪章 2.2.0](../../.specify/memory/constitution.md)。本规格不授予真实宿主、
  账号、模型调用、发布或远端更新授权，也不将旧历史验收转为新版支持证据。
- 用户具备所选平台的明确前提及自有机器绑定与账号。具体平台、宿主/插件版本与组合在
  计划阶段固定；平台未获验证时继续报告未验证，不沿用旧规格的通过范围。
- 首版 Base 可先独立交付；Pro 协作和状态栏信息对齐分别验收，阶段性交付不等于整个功能
  已完成。具体插件、主题 flavor 和配置值由后续证据选择，不需要为本规格先锁死候选。
- 现有调研中的候选及配置只是输入材料，均须重新核对准入与所选组合。
  不以缺少合格插件为理由豁免只读/并发边界或上游不可修改原则。
- 旧栏缓存界面展示缓存读取量及其占输入与缓存读写合计的比例；单列缓存写入量、
  Git dirty、子代理进度和长命令进度均属新增信息，不是旧信息对齐的必达项。
  旧速度是单轮上下文增量的估算，权限摘要依赖旧控制插件，不作为可直接继承的公开数据来源。
- 公共框架对齐的变更范围仅限上述契约及受影响消费者；不顺带改造其他工具的功能、
  终端配置、网络代理或发布历史。
