# Contract: 公共配置、依赖、部署与实例准入

适用：FR-002–003、FR-008–016、FR-032–033。以下是新实现必须遵循的契约，
不表示当前 DSH/OMP/Pi 已完全对齐。数据定义见 [data-model](../data-model.md)。

## 1. 配置接口保持公共表达

保持 registry → tool defaults → profile → machine overrides 的来源解析，
对象递归覆盖、标量替换、数组整体替换；[] 与 false 不按真假回落。
所有引用须存在且被合法选择。未知框架字段和工具不能映射的能力返回 exit 2。
Pi 原生允许扩展 namespace 不等于 agent_options 接受任意未知字段。

同一非秘密输入必须产生同一渲染意图。公共来源不含真实模型、私人路径或秘密；
机器绑定提供 provider/model/service/editor，秘密只保留引用，由需要凭据的操作按部署契约注入。
非受管原生字段不作为输入重新拼装期望整文件，不因无法识别而删除。

UI 偏好初始化与持续受管字段分开：初始化只在合法新目标或缺失字段应用，不覆盖已有原生选择；
持续受管字段列明 selector。capture 只生成经过校验的非秘密 allowlist 提案，不自动采纳。

## 2. CLI 与副作用

全局选择参数在子命令前，`--machine NAME` 与 `--local PATH` 互斥，`--profile ID` 可选。
此表沿用当前公开 CLI，不引入一个新 Pi 控制命令组。

| 命令 | 允许的副作用 | 禁止行为 |
| --- | --- | --- |
| validate | 校验来源及映射 | 联网、读秘密正文、启动宿主 |
| render | 生成非秘密意图 | 安装、发现未声明可执行资源 |
| plan | 比较来源、基线与目标并展示脱敏差异 | 部署、安装、加载扩展 |
| lock --agent pi | 显式解析选中组合的完整依赖身份 | 登录、运行模型、暗中变更其他工具锁 |
| sync | 按锁暂存、验证、激活依赖包 | 更新锁、登录、启动宿主、改账号 home |
| apply | 遵守所有权部署配置与声明资源 | 下载依赖、软件降级、重置原生状态 |
| rollback | 恢复上一轮受管配置，消费备份 | 恢复软件/数据库/任务执行或删除非受管新增 |
| run | 检查已部署契约、所需凭据和实例准入，再启动官方 CLI | 自动 lock/sync/apply、获取项目缺包 |
| doctor | 默认离线核对非秘密状态 | 启动第三方宿主作版本探测 |
| doctor --live | 显式可达性检查 | 自动登录、模型调用或将网络可达写成完整可用 |
| setup | 显式复合 sync/apply 等操作 | 被只读教程或自动启动路径隐式调用 |

render/plan 可能产生管理器自己的非秘密临时产物，仍不得写入原生账号或任务状态。
内部错误与原生进程结果分开：

| 退出码 | 管理器阶段语义 |
| --- | --- |
| 0 | 管理操作成功，可附漂移或待登录信息；不等于产品验收通过 |
| 2 | 参数、配置、引用、映射、来源锁身份或准入组合错误 |
| 3 | 已启用路径所需凭据缺失 |
| 4 | 所有权冲突、活动/未知 owner、恢复待处理 |
| 5 | 依赖或原生检查失败、缺必要运行包或工具链 |
| 6 | 文件系统或内部操作失败 |

官方宿主成功启动后保留其实际退出码，不重新套用以上管理器类别。

## 3. 三方所有权与配置恢复

按受管文件/selector 比较 baseline B、current C、desired D：

| 条件 | 行为 |
| --- | --- |
| C=B | 应用 D（若也相等则无变化） |
| D=B 且 C≠B | 保留原生漂移并报告，不将 C 接纳为新基线 |
| C=D | 不重写目标；基线记录按现有公共提交规则处理 |
| C≠B 且 D≠B 且 C≠D | 冲突，拒绝覆盖 |

未知非受管字段、新增用户文件与新增原生状态保留。重叠 selector 或来源所有权不明确须先失败。
单文件用同目录临时文件原子替换；多文件复用公共 pending journal 与写前复查，
不承诺跨文件或跨进程绝对原子。journal 提交顺序和恢复语义不在 Pi 薄适配内另行实现。

仅实际成功变更轮换上一版受管配置；无变化与失败不轮换。rollback 成功消费备份，
恢复过程再次中断仍须保留可解释记录。配置恢复不能绕过实例维护准入。

## 4. 依赖 backend 与激活

继续使用 `DependencyBackend` 作为公共边界；重建 Pi backend 保持其协议签名，
锁字段可按原生格式不同，但以下行为必须一致：

1. lock 解析所有选中来源、传递依赖、必要构建与原生资源，固定身份及许可。
2. sync 只消费锁，先验证选择摘要和来源身份，再在隔离暂存目录准备产物。
3. 激活前核验清单、必要正文、链接、包入口、依赖闭包及平台前提；marker/size/mtime 不足。
4. 验证失败不替换有效运行包，不改变实例原生 home，不改变配置上一版备份。
5. 激活需实例维护准入；发布物缓存可按不可变内容复用，可变安装及账号状态不能无归属共享。

公共抽取只针对真正相同的内容校验、暂存发布和错误处理；DSH 包锁与 OMP 资产锁不被迁移到 npm。
旧 Pi task/lease 数据不得成为 backend 的必需输入。

## 5. 生命周期接口与三种工具的差异

继续由 adapter 的 lifecycle hook 进入公共启动/维护流程；共用中性锁/身份/路径保护原语，
保留 DSH `.guard`/实例标记与 OMP 自身 marker/lock 布局。不得以对齐为由移动账号目录。

可观察结果统一为：allowed、active_conflict、unknown_owner、recovery_required、ownership_conflict。
这些是内部结果语义，不要求新公共 CLI 输出采用一个全新 JSON 格式。

- 运行准入先核对实例归属与已部署资源，再登记本次 owner，才能启动子进程。
- 维护对相关实例资源排他；active、unknown 或 pending 均拒绝不安全写入（exit 4）。
- 父退出不能单独将实例标 idle；需核实相关后代与资源使用情况。进程组/会话号是观察线索，
  不能证明守护化或脱离组的进程已不存在；发现覆盖不足就保留 unknown。
- 原生包、资源及后台能力的可达范围必须与可观察生命周期匹配；首轮不启用后台委派。
- 同一 Pi 配方允许多个受管主会话并行，每次运行有独立归属和会话记录；
  同配方使用本实例账号与已部署来源，不复制认证或派生新配方。
  运行登记、退出移除与维护申请必须遵守同一受保护准入协议，避免检查空闲后又启动新会话的竞争。
  维护须对相关资源排他，确认所有相关主会话及后代空闲；单个退出仅更新自身记录，
  不能清除其他活动/未知运行。公共中性原语不能收紧 DSH/OMP 原有并发用法，也不复制 Pi 锁实现。
- 稳定私人 owner 记录须核对进程身份，避免 PID 复用；不只看 PID、超时、文件存在或锁已释放。
- 异常退出导致 unknown 时，提供显式只读核实与恢复指引；确认空闲前不自动清除记录。
  核实不能停止进程、接管继续执行或重放工具，也不恢复旧任务监督平台。

不能在指定平台证明上述保护时，相关运行/维护路径保持未就绪或保守阻塞，
不得将“用户自己保证没有进程”当成通过证据。具体实现变化交主代理审查，不由薄适配静默豁免。

## 6. 验收矩阵

| 场景 | 默认隔离证据 | 单独原生证据 |
| --- | --- | --- |
| 未知字段、空数组与 false | 公共解析及三个 adapter 差分 | 选中原生字段实际读取 |
| 双向冲突、漂移、回滚 | 临时目标、哨兵及中断注入 | 必要原生新增字段保留 |
| 缺包、内容损坏与安装中断 | 假 backend、完整清单及激活断点 | 指定平台真实发行物形状 |
| 活动/未知 owner 与后代 | 假进程、身份复用、维护竞争 | 正常退出、异常退出和后台后代 |
| 同配方多主会话 | 至少两个运行、单个退出、另一个及其后代活动/未知、启动与维护竞争 | 多终端运行归属独立；共享资源维护等待全部相关运行空闲 |
| 多工具/多配方共存 | DSH/OMP/Pi 临时 home 与状态哨兵 | 各自授权范围内独立运行 |

默认隔离验证不能启动第三方宿主。原生/账号支持按证据层级声明，不外推平台。
