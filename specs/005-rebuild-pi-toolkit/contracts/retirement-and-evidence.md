# Contract: 旧 Pi 退役、证据与发布收口

适用：FR-001、FR-017–018、FR-029、FR-032–034。
本契约约束未来实施，不是文件级删除已执行记录。旧要求替代关系以 [spec](../spec.md) 为准。

## 1. 退役清单与单一所有者

每项至少记录：仓库相对路径/资源 ID、旧用途、入口与消费者、已知动态注册、状态归属、
replace/rebuild/remove/archive/unresolved、理由、替代入口及验收。清单放正式 feature 材料，
不得从真实账号/会话导出；未知消费者阻止该项删除，不阻塞无关公共文档。

| 类别与当前位置 | 默认处置方向 | 删除/替换前必须满足 |
| --- | --- | --- |
| `src/agentcfg/pi.py`、Pi schema/资源投影 | 全新薄适配 | 不再进入 SDK 主循环；公共契约和新资源验证 |
| `pi_dependencies.py`、旧 recipes 与锁 | 重建 Node/npm 后端 | 官方发行物、新两档闭包、暂存激活与完整性核验 |
| `pi_host.py`、supervisor/control/native 执行链 | 退出新运行闭包 | CLI/adapter/展示调用均撤除，公共消费者有替代 |
| `model_delegate*.py` 与旧 Codex/Pi 桥 | 退役专属链 | skills/prompts/roles/登录与工具引用同步处置；不是禁止新 Pi 调查代理 |
| `activity.py`、`workspace_leases.py`、`process_tracking.py`、`pi_recovery.py` | 按剩余消费者整组退役 | 先核对 model_delegate、commands、presentation 及测试，不能按前缀裸删 |
| `agents/pi/packages/` 旧本地和 vendor 包 | 全部重新选型 | 公共内容同源承接，许可/来源保留，不继续构建发布旧补丁 |
| `profiles/pi-*.toml` 四旧配方与绑定示例 | 替换为 Base/Pro 和虚构示例 | 旧 ID 有明确迁移/不支持说明，不能静默路由到新能力 |
| 旧 Pi 测试与 validation selector | 删除专属平台假设，保留/迁移公共保护测试 | 不删除仍覆盖 DSH/OMP 的测试，不把旧通过套给新组合 |
| 旧 specs/验收报告 | 保留历史含义 | 新规格明确替代关系，不改写旧完成状态或平台结果 |
| 真实 native home、账号、会话、任务库与旧备份 | 原位保留 | 不导入公共仓库，不自动删除、迁移数据库或终止活动实例 |

以上是有证据的分类，不是完整文件清单；实施开始时生成具体引用图和文件归属。
`commands.py` 的旧 Pi recover 分发、`presentation.py` 的 workspace lease 展示等虽然名字通用，
也须按实际消费者移除或调整，不允许留下隐式依赖。

## 2. 实施批次顺序

1. 固定候选、建立清单与公共差异矩阵，记录已有偏离，不启动旧宿主做盘点。
2. 抽取公共中性原语及接口，先验证 DSH/OMP 行为；保持原账号目录与锁语义。
3. 在收紧 Pi schema 的同一来源切换批次中，先让四旧 profile 退出有效 catalog，解除
   `agents/pi/agent.toml` 的旧默认和 `bindings.toml` 的旧 owner，并将 Pi plugins/content
   registry 切换为无旧执行引用的最小有效集合；再新增 Base/Pro，承接完整资源及官方 CLI 薄适配。
   不保留 schema 豁免或静默路由；全 catalog 加载、旧 ID 明确拒绝和 DSH/OMP 不受影响须有隔离证据。
   这不删除旧实例、认证、会话、活动归属或用户 home；公共模型来源保留并重验。
4. 对已解除消费者的旧代码/插件/锁/测试按批删除，复核第 3 步的旧配方退出；每批检查静态引用、
   动态入口及相关回归。清理后核验新锁身份仍有效；若实际依赖输入变化，显式重锁、重审并重验，
   不能由 render/apply/run 自动修复。新组合须在旧链缺席时重建。
5. 分别处理 Pro、状态栏和按需模块准入；达不到条件保留失败与未完成，不恢复旧平台。
6. 整理正式文档、完整来源与支持证据，清理临时材料并审查稳定最终差异。

清单可以先形成，删除不必等旧功能复刻。新旧组合不能由两个管理器写同一目标。
库内清理不授权清理其他工作树、旧分支引用、用户数据库或远端发布。

## 3. 旧状态与恢复边界

新两档各有稳定实例与会话位置，用户在新实例自行完成必要登录；不复制旧 auth/trust/session。
旧目录只作为来源和状态归属依据，默认不改写。切换计划展示受管范围、差异、机器前提和失败恢复。

旧任务执行恢复从新产品路径退出，不继续打包整个旧平台来保留 recover 命令。
历史任务状态原位保留；提供脱敏的停止使用/人工归档指引，涉及活动进程的核实仍按公共实例准入，
不自动停止、接管或继续旧任务。无法核实的旧 owner 保持冲突，不自动清除以方便切换。
配置事务恢复仍由公共 pending/rollback 承担，与旧任务数据归档无关。

旧权限、自动确认、循环保护、Todo、自定义压缩、MCP/网页桥逐项明确处置；
原生压缩/原生 MCP 重新验收，现有 SpecKit 继续作为任务流程。
规则及提示不得建议调用已退出的角色、工具或隐式安装入口。

## 4. 验证层级与结果记录

| 层级 | 能证明什么 | 不能替代什么 |
| --- | --- | --- |
| 资料/静态发布物审阅 | 版本、源码接口、配置字段、许可与可定位来源 | 包真实加载、终端及账号行为 |
| 默认隔离测试 | 管理器 schema、命令边界、所有权、安装/恢复及状态映射 | 第三方候选真的只读或模型成功 |
| 原生组合 | 指定平台和精确组合加载/资源/会话/UI/退出 | 另一平台或真实账号结果 |
| 账号/服务场景 | 指定授权路线与可确认模型/服务结果 | 全部账户、费用及未来版本 |

每份证据绑定候选与目标 main、锁/选择摘要、OS/架构/工具链类别、实际 argv、退出码、
脱敏证据、通过/失败/未执行和限制；不要写真实主机名、私人路径、邮箱、凭据或会话正文。
源码摘要代替 commit 时记录覆盖文件集合和确定性算法；修改后重跑受影响检查。

已完成/进行中/失败待决策/环境不足未验证是任务状态，不用它们替代测试结果。
本轮没有原生授权，不推定环境不足，也不能记通过。未选模块与选中但缺账号严格区分。
Linux x86_64 为首轮目标；macOS 仍是候选，其他平台本轮不作支持承诺。
若以后纳入，逐平台、每个声明范围至少两种干净路径验收，不靠旧四配方结果抵扣。

本轮只生成正式计划材料，不提前删除或修改这些用户已有文档。

## 6. 最终门禁

没有未决公共消费者、退役资源不在新发行/加载/发现路径、选中资源与完整锁一致；
Base、Pro、状态栏、可选模块分别有真实状态。全文档结构/链接/公开内容和适用测试通过，
已知失败明确保留或获得对应范围接受，不能用候选未选解释已选能力失败。

稳定写入结束后完成最终审查。提交前核对批准的本地作者/提交者身份与环境覆盖，
移除宪章顶部临时 Sync Impact Report；本计划不执行提交或远端更新。
主线前进或来源/锁/实现再变动时重评证据；不强推、不丢弃用户工作、不普通合并旧私密谱系。
