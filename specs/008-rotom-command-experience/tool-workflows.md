## 本轮决策

公开维护采用三个显式阶段：停止所选运行、普通 setup、逐项恢复。跨阶段保存非秘密恢复
清单和执行事实，不声称整个流程是一笔跨进程事务，也不跨阶段保留部署写入许可。
本决策替代旧方案中“所有工具必须先统一进入 Domain 维护许可才可完成流程”的前提；
现有 OMP Domain 批次仍能查询与收尾，不迁移或重放历史批次。

1. 停止前先核验目标完整运行包的当前终端恢复准入，更新批准前再次检查；未知组合不先停止再报恢复不可用。计划绑定工具、机器、profile、确切运行身份、当前部署、所选 session 和工作目录。
   session 无可信观察时要求用户明确选择；不能以最新文件、启动目录或缺失回执推导会话。
2. 停止复用现有审阅、不可覆盖快照、一次请求、原 pidfd SIGTERM 和退出核验。
   DSH 保留原协议；Pi/OMP 控制端点作为原 inbox 的独立元数据，避免旧 manager 因新增
   RunRecord 字段或 OMP owner 摘要变化而无法收尾。旧运行没有通道时说明需人工停止。
3. 停止完成后撤销本次停止 fence。更新再次调用该工具原有 setup 预览、独立批准、
   sync/apply 和物理/资源门禁。并发新运行可使更新失败；不扩大停止集合，不以旧停止
   结果豁免新检查。DSH/Pi 使用原实例保护；OMP 继续使用共享包与 Domain 资源保护。
4. 原 setup 结果如实保留；失败或结果未知不会自动重试、回滚或恢复到未核实部署。
   只有可证实允许的新执行才能重新预览并批准；可能已执行的 unknown 不重试，不能从磁盘记录重建内存许可。
5. 恢复使用工具官方 CLI 的精确目标和原目录。当前终端逐项交接是基础能力；原 pane、
   新标签页和自动输入继续仍是独立能力。加载无回执显示待确认，交由用户核对并继续。
6. Pi 的会话写入保护覆盖启动前与公开会话切换事件，三个来源由 `locks/pi/session-control.json` 校验；旧 unguarded active/unknown 阻挡 claim。原生 `--resume` 是 picker，受管明确恢复用 Rotom 完整 ID；普通 `--session` 完整 ID 转精确路径并持租约。
   OMP 原生 session-ID 锁在首次写入取得，竞争时迁移新 ID 的 sibling；只读 open 不取锁，不承诺提前拒绝外部 writer。Pi 原生缺失文件可能产生新 ID，Rotom 启动前重核存在性；事后外部变化仍 unknown。
   任何只覆盖 Rotom 合作进程的保护必须明确其范围，不冒充对任意外部 writer 的排他证明。

恢复使用 Pi/OMP 的 `HandoffResumeBackend`，DSH 原 Host 类不变；全部加载待确认、请核对 TUI ID、零继续。OMP 18.12.6 无网络合成会话已验证同 ID 打开、竞争首次写入分叉且原 ID 不变、释放后恢复原 ID 写入。

## 验收边界

每个工具独立验证“预览 → 停止 → 更新 → 恢复”，以及未选实例、并发新启动、过期计划、
共享包引用、部分停止、写后失败、未知 session、目标缺失、重复恢复和取消。
正常 run/setup、代理选择、退出码、help 和旧记录兼容须回归。默认隔离测试与未修改官方
运行包的原生验证分开记录；缺环境不能写成通过。main 合入另需人工审批。
