# Feature Specification: Rotom 命令与会话体验

**Feature Branch**: `feat/tool-maintenance-workflows-20261026`

**Created**: 2026-10-22

**Status**: 实施中 — 统一入口与严格记录层有隔离阶段证据，整体功能及原生验收未完成。2026-10-24 按用户决定调整恢复交付：先提供官方恢复交接；缺加载回执时显示待确认并禁止自动继续，不依赖上游新增接口。范围、writer 与真实交接验收仍保留。

**本轮维护增量**：三工具分阶段流程已完成候选实现和分组验收，尚未合入 main；原 pane 与自动继续仍是独立未开放能力。详见 [验收记录](tool-workflow-validation.md)。

**Input**: User description: "用 Rotom 项目名统一 agentcfg、termcfg 和工作区入口，让 DSH、Pi、OMP 都能短命令启动；各级命令缺参时给出合法选项，提供完整 help 与 shell 补全，并通过受管 zsh 配置直接启动。展示活跃实例的进程、工作目录和 session ID，支持明确选择后的便捷停止及会话恢复；核实原 Herdr 标签页恢复与继续执行的能力。"

本规格承接 [已审阅计划](../007-rotom-cli-entry/README.md)、
[入口设计](../007-rotom-cli-entry/design.md) 与
[维护恢复探索](../007-rotom-cli-entry/maintenance.md)，受
[宪章 3.0.0](../../.specify/memory/constitution.md) 约束。
本文定义用户结果和验收边界；详细语法与实现候选留在设计和后续计划中。
发现跨文档冲突时必须显式协调，不能仅凭设计存在宣称功能可用。
实施基线与最新取证、任务解耦见 [主线核对与规划修订](main-review.md)。

2026-10-24 用户补充：不确定时不发送“继续”，允许交给用户在官方 TUI 中确认和操作；
上游支持不作为当前交付前提。本文的“恢复交接”表示向官方程序发起指定会话恢复，
“恢复成功”仍只表示有证据确认实际加载。两者在界面、记录和验收中分别判断。

候选已提交：基于 main `45953f0`，分支 `feat/tool-maintenance-workflows-20261026`；尚未合入 main，合入须另经人工批准。官方 Pi/OMP TUI/PTY 分项及分组隔离回归已完成；完整官方宿主 CLI 端到端维护链路未验证。分支复审发现 Pi 打印模式的 helper 失败不能可靠阻止后续提示词，修复与受影响验证完成前不满足合入条件；见 [分支复审](branch-review.md)。

当前三工具维护按[工具方案](tool-workflows.md)分阶段实现：精确 stop_only → 关闭本次 fence → 普通 setup 最新独立批准及原全门禁 → 逐项当前终端交接。此方案替代把所有工具统一纳入 Domain 许可的前提；旧 OMP Domain 批次仍按原协议查询/收尾，不迁移或重放。

## User Scenarios & Testing *(mandatory)*

优先级表示交付次序，各故事在其声明的能力前提下可独立验收。
前三个故事构成统一入口交付；会话与维护按后续阶段推进。
真实进程、终端和账号验收遵守宪章的独立授权边界，文档质量通过不代表功能通过。

### User Story 1 - 用统一短命令启动 Agent (Priority: P1)

作为日常使用者，我希望记住项目名和工具名就能启动已部署的 Agent，
同时能明确选择机器、配方和目录，避免为不同工具记忆不同长命令。

**Why this priority**: 项目入口和三工具短启动是当前最直接的使用障碍。

**Independent Test**: 为三种工具分别准备已部署目标，对比完整短命令、保存偏好和显式覆盖的目标与结果，
并与兼容入口的原有行为比较；无需任何会话或维护能力。

**Acceptance Scenarios**:

1. **Given** 三种工具各有可用的已部署配方，**When** 用户分别运行 `rotom run dsh`、`rotom run pi`、`rotom run omp`，**Then** 每条命令启动对应目标，不要求用户补写该工具的默认配方，也不隐式安装或部署。
2. **Given** 保存的启动偏好与当前管理默认值不同，**When** 用户显式选择机器、本地配置或配方，**Then** 显式范围优先；普通管理命令和既有工作区固定绑定继续采用各自的选择规则。
3. **Given** 目标尚未部署、保存的启动绑定与所选配方不兼容、已部署运行包不可用、偏好失效或配方不属于指定工具，**When** 用户启动，**Then** 启动失败并区分具体原因，给出范围明确的修正建议，不切换其它配方、不自动执行准备动作，也不把绑定不兼容一概解释为需要重新安装。
4. **Given** 用户继续使用旧入口或向原生程序传参，**When** 命令执行，**Then** 旧语法、默认值、输出及路径兼容，原生参数和退出状态保持原有含义。
5. **Given** 用户需要调整入口偏好，**When** 明确查看、保存或清除偏好，**Then** 只处理已声明的非秘密设置；无效字段或失败不静默丢失旧值，一次普通运行不自动改变偏好。
6. **Given** 当前选择有待部署的运行包更新，但保存的部署、启动绑定和旧运行包仍有效，**When** 用户正常启动，**Then** 继续使用保存的已部署契约，并可明确看到待更新及显式预览/部署的下一步；不隐式切换新版本，也不把待更新本身当成启动失败。

### User Story 2 - 缺参时获得选择，完整命令直接执行 (Priority: P1)

作为不熟悉完整命令的使用者，我希望输入入口或子命令后获得相关选项与提醒；
作为脚本使用者，我希望命令不会等待输入或替我确认操作。

**Why this priority**: 发现能力和补齐必要输入必须覆盖全部命令，才能形成一致体验。

**Independent Test**: 对全部公开子命令的缺参、完整参数、确认、隐藏输入和错误路径，
分别在交互与非交互条件下验收，不依赖真实 Agent。

**Acceptance Scenarios**:

1. **Given** 可交互的终端，**When** 用户运行 `rotom`、`rotom run` 或其它缺少必要参数的公开子命令，**Then** 出现与当前任务和范围相关的合法选项或输入说明；根导航包含启动、恢复和管理任务。
2. **Given** 系统没有增强型选择器，**When** 用户进入工具、模型、终端、工作区、配置或维护选择，**Then** 仍能通过编号完成已有合法选择和确认。
3. **Given** 完整有效参数或未知参数，**When** 用户执行命令，**Then** 前者直接进入原有批准与执行流程，后者报告错误；向导不自动修正未知字段或猜测目标。
4. **Given** 任一标准流不是终端或用户选择无输入模式，**When** 命令缺少必要参数或没有等价的非交互批准路径，**Then** 在读取输入和当前未接受动作的副作用前明确失败；完整且已具备所需批准的命令正常执行，不另开终端、不自动确认。
5. **Given** 尚未确认的交互，**When** 用户取消，**Then** 当前动作不保存、不启动、不停止任何运行；此前独立确认的动作保留原结果。
6. **Given** 用户请求结构化结果，**When** 同时出现范围提示、进度或失败建议，**Then** 结果仍可由原有消费者读取，提示不会混入结果内容。

### User Story 3 - 在任意目录查询并使用受管入口 (Priority: P1)

作为使用 zsh 的用户，我希望打开日常终端就能运行 Rotom，
用 help 和补全查到命令与合法参数，并知道安装或配置缺失时如何处理。

**Why this priority**: 可发现入口只有进入日常 shell 才真正降低使用成本。

**Independent Test**: 在空白与已有受管配置两种环境检查首次使用、入口部署、帮助、补全、
不同工作树来源和中断恢复，确认现有日常入口及文件漂移受到保护。

**Acceptance Scenarios**:

1. **Given** 没有私人业务配置，**When** 用户查询任一公开命令层级的帮助，**Then** 能看到用途、参数、默认值与范围、最短及显式示例和副作用；查询不要求配置或凭据、不打开菜单。
2. **Given** 用户已审阅并部署 zsh 入口，**When** 在新终端的任意项目目录输入 `rotom` 或触发补全，**Then** 入口可直接调用，候选与当前位置、已选范围和命令帮助一致。
3. **Given** 已有日常入口绑定到一个工作副本，**When** 用户从另一个工作副本部署其它 zsh 配置，**Then** 原入口绑定保持；只有显式选择并审阅换绑时才切换。
4. **Given** 尚未安装入口、绑定损坏或业务配置缺失，**When** 用户按首次使用或修复说明操作，**Then** 可从已知仓库入口继续，不依赖尚未安装的命令，也不自动创建其它管理面的机器配置。
5. **Given** 入口文件有冲突、用户修改或部署中断，**When** 用户预览、恢复或回滚，**Then** 得到实际状态与受影响范围，保留非受管修改，不根据当前目录猜测恢复来源。

### User Story 4 - 查看 session ID 并恢复确切会话 (Priority: P2)

作为经常中断或切换工作的用户，我希望知道正在使用哪个 session，
并能日常选择或指定它恢复，避免依赖“最近会话”或维护批次。

**Why this priority**: session ID 和实际 resume 是恢复能力的基础，应先于复杂批量维护交付。

**Independent Test**: 为首个已准入工具准备同范围内的多个会话、相同裸 ID 的不同归属及冲突状态，
独立验证查询、选择和官方当前终端恢复交接。真实验收检查原会话/历史及冲突行为；
运行时缺少可靠加载回执也可交接，但必须显示加载待确认、零自动输入且不自动重试。

**Acceptance Scenarios**:

1. **Given** 工具能可靠提供当前会话身份，**When** 用户查看运行或恢复信息，**Then** 可以看到并复制已确认的 session ID 和范围明确的恢复命令；缺少证据时显示未知。
2. **Given** 选定范围内存在多个会话，**When** 用户运行 `rotom resume` 或指定工具与 session ID，**Then** 交互用户可以选择，完整且唯一的有效目标可直接恢复；保存的启动配方不改写已知会话归属。
3. **Given** session ID 有歧义、未登记或与显式范围不符，**When** 请求恢复，**Then** 仅在当前范围内补充必要选择或报告错误；不能跨机器或原生存储搜索、使用最近会话或创建空会话替代。
4. **Given** 目标存在其它活动写入者、目录关系不兼容或无法保证原生 writer 冲突拒绝，**When** 请求恢复，**Then** 拒绝自动派发，不并行创建冲突写入者；允许时展示或聚焦已有位置。
5. **Given** 用户选择当前终端恢复，**When** 新运行加载成功，**Then** 实际会话身份和目录符合原会话规则；选择终端位置不把调用者目录冒充原会话目录，恢复后默认等待输入。
6. **Given** 某工具尚未取得恢复证据，**When** 用户查询或请求恢复，**Then** 明确显示未支持的能力和可用替代方式，不把静态命令或帮助计作已实现的恢复。
7. **Given** 官方目标恢复及 writer 防护已准入，但没有可靠的初始加载回执，**When** 用户发起恢复，**Then** 仍可启动官方程序并交接终端，分别展示请求目标、启动事实和“加载待确认”；不报告恢复成功，不发送继续，不因超时或失联重试，由用户在 TUI 检查后自行操作。
8. **Given** 恢复已经派发但后续观察丢失，**When** 用户重查或重复请求，**Then** 保留未知结果和运行引用，不再派发；人工确认和宿主退出码均不能替代机器可验证的加载或输入回执。

### User Story 5 - 看清活跃实例及可恢复性 (Priority: P2)

作为准备更新配置的用户，我希望在一个列表中看到相关运行的进程、工作目录、
session ID 和终端位置，并能辨别未知项，减少手工排查。

**Why this priority**: 精确观察是安全停止和避免误操作的前提，也能独立用于日常诊断。

**Independent Test**: 提供活动、已退出、缺字段、未登记占用和已过期记录，
比较过滤结果与逐项状态；只读列表无需停止或恢复能力。

**Acceptance Scenarios**:

1. **Given** 所选机器内有不同工具和配方的受管运行，**When** 用户查看实例，**Then** 能按工具或显式配方过滤；未指定配方时不会只显示默认配方，详情区分管理进程与宿主进程。
2. **Given** 有可靠记录及部分缺失信息，**When** 列表展示，**Then** 显示可证明的进程、目录、会话和位置，并分别标明进程状态、会话可信度、恢复位置能力及观察来源与时间。
3. **Given** 存在未登记占用或无法核实的记录，**When** 用户查询，**Then** 显示未知或未登记活动，不把它当作零运行、已空闲或可安全维护，也不扫描所有进程参数或会话正文补齐信息。

### User Story 6 - 明确选择后停止、维护并恢复 (Priority: P3)

作为要更新配置的用户，我希望审阅受影响实例后一次选择多个目标，
保存恢复信息、停止它们、执行已选维护，再恢复或保留可继续处理的清单。

**Why this priority**: 它解决重复操作的主要负担，但依赖可信身份、退出证明与相应恢复能力。

**Independent Test**: 在具备对应恢复证据的范围内，选择部分运行完成一次维护，
并分别注入目标变化、部分停止、维护失败、取消和结果未知，检查每项结果及未选目标。

**Acceptance Scenarios**:

1. **Given** 多个受管运行和一个尚未接受的维护操作，**When** 用户只预览或在接受当前操作前取消，**Then** 可以看到精确目标、资源、操作及各项恢复方式，不停止进程、不建立维护批次或准入状态；普通停止也可独立使用。
2. **Given** 已审阅精确范围，**When** 用户明确接受停止所选目标，**Then** 先保留必要恢复信息，再请求优雅停止；未选、非受管和新出现的运行不被顺带控制，强制停止需要另一项明确批准。
3. **Given** 计划已过期、目标身份变化、部分停止超时或仍有相关后代与资源占用，**When** 准备执行维护，**Then** 拒绝继续，报告逐项事实和重新审阅方式，不清除活动标记来制造成功。
4. **Given** 所选运行已证实退出且维护自身计划仍有效，**When** 执行已批准维护，**Then** 仅执行原操作；停止批准不替代配置批准，重叠批次或外部新运行仍受同一资源门禁约束。
5. **Given** 维护成功、可证实尚未派发、部分完成或结果未知，**When** 用户恢复或取消后续动作，**Then** 分别核对对应部署依据；未知或部分完成先对账，已停止项保留待恢复，不自动重做或静默退回旧配置。
6. **Given** 用户以无输入模式执行维护或批量恢复，**When** 超出声明的等待预算或某项失败，**Then** 命令有界结束并返回原维护结果、逐项状态和范围完整的下一步；多个交互实例不争用同一个终端输入。

### User Story 7 - 在具备能力时回原终端位置恢复 (Priority: P4)

**当前交付边界**：原位置和新标签页恢复均未准入；安装 Herdr 不会启用这些能力。已实现的当前终端交接不依赖 Herdr。

作为在 Herdr 中工作的人，我希望停止 Agent 后保留原标签页位置，
恢复同一会话；不能安全做到时，在停止前就知道替代方案。

**Why this priority**: 原位置能减少重建工作现场的成本，但不能成为未经验证的恢复承诺。

**Independent Test**: 分别使用具备和不具备保留能力的实例，覆盖原位置消失、被复用、
管理程序变化和重复恢复请求；只对已验证组合承诺原位置。

**Acceptance Scenarios**:

1. **Given** 用户选择原位置恢复，**When** 停止计划生成，**Then** 逐项说明本次可原位恢复、仅以后新实例支持、或需新位置/人工处理；不满足时允许保留运行或先改选恢复位置。
2. **Given** 位置保留能力已准入，**When** 官方 Agent 完整退出，**Then** 原位置显示等待恢复且不继续占用阻止维护的运行资源；明确请求后以新运行身份加载同一会话。
3. **Given** 旧实例没有保留能力、位置已失效或管理程序不兼容，**When** 请求原位恢复，**Then** 不假定配置更新已改造旧实例，不向未知终端输入命令；提供用户可接受的新位置或手工恢复方式。
4. **Given** 重复请求或恢复结果未知，**When** 用户再次查询，**Then** 先核实已有结果，不重复创建运行或复用已经消费的启动批准；既有工作区绑定的变更仍需明确接受。

### User Story 8 - 单独选择恢复并继续 (Priority: P5)

作为希望快速接续工作的用户，我可以额外选择向恢复后的确切会话发送一条新指令，
同时能知道它是否发送或结果未知。

**Why this priority**: 这是附加便利，不能阻塞普通会话恢复，也不能替用户决定继续任务。

**Independent Test**: 在已确认会话且具备可靠接收能力时测试单独批准、未就绪、目标变化、
接收失败和未知结果；没有该能力时验证人工替代方式。

**Acceptance Scenarios**:

1. **Given** 用户只选择恢复会话，**When** 恢复成功，**Then** 不发送继续指令。
2. **Given** 用户额外审阅并批准明确目标及文本，**When** 本次新运行已加载目标会话且确实可接收输入，**Then** 才发送；登录页、shell、崩溃界面或其它运行不会收到文本。
3. **Given** 没有可靠接收能力，或请求可能已送达但未确认，**When** 操作结束或重查，**Then** 分别报告未发送或未知，不自动重发；可提供复制文本和聚焦等人工方式。

### Edge Cases

- 未知命令、无效字段或失效偏好不能被交互向导静默修复；单个合法候选也不等于批准副作用。
- 待部署运行包更新与启动绑定不兼容必须区分：前者不阻止有效旧部署启动，后者需审阅并更新部署，不能误报为缺包或自动重装；原生程序内部存在退出命令不代表外部已具备可控制的停止通道。
- 模型隐藏输入、工作区递归选择、接管确认和失败后的修复建议都必须遵守相同无输入规则。
- 原生命令尾部中的 help 或控制选项不能被外层入口截获；声明由原生程序拥有全部尾部的兼容命令保留该规则。
- 帮助不能因业务配置损坏而失效；已安装入口只能为定位读取自己的最小非秘密绑定，绑定损坏时给出独立诊断。
- 补全没有候选或会话索引时不得创建索引、启动程序或猜测值；交互入口可以解释缺失原因并引导明确输入。
- 相同裸会话 ID 在不同工具、后端或原生存储中存在时不能交叉命中；未知 ID 只能经归属核验后使用。
- 当前目录、会话目录与终端位置是不同事实；目录失效或范围不符时不回落到调用者目录。
- 进程 ID 复用、单个进程退出而相关后代仍在、会话切换后旧记录过期，都不能成为停止或恢复成功的依据。
- 只读计划后新增运行、范围变化或并行维护必须使旧批准失效或保持阻塞，不能自动扩大目标集合。
- 停止、维护或恢复的回包丢失不能当作未执行；取消不能删除已发生事实、清除未知占用或宣称已恢复。
- 更新配置、Agent 运行包和 Rotom 管理程序是不同变化；旧驻留进程不能在未核验兼容时恢复新管理逻辑。
- 原 pane 被关闭、复用或仍有其它业务进程时，不按标题、位置或一段按键序列猜测可用性。
- 多个待恢复实例不能同时在调用者终端接收交互输入，改选位置必须先明确接受。
- 检查无其它会话写入者后到实际启动或发送前发生竞争时，不能形成冲突写入或误发文本。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供以项目名为统一入口的启动、恢复、Agent 管理、终端管理、工作区和入口偏好任务，并为三种已支持工具提供一致的短启动方式。
- **FR-002**: 系统必须保留兼容入口的既有参数、默认选择、输出、退出状态及配置/账号/会话路径；任何不兼容迁移必须另行声明。
- **FR-003**: 系统必须区分显式范围、按工具启动偏好和各管理面默认值；显式选择优先，错误或失效选择必须失败，不能改用其它目标。
- **FR-004**: 入口偏好不得覆盖已有工作区的固定启动绑定；聚焦已有实例不能重启、改目录或注入文本，采用新绑定必须明确执行。
- **FR-005**: 启动必须复用保存的已部署契约；未部署、配方启动绑定不兼容及已部署运行包不可用必须分别说明并拒绝相应启动。仅存在待部署运行包更新而旧部署仍有效时，必须继续使用旧部署并提供明确的显式更新提示，不得隐式安装、部署、登录、切换工具或以重新安装代替绑定检查。
- **FR-006**: 原生参数必须保持声明的边界与原有含义；新入口不得抢占原生 help 或改写原生退出状态。
- **FR-007**: 根入口和各命名空间必须提供任务导航；全部公开叶子命令的必要输入都必须声明补齐方式：可枚举缺项在交互时给出范围内选择，自由文本给出输入说明，默认值明确标示，批准与原生尾部保留各自边界；无合法补齐路径时明确失败，不能仅覆盖示例命令。
- **FR-008**: 自动交互必须同时要求三个标准流均为终端且未禁用输入；显式要求交互但条件不满足时必须失败，不能重新打开输入终端。
- **FR-009**: 无输入模式必须贯穿全部嵌套调用、确认、隐藏输入和失败后续路径；缺参或缺少等价批准路径时必须在当前动作副作用前结束。
- **FR-010**: 尚未接受的交互取消不得默选、保存或执行当前动作；退出结果必须区别于成功，也不能声称撤销此前独立确认的动作。
- **FR-011**: 选择必须限于当前范围的合法候选；无增强选择器时提供编号方式，自由文本仍按声明规则校验；未知输入不得静默丢弃或修复。
- **FR-012**: 菜单选择和无输入选项不得替代原有接管、计划确认、写入或进程控制批准；完整参数与交互必须使用相同的范围和授权规则。
- **FR-013**: 提示、交互与进度必须与最终结果分离，原有结构化输出保持兼容；后续建议必须保留实际机器、本地配置、配方及组件等范围。
- **FR-014**: 每级公开命令必须有可独立查询的帮助，说明用途、参数、默认值及优先级、交互条件、示例和网络/文件/进程等副作用。
- **FR-015**: 业务帮助不得依赖私人业务配置、凭据或会话，不得联网、启动宿主或修改状态；安装入口定位仅能读取其声明的最小非秘密绑定，失败时明确诊断。
- **FR-016**: 补全必须与命令和已选范围一致，只提供允许的非秘密标识；缺数据时返回无候选，不得为了补全执行初始化、修复、宿主启动或网络访问。
- **FR-017**: 用户必须能通过现有终端配置管理预览并部署日常 zsh 入口与补全，在新终端的任意项目目录直接使用统一命令。
- **FR-018**: 已有日常入口绑定必须默认保持，换绑需显式审阅；入口部署、恢复和回滚必须保护用户漂移并报告中断后的真实状态，不能按当前工作树重新猜测绑定。
- **FR-019**: 首次使用和修复必须能从已知仓库入口开始；不能要求尚未安装的命令先安装自身，也不能隐式初始化其它管理面的配置。
- **FR-020**: 用户必须能够查看、明确保存或清除非秘密入口偏好；无效字段拒绝，失败不得静默丢失原值，不得因一次运行自动保存新的默认选择。
- **FR-021**: 系统必须展示并允许复制已确认的 session ID、归属和范围明确的恢复命令；未知或仅历史记录必须标明，不能显示为当前已确认会话。
- **FR-022**: 日常恢复必须支持在明确范围内列选或指定确切会话；裸 ID 不能视为全局唯一，歧义和未登记目标必须补齐选择或核验归属，不能越过显式范围搜索或猜测。
- **FR-023**: 系统必须核验原生存储、配方及会话目录，分别记录请求目标、启动派发和实际加载证据；只有确切会话成功加载才可报告恢复成功。缺加载回执本身不禁止已准入的官方恢复交接，结果显示待确认并限制为人工操作；默认偏好不得改变已知归属。
- **FR-024**: 恢复必须说明各工具官方 writer 行为与保护范围：Pi 租约仅覆盖 Rotom 合作进程，旧 unguarded active/unknown 阻挡 claim；OMP 首次竞争写入可分叉新 ID，不承诺外部 writer 预先拒绝。缺加载回执的已准入交接须显示待确认/可能分叉并请核对 TUI ID；自动输入仍要求覆盖实际动作的排他及接收证明，无法取得时不发送。
- **FR-025**: 恢复位置选择只改变使用的终端，不能改变原会话目录规则；位置失效或目录不兼容时必须说明并取得新的明确选择。
- **FR-026**: 恢复交接必须建立新运行并调用官方指定会话恢复入口；只有确认历史加载后才记为已恢复，否则保持待确认。默认等待用户输入，不能自动重放中断命令、发送继续文本或宣称外部副作用已撤销。
- **FR-027**: 每个工具、会话查询及恢复位置必须分别说明官方恢复交接、加载确认和自动继续的能力状态；首先交付经过真实验收的 DSH 当前终端交接，不以取得新的上游接口为前提。静态接口、离线模拟或其它工具通过均不计本工具交接可用。
- **FR-028**: 实例页必须列出所选机器范围内可证明的受管运行并允许按工具或显式配方过滤，提供进程、工作目录、会话和位置及各自来源/时间；展示启动时登记的配置/部署与运行包版本，旧记录缺失时明确未知，不按当前配置补填。
- **FR-029**: 未登记活动、缺字段和过期记录必须保留未知；进程状态、会话可信度和位置能力分别报告，不得扫描全部进程参数或会话正文来猜测控制目标。
- **FR-030**: 停止与维护必须先提供只读计划，明确精确运行集合、受影响资源、维护操作与恢复方式；计划变化必须重新审阅，不能自动加入新运行。
- **FR-031**: 仅能对身份与归属已验证、被明确选择的受管运行请求停止；优雅停止与强制停止分别批准，不得按进程名批杀或因超时自动强制终止。对统一入口登记且控制能力已准入的 DSH/Pi/OMP，精确停止须核实目标、部署版本、原句柄与批准；其它资源占用覆盖未知须披露，但不单独阻止该请求，停止不授予维护写入资格或证明全部资源释放。
- **FR-032**: 维护前必须证明相关运行、后代及资源已释放；单个进程消失、请求已发送或删除标记都不能代替证明，未知继续阻止受影响维护。
- **FR-033**: 停止和恢复等待必须采用声明的有限预算；超时返回已知的逐项结果和下一步，不能继续进入维护、自动强杀或声称整体成功。
- **FR-034**: 停止批准与维护写入批准必须分别有效；只执行已审阅操作，防止重叠批次越权，并在可能执行后保留足以对账的事实，未知时不盲目重试。
- **FR-035**: 结果必须区分未执行、已派发但加载待确认、部分完成、失败、已恢复与未知，保留原维护结果；取消仅终止剩余动作，已停止及待核实目标保留待恢复清单，不能将启动派发算作恢复完成。
- **FR-036**: 恢复必须采用与可证明维护结果一致的部署依据；仅停止且部署未变、维护成功、部分或未知分别核验，不能从未知状态静默退回旧部署。
- **FR-037**: 普通实例停止和日常会话恢复必须可独立使用，无需先创建维护批次；它们与维护流程对同一目标采用一致的身份、范围、批准及成功标准。
- **FR-038**: 停止前必须逐项披露本次原位置恢复能力及替代方式；旧实例不能因为配置更新就被假定具备位置保留能力，要求原位置却无法满足时必须允许保留运行。
- **FR-039**: 已准入的位置保留在停止后必须明确显示等待恢复，不阻塞相应维护；后续恢复创建新运行并重新接受当前准入，普通单次启动仍保留宿主退出即返回的行为。
- **FR-040**: 原位置恢复必须核实位置归属及管理程序兼容；位置复用、身份变化或 Rotom 自身更新不兼容时拒绝原位执行并给出明确的新位置/人工路径。
- **FR-041**: 批量恢复必须避免多个交互实例共用同一输入；重复或可能已执行的恢复请求先对账，新的运行和工作区绑定不得复用已消费批准。
- **FR-042**: 恢复并继续必须单独预览和批准目标及文本，核实本次新运行、实际加载的确切会话、writer 和可接收状态后才发送；任一项不确定或无可靠接收确认时不发送任何继续文本，交给用户在官方 TUI 自行操作。人工确认不得升级为自动输入许可，未知结果不得自动重发；此附加能力不阻塞官方恢复交接。
- **FR-043**: 所有交付必须保持官方 Agent 未修改、使用公开集成能力，遵守配置与账号/会话所有权；观察及恢复记录只保存必要非秘密信息，不复制会话正文或完整环境。
- **FR-044**: 用户必须能区分计划、已实现、隔离验证及原生验收的状态；未经验证的能力保持未开放，并提供范围明确的说明或替代方式。

### Delivery Scope and Capability Gates

| 阶段 | 必须交付的用户结果 | 完成边界 |
| --- | --- | --- |
| 一：统一入口 | 故事 1–3，兼容旧入口、三工具短启动、偏好、全部命令缺参体验、help、zsh 入口与补全 | 入口部署冲突/中断/恢复与非交互路径通过相关验收；静态 resume 只说明能力，不计实际恢复 |
| 二：日常身份与恢复 | 故事 4 的 DSH 官方恢复交接，故事 5 的最小可信观察 | 真实验收指定会话的当前终端交接、原历史及冲突拒绝；机器缺回执可显示加载待确认且零自动输入，不要求上游增强或三工具同时完成 |
| 三：停止与维护 | 故事 6，补齐可信实例与退出观察 | 承诺可恢复前具有对应工具恢复证据；原位置未准入时，仅使用停止前接受的新位置或人工方案 |
| 四：原位置能力 | 故事 7 的原位路径 | 具备独立能力证据才开放；未通过时仍必须满足停止前说明及替代选择要求 |
| 独立附加能力 | 故事 8、严格加载自动确认与 OMP 工作区启动扩展 | 各工具及能力单独准入；不阻塞已支持的官方恢复交接，不能将未开放项标为完成 |

阶段一的完成只对应入口需求，不代表维护与实际恢复完成。
前三阶段是本功能的主交付路径；原位恢复与自动继续的实现承诺以各自能力验证为条件，
不能用一个静态按钮代替经过真实验收的官方恢复交接来宣布全部交付。
缺少严格加载回执时可承诺“一键发起恢复，加载待确认”，不能承诺已恢复或自动继续；
连安全交接也未准入的普通停止须在停止前明确标为需人工恢复。

### Non-goals

- 不修改上游 Agent 源码、官方二进制或使用私有实现接缝。
- 不扫描、接管或停止全部系统进程；不把进程名、目录或标签页标题当作控制权限。
- 不迁移既有账号、会话和配置路径，不重新引入任务调度平台或通用终端管理平台。
- 不自动安装、修复、更新依赖、切换日常入口、继续任务或删除未知状态。
- 不保证恢复进程内存、被中断的外部命令或撤销工具副作用。
- 不把 OMP 短启动等同于 OMP 工作区类型和恢复能力；不以统一界面放宽现有恢复拒绝。
- 不把首次使用向导、复杂全屏界面、额外短别名或全机汇总作为首阶段完成条件。

### Key Entities *(include if feature involves data)*

- **调用范围**：明确或按已声明规则选择的机器/本地配置、工具、配方、组件和结果形式；约束候选与操作，不能因显示默认值扩大。
- **入口偏好**：用户明确保存的各管理面默认机器和按工具启动配方；非秘密、可查看/清除，不覆盖固定实例绑定或会话归属。
- **受管入口绑定**：日常 shell 入口实际指向的可信工作副本及部署身份；与调用者当前目录不同，已有绑定变更需明确接受。
- **运行实例**：一次受管启动的稳定身份、归属、可证明进程关系、启动目录、观察时间和状态；恢复建立新的运行身份。
- **原生会话引用**：工具、后端、原生存储归属与确切会话标识，以及已验证的目录关系和身份可信度。
- **终端位置**：经核实的工作区、标签页或 pane 身份及可用恢复能力；位置与运行、会话各有生命周期。
- **停止/维护计划**：审阅时的精确运行集合、资源、操作、部署依据与逐项恢复方式；相关事实变化后需重新接受。
- **维护批次与恢复清单**：已接受范围、每项停止/维护/恢复事实、原操作结果及未决状态；不包含秘密、会话正文或完整环境。
- **继续请求**：单独批准的目标新运行、会话、文本和接收结果；未知不等于未发送。

## Success Criteria *(mandatory)*

### Measurable Outcomes

以下为待实施验收的目标，不是当前通过结果。条件能力只在相应准入范围内考核，
未准入范围必须通过“清楚说明限制且零越界动作”的验收。

- **SC-001**: 对已准备的三种工具，用户均可用一条包含项目名和工具名的短命令启动正确目标；显式覆盖与失效偏好的全部验收用例均无错误目标或隐式准备动作。
- **SC-002**: 当唯一缺项是工具选择时，用户通过一次命令和一次选择完成启动；全部公开叶子命令的缺参用例均有明确引导或非交互错误，无增强选择器时仍能完成合法选择。
- **SC-003**: 全部非交互或缺少等价非交互批准路径的用例中，输入读取与当前未接受动作的副作用均为零；交互取消用例的当前动作副作用为零，已确认动作的结果仍可辨别，不被误报为撤销。
- **SC-004**: 用户能从每一级公开命令的帮助找到作用、参数、默认值、例子及影响；帮助和补全在全部相关验收用例中不读取业务秘密、不启动宿主、不联网或写入状态。
- **SC-005**: 完成受管入口部署后，用户在任意项目目录的新终端均能直接调用和补全；所有跨工作副本及中断用例均保留正确绑定或准确报告冲突/待恢复状态。
- **SC-006**: 对首个已准入工具的全部确切会话、歧义、跨范围、目录冲突和活动写入者用例，官方恢复只请求被接受的会话；真实验收确认原历史及缺失目标/冲突拒绝，错误会话和新建会话替代均为零。缺少或丢失加载回执时允许交接，误报已恢复、自动输入和重复派发均为零。
- **SC-007**: 对活动、已退出、缺字段、未登记占用和过期记录五类实例，用户均能区分进程、会话可信度和位置能力；没有证据的字段被误报为已确认的数量为零。
- **SC-008**: 在三个实例中只选择两个停止时，未选实例始终保留；若它不阻塞已审阅资源，可完成所选维护，若仍阻塞则拒绝维护并说明原因，不自动停止它。用户不需逐一手工查进程或抄写已确认会话；全部超时、幸存进程、计划变化和未知状态用例均不进入不安全维护。
- **SC-009**: 对每个部分失败、取消或等待超时用例，用户可从结果判断每个目标的已发生事实、原维护结果及下一步，无需猜测是否已执行；停止/恢复就绪等待在声明预算内结束等待，重复未知请求不产生重复动作。
- **SC-010**: 对已准入的原位置恢复用例，以新的运行身份向官方程序请求同一会话，并真实验收原历史；加载回执缺失时沿用日常交接的待确认和零自动输入规则。计划时已知不满足位置或兼容要求的用例在停止前提供明确选择，之后发生变化时拒绝执行并重新选择，未获接受的替代位置动作数量为零。
- **SC-011**: 普通恢复后自动发送新指令的数量为零；附加继续的全部目标变化、未就绪及未知结果用例无误发或自动重发，恢复与继续结果可分别辨别。
- **SC-012**: 所有输出和保存信息的隐私验收用例中，秘密、完整环境、认证信息及会话正文泄露数量为零；用户可明确区分已支持、未知及尚未验证的能力。

## Assumptions

- 本次用户调用承接此前已审阅的整体方案，不要求重新描述需求；正式规格按顺序编号新建，原设计记录保留为输入。
- 目标用户是管理自己 Agent 与终端配置的本地用户；默认操作范围是已选机器内的受管资源，不推定对外部进程或其它用户资源的控制权。
- Agent、终端和工作区各有自己的机器选择；根短启动按工具选择偏好，普通管理命令保留管理默认值，工作区保留固定绑定，恢复遵守会话归属。
- “非交互”包括任一标准流不是终端或明确禁用输入；强制交互不绕过条件，无输入模式不代表批准。
- 首次正常运行需要已准备的运行环境及相应已部署工具；帮助与公开命令发现不以私人配置存在为前提。
- 工具默认功能和启动契约采用当前已审核配方，不假定 Pi 默认无扩展或关闭原生审批；工具内退出命令仍需独立验证外部控制能力，不能据其存在开放批量停止。
- DSH 是首个官方恢复交接目标，Pi/OMP 及各终端位置分别准入；严格自动加载确认可缺失，不以等待上游新增支持为主交付依赖。本轮 Pi/OMP 当前终端交接按工具方案与独立证据验收；严格确认、原 pane 和自动继续仍分别准入。
- 原位恢复依赖官方公开能力或明确采用的受管等待能力；现有 agentcfg 已管理宿主子进程，但保留原位置等待恢复是新增能力，不假定已有实例支持。
- 未取得稳定会话身份、可靠退出与必要排他证据时，显示未知、拒绝自动动作或明确转人工，不以方便使用为由推断成功。
- 原生程序启动和退出行为继续兼容；结构化结果保留原有格式，菜单、范围说明和进度与结果分开。
- 候选必须保留现有日常入口及用户工作；实施前重新核对最新主线、工作树、配置兼容和宪章修订状态。
- 宪章修订仍待维护者合入，原始批准日期 TODO 不由本功能编造；本规格不构成发布、部署、停止真实进程或真实账号验收授权。
