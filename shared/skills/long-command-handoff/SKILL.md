# 长命令交接

仅在用户确实需要跨终端观察或离开当前Pi主会话后继续运行时使用。短命令继续在当前会话执行。
不安装tmux、不修改termcfg、不自动启动常驻服务，也不把Pi内部任务或运行包维护交给后台执行。

开始前确认已有终端工具、用户批准的实际命令、工作目录、独立会话名和项目日志位置。
不得复用或接管未知tmux会话；不使用个人浏览器、Pi账号目录、Pi运行包或其他实例状态作为工作数据。
模型/服务凭据只给确有需要且获准的命令，不能把完整Pi环境导出到会话或日志。

由现有tmux/项目工具承接命令，所有启动、检查和停止操作仍属于主会话责任。
交接说明至少保存：

| 字段 | 内容 |
| --- | --- |
| 目标与范围 | 当前工作的目标、允许操作的目录以及停止条件 |
| 实际执行 | 已确认的argv、cwd、工具身份与会话名；不含凭据值 |
| 产物 | 项目拥有的日志、结果和退出状态文件；不复制完整聊天或认证 |
| 当前证据 | 执行状态、停止请求、进程/后代和副作用分别记录 |
| 下一步 | 如何由所有者继续观察、检查结果、显式停止或处理失败 |

状态必须分开：

- 停止请求已发出、已收到回执，都不能代替进程和后代确认退出。
- tmux会话消失、父shell退出、日志最后一行或Pi管理器恢复空闲，都不能单独证明项目命令成功。
- 退出码、结果完整性和实际副作用分别核对。结果为空、截断或缺失时不假称成功。
- 活动或无法确认的后代继续由声明的项目/终端所有者处理；不自动kill进程组或清理未知PID。

不承诺tmux服务器崩溃、机器重启或内存丢失后的任务恢复，不自动重放命令或失败重试。
配置rollback只恢复受管配置，不能恢复项目工作、命令效果或长期进程。

`pi-processes`仍是会话内候选；其停止信号和shutdown不构成完整退出证据。需要stdin/PTY/REPL时，
先评估单一明确所有者，不能同时启用多个进程/PTY管理模块；它们也不提供跨重启恢复承诺。

本Skill只保存方法与交接要求，没有执行器、任务数据库、后台hook或运行时注册表。
