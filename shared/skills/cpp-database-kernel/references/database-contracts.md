# 数据库内核修改的契约与验证

这是领域检查参考，不规定某种数据库实现。只检查本次变更触及的边界，以目标项目已有事务、隔离、持久化与生命周期契约为准；不同系统的 WAL、MVCC、复制和回收协议不能互相套用。沿用用户项目规则与流程，不安装平台或自动执行脚本。

## 修改前的局部证据

记录真实文件、符号、调用者、被保护状态、提交或发布点、失败后仍须成立的不变量。标明锁与资源的原拥有者、可重试范围和实际构建目标。没有证据时提出具体缺口，不用类名、注释或一次成功运行替代契约。

## 锁、并发与原子发布

- 从实际获取点列锁顺序和嵌套边；核对释放、取消、异常及析构路径，检查同一路径是否以相反顺序进入。不要为消除死锁删锁或移出事务。
- 明确锁保护的是容器结构、记录内容、事务状态还是资源生命周期。回调、IO、条件变量等待及 coroutine 挂起跨出临界区后，重新取得锁前哪些事实可能失效？条件变量谓词由谁保护？
- 检查原子字段发布/消费的 happens-before 关系、读写线程及对象存活期。不能把所有内存序换成更强顺序来掩盖未确认的协议，也不能仅凭压力测试没有失败就断言正确。

## MVCC、可见性与版本回收

- 先确认项目隔离级别、快照取得点、事务 ID/时间戳含义及提交状态的发布顺序；区分读已提交、固定快照和串行化约束，不假定所有读共享同一可见性规则。
- 沿实际版本链核对未提交、已提交、已回滚版本和删除标记。版本链接、索引入口和事务状态的更新次序必须符合原协议；部分失败不能使另一读者看到混合状态。
- 回收前确认所有可能使用旧版本的读者、游标、异步回调、epoch/pin、复制或恢复需求已越过原安全界限。版本“当前不可见”不等于“无人再引用”；不要仅依据最新事务时间删除旧链。
- 针对性检查至少覆盖旧快照与新读者、提交与回滚、删除与重建、并发更新以及回收边界。项目若依赖冲突检测或重试，核对重试是否保留快照、是否重复副作用。

## WAL、提交、checkpoint 与恢复

- 区分原系统的逻辑提交、对调用者成功应答、持久化完成和复制确认；按已配置同步/异步模式核对它们的先后条件，不额外发明统一 fsync 规则。
- 检查日志记录 framing、长度、校验、序号/LSN 与数据页或对象版本的关联。短写、部分尾记录、段轮换、提交记录缺失和 checksum 错误必须走项目定义的拒绝或恢复路径。
- 核对 WAL 与数据写入的原顺序，checkpoint 的覆盖界限、日志保留边界、manifest/文件发布及目录持久化规则（若项目使用）。不能提前清掉恢复仍需的数据或日志。
- 对实际 redo/undo/补偿协议检查重复重放的幂等性、未完成事务、恢复中再次失败以及兼容版本日志；不要假定所有引擎都实现同一种 undo。
- 在本次修改对应的发布点与失败点安排已有故障注入或恢复测试：写日志、写数据、发布提交、checkpoint 与重启后的读回。明确测试实际模拟了什么，不能把正常关闭重启当崩溃恢复证明。

## 所有权、生命周期与关闭

- 核对 raw pointer、借用引用、iterator、buffer/page pin 和 handle 在 move、容器重排、回收及事务结束后的有效期。回调捕获 `this` 时追到调度、取消与销毁，不直接改成可能循环引用的 shared ownership。
- 部分初始化与失败清理按原拥有者逐项处理；异常、取消、超时和重试不能漏释放或双释放，未知清理结果不能当作已释放。
- 关闭时检查停止新准入、通知/取消、等待工作完成与资源销毁的原顺序；确认 join/等待是否持有工作线程仍需要的锁，以及回调是否能在对象撤销后继续运行。

## 持久格式与兼容

- 记录受影响的 magic/version、字段宽度、编码/字节序、默认值、校验、读写端和迁移规则。未知版本或损坏数据按原策略拒绝，不能为“修复”自动覆盖。
- 依据项目承诺检查旧数据读入、新数据写出、混合版本 reader/writer、升级失败与回退、旧 WAL/checkpoint 恢复。仅当前编译器或当前版本 roundtrip 不证明向后兼容。

## 最小修改与验证

先确认相关构建宏、模板实例、平台分支和测试目标，只修改已证明需要改变的状态转换与调用链。正确性修复不夹带格式迁移、锁重构、命名清理或统一现代化；保留他人的变更。

| 触及的边界 | 选用项目已有的验证 |
| --- | --- |
| 锁/原子/生命周期 | 受影响目标构建、竞争与取消用例、适用 sanitizer、关闭/失败路径 |
| MVCC/回收 | 隔离与可见性用例、旧读者存活和版本回收边界、重试副作用 |
| WAL/恢复/兼容 | 对应故障点、损坏/部分记录、重复恢复、旧格式样本与回退 |
| 热路径 | 相同输入与环境下的分配、复杂度和性能比较；报告测量条件与限制 |

检查最终稳定 diff，列实际运行命令、结果与未验证项。缺少构建环境、sanitizer、压力或基准权限时明确记为未验证，不伪造通过，也不自动全量构建、开启后台服务或修改用户工作流。
