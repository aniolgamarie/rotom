# 配置维护

来源：rotom 仓库原创，按个人多工具配置管理、本地密钥和上一版备份需求编写。工具原生映射以管理仓库当前锁与适配文档为准。

先定位用户指定的 **rotom 管理仓库** 和 `--machine` / `--local` / `--profile` 选择器。当前工作目录可能是业务项目，不要假设它就是管理仓库。使用管理仓库根的 `agentcfg` 绝对路径；原生 run 的 `--cwd` 保持用户业务目录。

由 agentcfg 启动时，可只读取 `AGENTCFG_REPOSITORY`、`AGENTCFG_LOCAL_FILE`、`AGENTCFG_PROFILE` 三个非秘密定位变量；它们指向已部署时选定的来源。不要运行全量 env 转储。变量不可见且用户未提供位置时，只询问缺少的管理仓库/机器文件位置，不猜测或扫描其他工具的配置。

定位信息不扩大原生权限。当前会话无法写管理仓库或私人实例目录时，在管理仓库启动维护会话或使用原生授权机制，不把默认权限改成完全访问。若正在维护自身活动实例，先完成源文件、生成与计划，再说明退出实例后从外部终端 apply。

## 选择正确的配置来源

| 用户需求 | 编辑位置 |
|---|---|
| 所有机器共用的规则/技能/provider/model | 管理仓库 `shared/` 与所选 profile |
| DSH 原生字段、主题、插件版本或映射 | `agents/dsh/`，先核对 `docs/upstream-verification.md` 与依赖锁 |
| 本机路径、编辑器、私有网关/模型/MCP、机器偏好 | 仓库外机器 TOML；见管理仓库 `docs/local-config.md` 和 `schemas/local.schema.json` |
| TUI 中已经修改的设置 | 先运行 `capture`，审阅 allowlist 本地提案 |
| 新工具 | 遵循管理仓库适配接口文档；未实现的 Pi/Codex 不能声称已同步 |

不要只修改生成文件。已有原生 settings 可能混有 OAuth 动态目录和用户 UI 改动，不能全量反向同步或整目录复制。

## 编写合法本地 TOML

先查看当前版本的 schema 和 **非秘密相关表**，不要打印整份含 `[secrets]` 的文件。`machine` 放机器身份与默认选择；`machine.paths` 放实例/状态/缓存根；`machine.environment` 仅放明确的非秘密环境变量；私有实体放 `overrides.providers/models/mcp`；选择与工具参数放 `overrides.profiles.<已存在的ID>`。

- 框架格式不是原生 DSH 配置，不能猜键或建立任意 extras 表。工具参数由该 profile 所属 adapter 校验。
- provider 与 model 使用稳定 ID；model.provider 和 roles.main 必须引用合并后被选中的实体。动态 OAuth 不编造静态地址或模型目录。
- 对象递归合并，数组整体替换；空数组会清空选择，false 不能被忽略。只新增一个模型时也要考虑原有选择数组是否应保留。
- TOML 路径只使用绝对路径或 `~/`，中文/空格按字面保存；不 source/eval，不做 `$HOME` 或命令替换。
- 凭据只写 `secret:<name>` 引用。新 secret 区域用空值供用户手工填写；不要索取、打印、复制或替用户查找已有账号密钥。
- 只改任务涉及的局部表，保留其他 profile、注释和 secrets 原文。无法安全局部编辑时给出只包含相关非秘密字段的修改提案，不全量重写私人文件。

修改后依次运行选中配置的 `validate`、`render`、`plan`，检查类型、引用、合并结果、来源与脱敏差异。出错按字段位置修正，不关闭 schema 校验，不把秘密值粘贴到错误报告。

## 按授权完成任务

“生成并检查”完成 validate/render/plan 即可，不因此部署或安装。“应用到本机”则在已授权范围内继续运行 apply，不对正常部署重复确认；上一版备份、冲突检测和恢复由管理器负责。依赖变化才进入显式 lock、审查锁差异和 sync；不能偷偷采用 latest 或无版本 npx。

活动实例阻止修改时，说明退出该实例后重试；不要杀进程或直接绕过管理器改文件。真实登录、模型调用、业务项目 OpenSpec 初始化、其他工具部署与发布必须在本次用户授权范围内，不能由普通模板修改推断。

使用 `rollback` 恢复上一版受管配置；不要手工恢复整个 home。密钥、账号、会话和插件数据库不属于配置恢复范围。

完成时说明修改了哪些来源、本地格式是否校验通过、生成还是已部署、备份是否更新、测试证据和仍需登录/验证的内容。不要把 fixture 测试当作真实宿主或模型调用成功。
