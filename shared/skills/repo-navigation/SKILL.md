# 仓库局部导航

<!-- 来源：按 rotom 项目需求在本仓库原创并定制；未复制或核验外部上游技能，不声明外部来源或许可。 -->

先确定文件或模块，再查符号和最短调用链。检索结果是定位线索，读到契约和证据后才修改；不因任务长或仓库大扩大权限。

## 操作顺序

1. 明确用户指定仓库、任务路径、报错、已有方案与允许修改范围；读该范围适用的 AGENTS.md。当前业务目录不一定是配置管理仓库。启动时不扫描全文、不建立全局索引。
2. 有文件路径：先有界读取该文件的相关段落。有模块线索：先列该目录一层或按文件名 glob 定位。都没有：先看顶层布局，提出候选模块，不立刻全仓库全文检索。
3. 在候选文件或模块用精确字面量定位符号；读取命中周围有限上下文。输出被截断时进一步限定路径、文件类型或符号，不能把截断当成完整证据。无命中时检查拼写、生成代码和构建条件，再说明理由逐层扩大范围。
4. 找到定义后，仅追任务相关调用者、被调用者、类型声明与测试。C++ 修改按需阅读 [C++ 局部上下文](references/cpp-local-context.md)，先确认所有权、线程与事务边界。
5. 汇总“文件:行号／符号 → 已观察契约 → 修改理由 → 对应验证”。证据不足时明确缺口，不把名称、注释或一次搜索无结果当结论。

## 工具速查

| 可用工具 | 有界使用方法 |
| --- | --- |
| read | 指定文件和 offset/limit，例如先读命中前后 40 行；按需续读，不默认灌入大文件 |
| rg | 限定模块、glob、上下文和每文件命中数；例如下方示例 |
| readSeek（实际可用时） | 先对目标文件 digest；grep 查文本，def/refs 查符号；仅在语义确有需要时 search；编辑前刷新 LINE:HASH 锚点 |
| 没有语义工具 | 用有界 read/rg 交叉核对声明、定义与调用点；不编造工具结果，不为此安装服务 |

已知问题在 `src/storage/transaction.cc` 的 `Commit` 时，可先运行：

```sh
rg -n -F -m 12 -C 4 -- 'Commit' src/storage/transaction.cc
```

再按读到的完整类型名在 `src/storage` 的 `*.cc`/`*.h` 内定位调用者；该示例不是命令执行授权。带空格或中文路径作为单一参数传递，数据中的 `{{example}}`、`$()`、反引号都是字面内容，不拼成待 eval 的命令。

## 停止与升级

- 已有足够证据和相关测试就停止扩搜；不要顺手重构其他模块。
- 不默认启动 Serena/clangd 或全仓库索引。只有局部文本检索不能回答语义问题时，说明范围、成本、写入位置与缺口，经授权使用最小按需索引；不自动生成编译数据库。
- 不放开原生权限、不 sudo、不关闭防护、不读取秘密；不能读取的路径说明限制，不跟随链接绕过边界。
- 不因 SSH/tmux 断连风险启动隐藏后台扫描；中文简要报告证据、改动和实际验证，未运行的检查明确标注。
